# Native Mac build profiles

The Mac bundle builder defaults to the optimized Rust release profile. Production-default features are used; test hooks are not enabled. `Cargo.toml` retains thin LTO, one code-generation unit and explicit integer overflow checks. Rust's explicit validation, checked arithmetic, complete-original authentication, transaction guards, private native seal permit and phase deadlines remain active. Debug assertions are not used as runtime authorization or source-validation checks in the local engine, recording or store code.

Run `bash scripts/build-native-mac.sh` or add `--release`. Use `--debug` only for an explicitly identified diagnostic bundle. Unknown, empty or multiple profile arguments reject before Cargo. The builder explicitly uses this workspace's target directory and selects the unique actual Cargo compiler-artifact executable for this app's source target, rather than guessing a path. It requires all seven current application-owned artifacts, validates their effective optimization level (release 3, debug 0), overflow checks and absence of test hooks, and retains their JSON records under `.runtime/native-builds/`. It rejects nonhost output paths and an inherited nonhost `CARGO_BUILD_TARGET`; a host-architecture check precedes copying. This avoids stale binaries when Cargo target/profile settings differ. The signed Info.plist records the validated profile, optimization level and overflow setting. The builder preserves the previous bundle before installing the new development bundle. It remains ad-hoc signed; this is not an installer or a distribution release.

The app launches its bundled executable as the private audio worker. Its protocol build identifier does not distinguish optimized and diagnostic variants. Verification receipts must therefore retain the executable SHA-256, source fingerprints, build profile, feature selection, signature verification, source/test boundaries and actual native workflow. Neither a debug receipt nor an all-features test executable qualifies a default-features optimized bundle.

The previous builder always copied the unoptimized debug executable. A fresh diagnostic 39.434667-second native take expired the unchanged ten-second sealing deadline. Its complete 32,436,224-byte original is retained without attachment. Equivalent isolated storage work measured 27.467864 seconds before statement reuse, 25.072617 seconds after reuse in debug, and 2.540018 seconds in the existing optimized profile. The latter predates the explicit release overflow-check setting; repeat measurement and native qualification under the final setting are required. These timings do not attribute the gain to one compiler/library, guarantee all durations, or authorize dropping authentication or raising timeouts.

Original-row hashing reuses at most three prepared statements per included column, at most 128 columns for the current table and hash invocation. Every field and original row is still read and hashed in the same v1 order, including unknown columns and damaged tails; byte slices remain at most 64 KiB. No digest crosses validation snapshots or transactions. Logical budget charges, sticky cancellation and SQLite instruction accounting remain enforced. Independent value-encoding and frozen-legacy oracles qualify compatibility separately from performance.

Qualify final optimized recording/storage tests, source checks, package/signature and an actual fresh native Record/Finish/normal seal/explicit attachment/same-generation Play/Stop/history/archive/restore/restart workflow. Mark unavailable physical input, listening, latency and platform checks separately. The fixed ten-second seal deadline and current retained-inspection/playback capacities are independent limits; thirty-minute recording and complete long-take workflows still require their own capacity/governor design and actual evidence. Changing the build profile does not close that gate.
