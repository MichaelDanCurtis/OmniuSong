# Bounded copy-recovery primitive

October 22, 2026. Library foundation for gate 3 of the [performance recovery plan](../reviews/RUST-PERFORMANCE-RECOVERY-PLAN.md). The durable execute/reconcile service and native UI remain closed. This primitive does not prove a Prepared receipt exists and must not be wired directly to a UI or run automatically. Later session integration must authenticate the exact durable Prepared action and fresh semantic review before calling it.

`RecoveryCopy::create(CaptureReader, existing_action_parent, action_id)` accepts only a bounded, unsealed reader. The reader's one sticky governor, source transaction and source owner survive through the operation. An opened-file identity anchor established during bounded reader acquisition rejects later pathname replacement, including a byte-identical replacement. Initial identity support is Unix; other platforms refuse this operation until their file-identity/alias handling is qualified. Trusted parent directories and cooperative ownership are required; this is not a hostile-directory sandbox.

The action ID is nonzero 32-character lowercase hexadecimal. The existing parent must be an absolute canonical ordinary directory with no symlink components, outside the original source directory. Derive `action/evidence/take.sqlite3` and `action/recovery/take.sqlite3`; exclusive-create every directory/file. Never overwrite, remove, truncate, rename away or clean up an existing/partial action. Existing actions refuse and remain available for the later reconciliation service. This first primitive has no restart/replay API and does not manufacture a new manifest to resolve uncertainty.

Read complete physical files in bounded chunks, including unselected/corrupt/free pages. Charge every raw-copy read, hash and write byte to the original governor; hash and compare exact byte lengths and physical SHA-256. Sync each completed file and its containing directory. The source and verified evidence image are never opened for write. Create a distinct working copy and its exclusively created owner file, with continuous ownership through read review and recovered finalization. Source identity, sidecars and full physical digest are checked again before/after copying and after finalization. No sidecar is deleted or repaired.

FileBytes remains its existing high-water measurement. A separate fixed artifact policy reserves at most 1 GiB for evidence plus the working database, including a 512 MiB working-file ceiling enforced by SQLite max_page_count. Existing 512 MiB source/1 GiB cumulative work/row/VM/etc. limits do not increase or reset. Repeated authentication can exhaust work allowance below the source-size ceiling. Lock files are empty. Filesystem/SQLite overhead, rollback journals and hardware durability are not covered by the database-byte reservation; failed artifacts remain retained. No duration/capacity claim follows.

`RecoveryCopy::reader()` exposes a held read-only working reader for a format-aware engine to authenticate its checkpoint. `finalize(&RecoveryPrefix, operation_id)` is low-level byte-prefix authority only. It cannot establish six-stream performance semantics, a native Finish, callback retirement or normal sealing. Keep existing bounded `CaptureReader::recover`/`recover_prefix` refusals unchanged.

Before opening a writer, require the exact canonical journal-v1 schema including all table columns/index/trigger definitions. Unsupported extensions remain in the source/evidence/working copies and refuse mutation. Recheck in the writable transaction. All SQL, scans, hashes and serialization use the same cumulative governor. Logical SQL payload/row work and SQLite VM instructions are accounted separately from raw-copy bytes; this is not a measurement or quota of the operating system's SQLite page I/O. In one IMMEDIATE transaction authenticate the exact working snapshot/original rows, create or authenticate interruption metadata, verify the positive selected audio prefix, write a recovered manifest with unknown tail, and verify unchanged original rows. No normal or complete-original finalizer is reachable. The source take/descriptor identity is unchanged.

Success returns artifact paths, recovered manifest, fully reverified working inspection and cumulative usage. Errors retain the typed underlying cause, boxed derived paths and a conservative monotonic boundary: no artifacts, action created, evidence created/verified, working created/verified, recovery may have written, recovered verified, or existing artifacts. Cancellation or a limit after submission cannot imply rollback/no commit. No success is published until post-commit authentication and source/evidence comparisons finish. An uncertain working artifact is retained for future explicit reconciliation. No catalog write, attachment, adoption, evidence archive or engine command is part of this API.
