# Retained capture review and explicit prefix recovery

October 20, 2026. Milestone 2; release rows R03–R05, R07–R08 and H07–H08. This packet closes discovery and explicit recovery of engine stages that survived a restart before project attachment. It does not qualify physical input or the full recording milestone.

The engine retains stages at `native-root/captures/<canonical UUID>/take.sqlite3`. Discovery is bounded to 128 directory entries, does not recursively search, create a captures folder, open a journal or change its state. Invalid/redirected entries remain visible as diagnostics. Only ordinary canonical stage directories and single-link ordinary journal files inside the owned root may become actionable. Trusted parent directories remain a precondition; this is not a hostile same-user namespace sandbox.

The storage worker owns scan, inspection, recovery and attachment. UI paint/input/drop performs none of that work. Native input stays software-loopback-only for verification; no device is opened by these operations.

## Read-only inspection

Add a recording reader that holds one read transaction and acquires the journal's existing exclusive ownership guard. A live writer returns `Owned`; inspection never takes over a recording. Read-only/query-only SQLite access validates the descriptor and verified prefix/sealed manifest without changing the journal, its state, interruption rows or original chunks. Unsealed material always has an unknown tail. A consistent verified snapshot is required; a file size or filename is not a completed take.

The store exposes `scan_captures`, `inspect_capture(stage_id)` and `recover_capture(expected_inspection, operation_id)`. DTOs are `CaptureStageScan`, `CaptureStage`, `CaptureInspection`, `CaptureStageState`, `CaptureAudio`, and `CaptureRecoveryReceipt`. Inspection includes stage/path, take identity, descriptor SHA, canonical inspection SHA, state, verified counts/problems/unknown-tail flag, audio stream frame/rate/channel summaries and optional sealed manifest SHA. No inline PCM or full project enters the GUI.

Recovery is a separate explicit action. It checks the reviewed inspection fingerprint before interruption/finalization; any new bytes or changed interpretation require another review. Exclusive acquisition may record an interruption receipt, but must never resume input, append invented samples, remove bad rows or silently extend the reviewed prefix. Recheck the normalized prefix after writer acquisition before sealing. Use the existing `seal_recovered`, retaining its unknown-tail disclosure, proven index and all original rows. Empty verified audio cannot become a playable clip.

Derive the durable seal-operation identity from the caller's operation ID and the exact reviewed stage/inspection. After a lost reply, the same request may authenticate the existing recovered manifest and return it. A changed request or different operation cannot reuse that receipt. Recovery and project attachment are separate commits; attachment uses the existing stable `AttachCapture` operation and expected project revision. A conflict retains the recovered original. The user explicitly chooses the current project and stream; frame-zero placement remains uncalibrated. No automatic attach or record resume occurs on launch or scan.

## Interface and archive policy

The implemented review token binds every DTO field, including a complete physical file SHA and a normalized digest of retained descriptor/chunk/cache/schema rows. The latter includes damaged and unselected rows and streams large SQLite fields in 64-KiB pieces. Sealing changes controlled metadata and physical bytes, so replay checks this original-row digest as well as the derived operation and verified prefix. Altering expected fields under an old token is rejected. The exclusive owner guard passes directly from the read-only transaction to the recovery writer; the checked original digest is verified again inside the final sealing transaction. Inspection requires an existing ordinary owner sidecar and rollback-mode database; missing sidecars or ambiguous WAL/shared-memory sidecars remain visible errors, never automatic repair.

Expose a retained-capture section with Scan, Inspect, explicit Recover verified prefix, and explicit Attach selected original to current session. Show source path, verified frames/gaps, unknown tail, problems and whether a manifest exists. Keep normal audio/capture/session guards and stable operation identities through uncertain completion. An inactive uncertain attachment may be explicitly kept local to release session navigation while preserving the exact request and source evidence. Its unchanged retry requires the original target and a clean draft; a fresh attachment is disabled while that outcome remains unresolved. Only a matched typed `RevisionConflict` with `outcome_unknown=false` permits an explicit rejected-choice release into bounded read-only history before a separate new user choice. The original may already be durably ingested although its project attachment did not publish. This release never cancels or undoes a possibly completed operation. Do not automatically replay recovery on reconnect.

Current project archives include their complete referenced original/history closure. Staged originals are local recovery material outside that closure until explicitly attached. The interface must say so whenever this section is shown; do not claim an unattached stage is included or delete it after export. General reversible set-aside management, a combined archive of unrelated/unassigned stages and independent failure-domain checkpoints remain required follow-on work.
