# Native studio evidence jobs

October 22, 2026. This is the agreed integration contract for the **next session/job/UI work**, not a claim that these controls are implemented. The OSRE storage API, reviewed-restore pin and typed export failures are prerequisites. Per-song OSAR restore-as-copy, OSRE inert extraction and manual operator rollback remain separate workflows.

## Worker and outcomes

Use the existing capacity-one SessionService and its exact RequestId/worker generation. Add explicit full-root Export, read-only Inspect, reviewed inert Restore, bounded List jobs and read-only Reconcile commands. Export/Restore keep exact job IDs and paths; they are excluded from generic retry safety. A new operation must not masquerade as retry by choosing another destination. Reconciliation observes prior uncertainty even though it is read-only; losing its reply cannot establish the earlier mutation's outcome.

Use a distinct evidence cancellation token and a compatible default Backend trait entry point. Cancellation requires the exact pending request and an evidence command kind. It retains worker credit until correlated completion or actual disconnect. Drop may stop an inspection; it must not silently cancel an accepted mutation. Cancellation requests cessation, never rollback. Bounded phase/usage observations must not claim an invented percentage or create a second terminal channel.

An evidence-job reply carries a typed primary outcome and optional `catalog_retirement: ServiceError`. Extend `terminal_storage_failure` to inspect this field, as it already examines attachment current-document errors. The primary cancellation/limit stays distinct from an observed fatal LiveCatalog/BackupTransfer SQLite code. Apply the existing IOERR/CORRUPT/NOTADB classifier to the original typed code, queue the correlated completion, then retire the backend. Mixed Backup failure warrants conservative retirement but does not establish catalog corruption. Archived SQLite or private snapshot failure stays local and must leave healthy sessions available. Never classify from error text or call blanket `store_failure` on archive-only parsing.

## Durable request and uncertainty

Introduce a bounded EvidenceJobs journal owned by the session worker, with exact versioned request bytes, canonical origin root, nonzero32hex job identity, operation, input/output paths, export ID or reviewed SHA and a canonical request fingerprint. Sync the immutable request and started marker **before** invoking a mutating storage path. Retain a bounded terminal record and bounded appended reconciliation observations. Define compiled serialization/history/job-count ceilings before implementation; refuse new admission when full without evicting unresolved jobs.

Keep this application job history in a dedicated versioned evidence-job namespace outside captures/source-actions/takes, with its location and fixed limits qualified by the journal implementation. It is separate from OSRE's explicit catalog/three-tree scope and must never be restored as execution authority. Do not silently alter the schema-6 archive contract. Job metadata uses its own bounded ownership/write/sync protocol and must not hold a conflicting store-writer lease across OSRE export. Exact paths and identities cannot be edited into a different operation after starting.

If terminal persistence fails after artifacts complete, the synced request remains discoverable and uncertain. Startup may load bounded metadata; it must not inspect archives, resume jobs, create destinations or reconcile artifacts automatically. A completion marker's presence alone is insufficient proof: errors/cancellation can occur after it is written. Preserve all partial/complete evidence, without cleanup or blind replay.

## Existing-artifact reconciliation

Export reconciliation uses `reconcile_evidence_export` to authenticate only the exact recorded existing archive, export ID and origin root. Missing, partial, unreadable or different bytes remain unresolved/local failures. It must not call a fresh-export path that falls back to creation.

Restore reconciliation uses the separate read-only `inspect_restored_evidence(directory, expected_archive_path, expected_archive_sha256, budget)` verifier for an existing inert directory. Bind the original input pathname lexically as well as its digest and destination: completion provenance is outside the OSRE digest. Do not call create-new restore again. Authenticate ordinary anchored private directories, strict bounded completion/manifest bytes, exact numbered membership, every object hash and the archived catalog's reference closure. Bind the result to the recorded expected whole-container SHA and destination. Reconstruct the OSRE digest from canonical header/manifest, ordered numbered objects, content digest and footer so the original archive need not remain available. A missing/invalid marker remains incomplete; never synthesize it, repair objects, adopt identities or redirect the job.

## Native controls and qualification

New `evidence_ui.rs` owns bounded fields, view epoch, selected job, reviewed fingerprint, explicit confirmation, progress/cancel and uncertainty/result cards. Main owns command submission and audio/capture/draft guards. Reads preserve metadata/note/clip drafts. Mutations require resolved drafts and stopped/released audio/capture. Restore confirmation binds path, SHA, UI epoch and worker generation. Field changes/reconnect invalidate that confirmation. Stale completion may update its historical card but never replace current review/drafts. Paint, selection and refresh/reconnect perform no artifact work. Use separate labels for per-song backup and retained studio evidence.

Required tests cover real archived SQLite corruption followed by healthy sessions; typed live/mixed fatal plus simultaneous governor stop; exact cancellation and held credit; stale/mismatched replies/EOF; faults before/after request/started sync, artifact completion and terminal persistence; original-absent export/restore reconciliation; malformed/missing/changed objects and surplus members; saturation without job eviction; no automatic restart execution; raw UI bypass, drafts, active audio and stale confirmation guards.

Actual installed-app acceptance must exercise Export→Inspect→explicitly confirmed inert Restore, changed-source refusal, cancel/uncertain restart and reconciliation, malformed-archive local failure with healthy sessions, and independent catalog/original preservation. No native input, including loopback, is needed or permitted. Current file/work ceilings may refuse a large full studio; qualify actual scale and add a separately bounded scalable design rather than claiming capacity from small fixtures. Hard power loss, complete long-session capacity, source adoption, platforms and the rest of milestone 2 remain separate required work.
