# Native live keys and pads — implementation contract

October 20, 2026. This packet follows the saved-session output and retained-capture foundation. The public interfaces below are frozen in [live_types.rs](../../crates/omniusong-engine/src/live_types.rs). Engine and native UI source are implemented; the [329-entry gate](../verification/rust-native-live-tests.json), [independent review](../reviews/RUST-LIVE-AUDITION-IMPLEMENTATION.md) and [synthetic render/archive proof](../verification/rust-native-live-bus.json) pass. Actual native-live output and interaction remain [pending](../verification/rust-native-live-ui.json) at the rebuilt app's native file-open wait. The full [release goal](../GOAL.md), [audio contract](NATIVE-AUDIO-ENGINE.md), [recording contract](NATIVE-TAKES.md) and [existing process-local event contracts](../../crates/omniusong-core/src/contracts.rs) remain authoritative.

## Musical scope

Deliver explicit **Start live audition**, computer/on-screen keys, sixteen pads, keyboard patch/velocity controls, sustain and **All notes off / Stop**. Keys use prepared procedural keys/bass/pad patches; pads use a prepared procedural drum kit. These are ordinary synthesis, not AI. Patches may share a 64-voice pool, with the patch selected on each NoteOn so a held sound does not change when the UI selector changes.

Audition is output-only and mutually exclusive with saved-session playback and solo capture. Starting it opens no input, creates no journal/track/project revision and cannot arm recording. The interface must clearly say the performance is not being recorded or saved. It cannot silently replace unsaved edits, attach a take, or accept a candidate. Existing music and original captures remain untouched.

This first packet does not qualify hardware MIDI, MPE, UMP transport, expression routing, project performance capture, timing alignment, monitoring/overdub, or under-10-ms response. Those remain required later. Native device identity, actual negotiated rate/channels and explicit loss/fault states must be observable; actual buffer/latency reporting remains a separate addition. Current default output format restrictions still apply.

## Two admission paths, one owned worker

Keep the existing capacity-one acknowledged control path for Initialize, device enumeration, saved playback/capture and Stop. Add explicit StartLive and PanicLive controls and typed live start/status results. Do not send each key press through `try_submit`: a held control request must not reject every subsequent release.

Add a separate bounded application-to-supervisor live-ingress queue. Public method: `try_push_live(batch)`, with a fixed process-local batch and a typed result distinguishing accepted into the parent queue, stopped/stale session, saturation and retired worker. Parent-queue acceptance is not a claim that the worker or callback rendered the events. New admission must stop immediately on terminal loss; there is no automatic live replay or retry after an uncertain acknowledgement.

The same private control socket may carry bounded worker LiveBatch exchanges, serialized by its supervisor. A second process/socket/shared-memory protocol is not required for this packet. This is separate ingress admission, not a claim of independent IPC transport. A stalled exchange still has the existing total deadline and must retire its worker; the callback lease below prevents the supervisor's ordinary Status heartbeats from sustaining stuck voices in the meantime.

The supervisor checks urgent Stop/Panic before live batches; controls are never appended behind an unbounded event stream. Healthy requests may finish before a newly requested Stop. Panic is out of band to the note queue through a dedicated bounded latch, not dependent on enqueuing a NoteOff into a full queue. It is not cross-process shared memory: worker-side panic becomes effective when the next bounded exchange reaches the worker, or the callback lease expires sooner. Report that limitation; do not claim an immediate physical silence guarantee.

Normal live telemetry can be coalesced into a bounded latest-status slot. Admission receipts/counters, overflow and terminal causes cannot be hidden by a later idle or success result. Retain the existing once-only terminal delivery behind an already queued ordinary completion. The existing actor's blocking normal `replies.send` must become a bounded nonblocking outbox while the child is active; otherwise an unpolled completion would prevent urgent control processing. All admission paths and returned UI reply credit wake the actor through a bounded notification. Idle wake must not wait 250 ms before noticing a fresh key. Only terminal delivery may wait for UI reply credit, after child retirement.

Shared public surface:

| API | Meaning |
| --- | --- |
| Existing `try_submit / try_poll / is_busy` | Keep correlated, capacity-one ordinary controls. Live ingress and urgent requests are independent of `is_busy`. |
| `EngineCommand::StartLive { output_device, gui_clock }` | Explicit output-only start; worker prepares fixed GUI source bindings. Result `LiveStarted(LiveReady)` supplies scope, source/clock bindings, actual device/rate/channels, sequence 1 and first lease token. |
| `try_push_live(LiveBatch) -> Result<LiveQueued, LiveSubmitError>` | Fixed 32-event parent queue admission only. Typed failures: not-live, stale scope, invalid, panic pending, saturated/faulted, retired. Parent saturation itself latches fault and requests panic, even if the caller ignores the error. |
| `request_stop() -> Result<UrgentTicket, String>` | Queue-independent, coalesced Stop obligation. Repeated outstanding requests return the same ticket; no unbounded urgent list. Error text alone does not prove retirement. |
| `request_panic_live(LiveScope) -> Result<UrgentTicket, LiveSubmitError>` | Queue-independent scoped panic obligation. Repeated requests for the same pending scope coalesce. Reject while Stop is pending. |
| `try_poll_update() -> Option<EngineUpdate>` | Nonblocking cumulative snapshot: worker generation/update revision, optional live progress, urgent ticket outcomes and first latched fault. Stopped updates can acknowledge Stop without inventing an active live session. |
| `is_retired() -> bool` | Nonblocking Acquire observation of irreversible worker retirement. A pending ordinary error may carry the terminal cause, so a second request-zero terminal notification is not guaranteed. Capture originals retain their separate uncertainty rules. |

`LiveReady` uses prepared source kinds (computer keys, pointer keys, pads and accessible pulse), not UI-guessed numeric handles. `LiveProgress` supplies authoritative scope, worker-accepted and callback-applied sequence watermarks (Options), active/release-tail voice counts, late-release/rejection/overflow counts, lease credit and first latched fault. Lease credit includes its issuing accepted-sequence watermark. `EngineUpdate` revisions and completed urgent tickets never regress within their worker generation. Coalescing cannot erase an unconsumed credit, completed panic fence or fault. A sticky stopped summary retains the ended scope needed to interpret an urgent completion. Existing `try_poll` still delivers exact once-only terminal errors; no normal snapshot replaces them. A latest-snapshot mailbox may use off-callback locking, with UI `try_lock` and no blocking waits.

Stop superseding Panic must acknowledge that ticket as superseded by a completed Stop after callback quiescence, rather than silently dropping it. Stop also fences all already admitted/in-flight starts through `cancelled_through_control`, the last admitted ordinary request ID: an old queued Start cannot create a new stream after Stop was acknowledged. Pending/in-flight normal completions must not reopen the UI's note gate when a newer Stop ticket exists. New starts require explicit admission after the Stop fence. The parent's admission gate must close independently of whether the UI has consumed a stopped snapshot.

Private initialization supplies `store_root`, random `worker_generation` and profile `omniusong.engine-live.v1`; `Initialized {profile, worker_generation}` must echo both. The exported build ID includes `-live-v1`. Private `LiveBatch`, `UrgentStop`, `PanicLive` and scoped `LiveFault` actions share the finite serialized exchange. Responses retain the ordinary reply plus an optional cumulative update. An internal live error needs validated matching-scope sticky fault evidence; otherwise retire the child with its exact cause. `LiveFault` requests callback clearing and cannot fabricate a successful Panic acknowledgement.

## Identities, generations and sequencing

StartLive prepares output, queues and voices before returning a fresh random session UUID, worker generation and initial event sequence. Session and panic generations scope every batch and every internal note/voice handle. They are not MIDI 2 protocol note IDs. Reject exhausted counters rather than wrap or silently reuse them.

Every batch carries session UUID, worker-generation UUID, panic generation and an exactly contiguous sequence beginning at 1, including empty GUI lease renewals. A rejection does not consume that sequence. Healthy acknowledged Panic creates a new panic generation and resets its sequence/watermarks to 1/None; old-generation queued batches are inert. Its events carry a prepared source handle/connection generation, source-observed monotonic ticks, and fixed NoteOn, NoteOff, source Sustain or bounded Pulse data. A source clock descriptor is established off callback; domains/epochs/rates are retained independently of audio frames. GUI receipt timing is not a calibrated audio coordinate. Native MIDI raw endpoint/connection/group/channel/packet information will have its own later adapter and original-event path.

Panic resets issued note/voice ordinals and sustain, but preserves each source's observed-clock high watermark within the unchanged GUI clock epoch. A newer panic generation cannot make an older source timestamp valid.

Bounds: 32 events per batch, 16 parent ingress batches, 16 worker-to-callback batches, 16 prepared sources and 64 live voices. This packet prepares exactly four bindings, one per public source kind, with immutable nonzero connection generations. Wire encoding is validated, versioned JSON with a 16-KiB batch ceiling; fixed Copy packets are process-local only. Never send Rust enum layout as an ABI. Batches/events must be bounded before queue admission and checked again at the worker boundary. The private engine capability/build/profile boundary prevents an older helper claiming live support merely because the package version matches.

Use distinct internal note and voice handles, nonzero and contiguously issued per prepared source within their session/panic-generation scope. Do not reuse them. Repeated same-pitch presses create distinct voices; NoteOff identifies its voice **and owning source/connection** and preserves 16-bit release velocity. Preserve 16-bit NoteOn velocity without a MIDI 1 zero-velocity reinterpretation in this API. Source bindings/connection generations are immutable during this first local session. Sustain is scoped to its prepared source/connection. Sustain release cannot release another source's held voices. A release for an already-issued ended one-shot is a counted no-op; a never-issued future handle is invalid, without requiring an unbounded tombstone list. An old generation cannot release a new voice. Release tails still occupy the fixed 64-voice pool until ended. A Pulse contains exact on/release velocities and a checked output-frame duration (at most half an output-second), with callback-owned automatic release; it does not depend on a future GUI timer or a same-frame On/Off pair.

The worker acknowledges whole-batch queue admission with its last accepted sequence; telemetry separately reports the callback's last applied sequence, active voices and latched faults. Never label queued events as rendered. Validate the entire batch before admitting it. Callback application must produce no partial batch's sound if application discovers a bad handle/polyphony fault: use bounded validation/staging, then apply; otherwise silence/panic and latch the failure visibly. Apply ordered events at the next defined callback/sub-block boundary, preserving in-packet On/Off order even at the same boundary. This is quantization to the next rendering boundary, not sample scheduling derived from GUI timestamps.

On current-session saturation, sequence loss, unsupported data or exhausted polyphony, fail closed: request callback-owned clearing of held voices/sustain and latch the cause until explicit Stop/new StartLive. Do not silently steal a held human voice, drop a release, clamp unsupported expression, or continue as if the whole batch succeeded. Generation changes invalidate queued old batches without letting them retrigger. A stale old-session/generation batch rejects inertly; it must not panic or retire a newer healthy session. Callback fault status cannot be cleared by ordinary Status or a healthy Panic acknowledgement.

## Panic, lease and UI loss

All notes off clears local held-key/pointer/pad/sustain maps before requesting panic. Control requests the next live panic generation, but **only the callback** mutates/clears voices and sustain. The acknowledgement must confirm callback-applied silence/fence, not merely queued control. Give requests scoped tickets; an old acknowledgement cannot clear a newer pending panic. Before returning a healthy rearm boundary, dispose of old accepted batches under the fixed callback drain bound so they do not fill the new generation's ingress. The UI admits no new notes until the matching acknowledgement supplies the authoritative generation, sequence 1 and token. Old batches and delayed releases cannot retrigger sound. A new physical press is required after cleanup; focus restoration must not replay held keys.

Stop closes live output using explicit render-closure **and error-closure** destruction acknowledgements, with control retaining all backing owners until both are proven gone. The existing finite Playback pause/drop alone is not proof of both acknowledgements. Bound the control-side wait and retire the entire process on failed native pause or uncertain quiescence before another device session. Parent EOF, worker failure and stream loss never restart audition automatically or replay a performance.

GUI-origin empty lease batches should be sent approximately every 250 ms while live audition is active. Ordinary supervisor Status polling does not renew the lease. StartLive supplies a worker-created one-use lease token; a GUI batch may consume that token once, and its receipt supplies the next token for the GUI to observe. The GUI removes its usable token as soon as the corresponding batch is parent-admitted, accepting replacement only from matching scope and a newer issuing accepted-sequence watermark. Other event batches explicitly carry `token=None`. Queued packets retain the token originally supplied by the GUI: the supervisor must never replace it with a newer token on the UI's behalf. An old-token event batch may be admitted under the normal sequence rules, but cannot renew the lease. Thus a backlog cannot keep renewing one credit after the UI has frozen. Panic rotates the token; a latched expired lease refuses late renewals and requires a new session.

The callback independently silences and latches a fault after at most one output-second of frames without a newly accepted GUI lease. The lease is measured in the output callback domain, not wall-clock or physical output delivery. One already-issued queued token may renew once after the last UI action; record that allowance explicitly. A UI freeze or stalled control exchange cannot sustain a voice indefinitely merely because the supervisor thread is healthy. The worker publishes the latest deadline at **whole-batch admission time**, never when delayed event packets are drained. Lease expiry and renewal use a checked atomic transition: reject when the frame counter has reached the old deadline, and use a bounded strong CAS with a sticky expired bit. No unbounded CAS retry occurs on the callback. Once expiry wins, no late token/status/Panic can rearm it. Split rendering exactly at the deadline, so a 2,048-frame sub-block cannot overrun the frame bound. The worker updates only fixed lease/generation counters off callback, with checked acquire/release ownership; token generation and wire handling never occur on the sample callback.

Progress publication must be coherent: paired voice/tail counts cannot contradict; watermarks, frame/counter values, completed tickets and first faults cannot regress. Running requires a credit, positive deadline and no fault; Panicking has no credit or fault; Faulted requires the exact sticky fault and no credit; Stopped has no active voices or credit. During the short first-fault publication sentinel, report Panicking without credit until the exact fault is acquire-visible. This transient never confirms a healthy Panic or reopens admission.

Lease expiry requires an explicit stopped/new live session, not automatic rearming by a late batch or focus restoration. The UI must surface the fault, clear local held maps and provide Stop/Start recovery. Idle healthy panic may keep an explicitly started silent audition open; it must not sound anything until a fresh post-acknowledgement human press.

## Callback ownership and work limits

Prepare oscillator tables, patch data, voice storage, ingress queue and telemetry owners off callback. Callback events contain fixed primitive handles and values only. No serialization, strings, heap allocation/deallocation, locks, filesystem, IPC, waits or device lifecycle calls in the hot path. Retain control-side ownership so dropping callback state is not the final owner of a heap/refcounted object during rendering.

Reuse the existing `RealtimeEvent` concepts for prepared note/voice values where they fit. The existing 256-event `RealtimeBatch` is not the GUI/wire DTO: it has different frame/source/patch/Sustain semantics. An indefinite LiveRender owner must not be represented by the finite prepared-PCM RenderCursor. The current fixed sub-block ceiling is 2,048 frames and the whole native callback ceiling is 16,384 frames. Invalid shape or excessive size fills silence and latches a fault. Split accepted larger native callbacks into checked sub-blocks; never assume a selected device uses that block size. Drain at most **four 32-event packets total per native callback**, including stale and empty packets, even if the producer keeps filling the queue. Sub-block splitting cannot multiply this limit. Fixed 64-voice rendering bounds the musical work independently of event producer speed.

Use a preallocated frequency table and finite, checked envelope parameters. Source/voice state transitions, output conversion, clipping policy and packet faults need independent review. Preserve actual device error/clock outcomes separately from a musical release or known queue overflow. No capture gaps, completed originals or recording alignment may be invented for this monitor-only mode.

## Interface behavior

Start audition is explicit; device selection alone opens no stream. The piano and pads must offer both pointer and accessibility activation. A discrete accessibility activation may be a bounded audible pulse with its own reliable release; it must not pretend to be a held key. Pointer-down/up/cancel, leaving the active surface, application focus loss and window closure require defined cleanup. Text editing, shortcuts/modifier chords and key-repeat must not trigger unintended musical presses.

UI buffers are bounded and are not a second unbounded performance journal. A failed admission clears the local held maps and requests reliable panic, rather than retrying an unknown subset. Show source/patch, velocity, live/not-recording state, negotiated output configuration, queued/applied progress and actionable fault text without implying measured physical latency. On-screen pad and computer-key mappings must be visible and avoid conflicting shortcuts.

Changing projects while audition is sounding must first acknowledge Stop, or visibly require it. Preserve the existing dirty Save/Discard/Cancel behavior for actual project mutations. An output-only audition must not manufacture a saved performance or change project history.

## Ownership and acceptance gates

The coordinator owns this shared contract, public/wire interface decisions, dependencies, capability boundary, integration and device/UI operation. Engine implementation owns live renderer, worker state, bounded ingress/priority/generation/lease behavior and its owner tests. UI implementation owns keyboard/pad controls, local held-state/cleanup and headless interaction tests after the public API is frozen. The independent reviewer owns adversarial callback/release/sequence/process tests and acceptance disposition. No agent runs Cargo, opens devices or operates UI concurrently with the coordinator.

The [independent contract review](../reviews/RUST-LIVE-AUDITION-CONTRACT-REVIEW.md) and engine/UI feasibility review identified the ingress/acknowledgement polling API, saturation/panic generation race, per-callback work bound, reliable accessibility pulse and GUI lease transport/token semantics. The coordinator incorporated those corrections and froze the Rust DTOs/private response types, source bindings, urgent Stop correlation and bounded atomic lease choices before the separate engine/UI implementation. Independent source and process review continues; implemented source alone does not qualify native playback, hardware MIDI or recording.

Required software evidence: repeated same-pitch voices, rapid on/off, zero and maximum 16-bit velocities, release velocity, per-source sustain, one-shot late release, full queues, polyphony exhaustion, lost/duplicate/stale sequences, Panic priority, pre-/post-panic batches, source/focus/parent loss, stalled exchange, GUI lease expiry, late lease refusal, variable callback sizes and callback allocation/deallocation checks. Preserve exact terminal errors behind queued replies. Prove no project/journal/asset mutation during audition.

Required actual Mac evidence: explicit output start/stop, keyboard and pad presses/releases, sustain, focus/text-field protection, All notes off and reopening saved work with all originals unchanged. Use output only under current authorization. A synthetic software render/capture/archive fixture may verify sample output and storage without opening input; label it synthetic. Physical controller delivery, listening quality, measured response, 30-minute continuity and Windows remain independent unfinished gates.
