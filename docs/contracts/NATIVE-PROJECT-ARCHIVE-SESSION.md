# Governed project archives in the session worker

This stage connects the three [governed performance-aware OSAR routes](NATIVE-GOVERNED-PROJECTION-ARCHIVES.md) to the sole Rust session worker. It adds compact typed completion, exact in-memory request correlation, cancellation and catalog retirement without activating a new native archive workflow. A separate qualification exercises schema-3 OSRE as inert evidence. Neither work grants source authority to a library summary, reader, attachment or document received in a reply.

## Request and worker admission

`Command::RunProjectArchive { request }` carries version 1 `ProjectArchiveRequest`: the exact canonical origin root and one `ProjectArchiveOperation`. Export binds a project ID and output pathname. Identity restore binds its input pathname. Copy binds the input pathname and the complete existing `RestoreCopyIntent`, including operation ID and whole-file SHA pin; the origin root separately binds the destination store, and copy allocates a fresh destination project ID. Identity restore currently has no expected input SHA argument; export currently has no expected saved-revision argument. This stage adds no bounded Inspect command. Durable confirmation cannot promise these missing pins.

Paths are bounded absolute UTF-8 lexical paths with no controls, aliases or non-normal components; their maximum is 4,096 bytes. IDs and SHA strings retain their existing validation. The strict JSON request cap is 65,536 bytes; its canonical encoding has a domain-separated SHA-256 fingerprint. Direct derived serde use is not a replacement for the bounded decode/validate boundary.

Execution requires an already opened store with exactly matching origin text. It neither creates nor lazily opens another store. Export additionally requires an ordinary nonsymlink canonical parent. A single default `InspectionBudget` and a distinct cancellation token cover the invocation, including a prepaid 2.5 MiB correlation/response allowance before fingerprinting or effects. Malformed admission or an initial governor stop returns a pre-effect outer error. Once this allowance is available, missing-store and later preflight failures return typed `Failed` outcomes with `invoked=false`; calling a store method, including recorded replay, sets `invoked=true`.

The worker calls exactly one bounded store route with that same governor. It does not load/list a project, read/hash an archive, serialize a full returned document or check cancellation after a successful store result. Those operations cannot turn its already completed mutation into a failure. Default lower limits remain unchanged: 512 MiB maximum individual file, 1 GiB cumulative credited work and the existing row/chunk/record/VM and private-plan caps. This is not a hard wall-clock or every-allocation bound and does not qualify 30-minute recording capacity.

## Compact result and errors

`Reply::ProjectArchive` carries version 1 `ProjectArchiveReply`, request fingerprint, invoked flag, outcome and independent optional catalog retirement. Export returns its bounded receipt; identity restore returns only project identity/revision; copy returns only its recorded operation/source/destination facts and `CatalogCommitted` or `RecordedReplay`. No project document or newly granted source token is transported. Exact replay can return its historical revision after later human edits without reinstalling that old document.

Cleanup problems remain warnings on success, retaining up to four exact path/detail issues plus an omitted count. Failed outcomes retain their primary problem, SQL origin/code, phase, source/destination/stage, available hashes and confirmed placements, plus a separate governor stop. `RecordedReplay` can survive a current-owned-source refusal; it is a known historical fact and does not authorize fresh execution.

Context validation follows actual incremental store facts. Initially invoked `NotStarted` failures can omit fields not yet observed, and early export can still have the root as destination. Normal export source is the root's catalog file. Later phases require their compatible paths, stage/hash association and placement limits. A second replay check after acquisition can carry both associated stage and observed SHA; the first check can carry neither. This representation is tested with constructed replies, not an executed concurrent replay race. Context paths are diagnostic association and confer no permission to open/delete them.

Catalog retirement is computed independently from the original store failure before bounded primary-message conversion. Only actual live-catalog failure/unusable facts can retire that generation; private/source/input SQL cannot. A matching malformed body cannot erase a valid retirement core. An explicit fatal live-catalog primary SQL diagnostic also conservatively retires when a malformed body omitted that separate core. Underlying recording compatibility finalizers can still replace a lower-level error before storage receives it, so this is not universal physical-error retention.

Reply strings use bounded UTF-8 formatting. Encoding counts before reserving the capped output vector; raw decode enforces 262,144 bytes and strict syntax first. `from_json` alone is not acceptance: callers must match the request reference, retain retirement and then call semantic validation. These DTOs currently travel over in-process channels; no new serialized worker transport is installed.

## Credit, cancellation and uncertainty

This command family shares the single worker credit. Replies must match generation/sequence, command kind and exact request fingerprint before consuming it. A foreign reference leaves the pending request intact. A matching reference first preserves retirement, then validates the body; invalid semantics consume the reply as Protocol with unknown outcome and install no project/proof. All three operations are explicitly non-retryable by generic session retry.

`cancel_project_archive` accepts only the exact pending request ID and changes only its distinct token. Cancellation retains credit until completion or disconnection and promises no rollback. The token resets only while credit is free before the next request. Client Drop preserves an accepted mutation's token, while retaining the older read-only inspection cancellation behavior. A completed store result survives a late cancellation. A verified EOF caches uncertainty across later polls; an empty generic retry slot cannot turn a non-retryable accepted mutation into known rollback. This is in-memory retention, not durable restart reconciliation.

## Native and evidence boundaries

The native coordinator rejects all raw new archive operations before assigning actions, consuming credit or changing drafts. Its defensive reply arm installs no document and runs no continuation. Existing backup controls retain their legacy guarded routes. The headless native guard test paints a frame and verifies rejection, preserved editor/name draft and no queued work; it does not qualify an actual application window or every draft combination. Durable exact-request admission, confirmation, unresolved restart/reconciliation, warning presentation and explicit subsequent document loading remain required.

The separate OSRE cases use genuine device-free performance writers, recovered originals and authenticated publication in both performance profiles, including copied ancestors and an unrelated ordinary project. An independent framing/digest and complete catalog/raw-tree oracle verifies full-root inert export/restore. Reviewed whole-container pinning refuses replacement; restored evidence can be inspected after the original archive is parked. Coherently rehashed false retained music remains inertly preserved while active closure/OSAR validation rejects it; a missing registered original refuses export. These checks add no active IDs or source authority. They do not qualify native OSRE controls or authorize adopting false metadata.

Final acceptance of this backend slice requires source-stable full-workspace and selected release tests, warnings-denied Clippy, formatting/default build, independent source review and an exact read-only preservation audit. Token/channel/constructor controls remain distinct from actual disk failures and native operations. No installed binary, microphone, device, listening, hard power-loss, long-capacity, MIDI 2/MPE transport, AI inference, plugin, installer or Windows acceptance follows. The full workstation goal remains active.
