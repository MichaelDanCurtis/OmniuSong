# Retained native studio evidence archive

October 22, 2026. OSRE version 1 is distinct from the per-song OSAR archive. The explicit `export_retained_evidence_full_root` request selects the **entire catalog and all currently retained bytes under captures/, source-actions/ and takes/**, including orphan ingest stages. It is not a selected-song export, an automatic upload, or a claim about material outside these namespaces. Selected-source and combined-song presentation remain later UI work.

The catalog is a bounded SQLite Backup snapshot (including committed WAL cells), preserving every SQL row and exact BLOB/TEXT payload, original intentions, reviews, action revisions, operation receipts, project relationships, assets and schema. This is logical catalog preservation, not a byte-identical physical image of the live catalog file. Only the new private snapshot is reopened/normalized to rollback mode; the live catalog is never checkpointed or rewritten by this path. OSREv1 supports native catalog schema 6 only; older/future schemas refuse unchanged, with no migration. Recording source databases and all sidecars are copied as raw bytes without SQLite opening, recovery or repair. Empty directories, unknown ordinary files and operational lock bytes are inventoried; none are silently truncated. Known missing required source/image/working/registered-object references refuse complete export. A request without an observed descriptor and an unexecuted/uncertain action may legitimately have no artifacts; the manifest retains those absence facts. Unsupported linkage refuses rather than inventing evidence.

Fresh export first takes one nonblocking process path lease covering the canonical source root and destination parent, including its private SQLite backup stage. Owned ingestion, recovered ingestion, store open and song archive I/O hold shared writer leases on their canonical store root and applicable archive file parent; raw evidence holds its exclusive lease through closure of every raw descriptor. Overlapping trees conflict in either direction, even across distinct store roots or archive destinations; disjoint roots remain independent. This also excludes ownerless private SQLite backup stages under takes, whose transaction locks could otherwise be released by an extra same-process raw FD close. A busy gate refuses before touching raw source files. Complete historical replay occurs before source-tree admission and needs no live tree. The brief process mutex only admits/removes active RAII leases, never holds file I/O, and creates no filesystem authority. Lease errors refuse without waiting; poisoned admission requires an explicit process restart. One nonblocking deterministic acquisition of every existing capture owner and action execution lease then protects cooperative writers. All existing owners are pinned and locked before any data descriptor is opened. Every nonowner descriptor closes before owner release on normal/error exits. A retained file with ASCII-case-insensitive reserved basename studio.sqlite3 refuses during metadata inventory, before data descriptors: a nested native catalog cannot safely be treated as an ordinary recording object. Opening a new nested store also requires an overlapping writer lease before SQLite; a refused new open may leave only its just-created empty directory. Existing source/action files require their known owners. No owner is created, truncated, deleted or restored as authority. Ordinary canonical directories, non-symlink single-link files, exact inode/size/mtime/ctime anchors, fixed file sets and bounded full hashes are checked before/after. Unix cooperative-owner/trusted-directory scope only. Do not hold a catalog transaction across raw copying or owner acquisition. The same NativeStore connection's data_version before the snapshot/inventory and after final proof must match; any intervening catalog commit refuses. SQLite Backup itself supplies a consistent short snapshot. The live catalog path has metadata-only inode/size/mtime/ctime/single-link checks before/after. Never apply std file locks or open/close an extra raw descriptor on the active catalog: the actual macOS tests exposed a SQLite lock conflict, and POSIX raw-descriptor close can release process locks. NativeStore's exclusive mutable borrow prevents same-connection writes during export. The process leases cover application-owned file writers across store instances; external direct writers must follow the documented cooperative-owner/private-namespace contract. Public archive inspection/replay holds an exclusive lease on the exact resolved input file, without claiming the sibling live store. Restore similarly claims the input file and inert output subtree. Native *.sqlite3, *.sqlite3-wal/-shm/-journal names are reserved case-insensitively for archive input/output; any existing <archive>.owner.lock also refuses metadata-only before raw open. This protects the native naming/lease protocol, not arbitrary same-process SQLite handles outside it. Private post-write verification reuses its admitted export lease.

Container: eight bytes `OSRE\x01\r\n\0`, little-endian u64 manifest length, strict canonical JSON manifest, each File entry's exact bytes in lexicographic entry order, then SHA256 of all preceding bytes (32 raw bytes), then eight bytes `OSREEND1`. No compression or new runtime dependency. Manifest <=2 MiB; <=2048 entries; relative slash-separated paths <=4096 UTF-8 bytes and depth <=12; no empty/dot/dotdot/backslash/colon/NUL/control path components, leading slash or duplicate/case-alias paths. Every directory is explicit. Nested native catalog basenames are unsupported, with complete export refusal rather than omission. Roots are exactly captures/source-actions/takes with presence flags; catalog.sqlite3 is mandatory. Manifest has version=1, a nonzero32lowerhex export_id, fixed scope string, bounded absolute origin_root provenance, catalog_schema, roots, missing declarations, and entries with kind directory/file, byte_length and optional raw SHA256. File hashes are mandatory, directory hash absent/length zero. Origin replay binds the same canonical root path without reopening it; this is not a cryptographic stable identity against coherent replacement of that entire root. Source bytes may be malformed, future, sidecar-bearing or unplayable; the format proves preservation, not semantic validity.

Use the existing sticky InspectionBudget (512 MiB per file including the archive, 1 GiB cumulative work, 32 million SQLite VM steps; no raised ceilings), charging all reads/hashes/copies/backup-page work and metadata processing. Before loading histories, conservatively reserve their entire compiled read/parse/hash ceilings (3 times 18 MiB) and bounded row credit; usage is reservation, not a measurement of actual catalog size. More passes can refuse below file ceilings. No total disk quota or long-capacity claim. Cancellation retains any private catalog stage, partial destination or inert restored objects. Only the current request's successful catalog stage may be retired, without deleting evidence.

Export destination is an ordinary canonical parent outside the live root; exclusive create and an OS file lock prevent overwrite/racing read. The final digest/footer is written only after all source/file-set/catalog fences pass, then file and parent sync precede receipt. Existing same-ID complete archive is authenticated before any live-source requirement and returns a historical receipt; different-ID or partial bytes refuse unchanged. The caller retains exact export ID/path. No retry silently recopies partial bytes or changes that request's destination/source set.

Inspection, historical replay and restore share known-reference closure validation after strict manifest, file hashes, full footer/hash and EOF. Only the authenticated catalog bytes are buffered, with allocation/copy credit reserved before allocation. A second bounded SQLite-owned buffer is deserialized read-only in memory under the same sticky VM/cancellation governor; raw recording objects remain streamed and unopened in SQLite. The existing rusqlite serialize feature adds no new crate/runtime. An already length-verified buffer/Cursor avoids the version's fallible-reader allocation leak. Check catalog user_version, ordinary known linkage tables, their exact expected column set with no hidden/generated/default expressions, all required members and exact optional absence facts. Layout validation precedes value projection because a single generated builtin could allocate outside VM-step accounting. Rehashed omission of a referenced object therefore refuses even with unchanged valid catalog bytes. Checksums do not authenticate a coherently rewritten catalog plus index or prove an omitted unreferenced file against a malicious archive author; complete capture is established by the creator's exact inventory/ownership/fences.

Restore creates one exclusive private directory and writes payload to **numbered objects**, with original paths only as inert manifest provenance. Thus captured database sidecar and lock names never become live SQLite neighbors or executable identities. No active catalog, source ledger, recording intent, operation, capture, take or action is inserted. Pin output root/objects identities, independently verify every object and canonical manifest, and require exact membership before publishing complete.json; sync and final membership/identity checks precede receipt. Failures retain incomplete private material and never overwrite an existing destination. A subsequent reviewed adoption/mapping requires a separate explicit action. Exported absolute paths, reserved operation IDs and unknown metadata remain historical bytes.

Root owns format/store integration; raw inventory implementation and independent tests have separate owners. Required tests: actual catalog exact SQL rows; original/evidence/working/sidecar/unknown/empty/ingest closure; lost-ack replay without live sources; corruption/truncation/trailing bytes/path aliases/duplicate entries/oversize; existing targets; cancellation/limits; active owners; separate-process SQLite writer probes before/after refused owner acquisition and ownerless-ingest export, two-handle bidirectional coordination and historical replay, overlapping/nested roots and cross-root destinations, actual WAL/SHM wrong-input refusal; symlinks/hardlinks/ancestor substitution; missing required references; concurrent catalog/file-set change; private inert restore and unchanged live histories/originals. Native UI, operator rollback, long-session, hard power loss and Windows remain separately unqualified.
