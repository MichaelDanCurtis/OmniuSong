# Explicit recovered-source choices and attachment

October 22, 2026. Extends NATIVE-SOURCE-ACTION-EXECUTION, retaining exact Prepared1/Started2/Verified3 and review bytes. This packet adds a Unix backend path for a verified copied recovery. Native UI, normal-source adoption, parking before Verified, multiple successful placements of one action and complete evidence archives remain subsequent requirements. Do not change the existing normal-only performance-intent guard or relax bounded reader export refusals.

## Immutable decisions after Verified

Append canonical <=16-KiB `PerformanceSourceDecisionRevision { version:1, id, prepared_payload_sha256, verified_payload_sha256, decision }` only after Verified3, through revision16. Every envelope references the exact Prepared/Verified row hashes, same immutable review, strict serde shape and whole validated-history fence. Preserve the existing 32-identity/16-revision/raw-review/reply limits. Fold these events separately from the original execution result; the action head's revision/hash may advance while execution remains the original Verified.

`PerformanceSourceDecision` is a caller request: KeepLocally; ReturnToReview; PrepareAttachment { choice }; RetireAttachment. Stored `PerformanceSourceDecisionEvent` is: KeptLocally; ReturnedToReview; AttachmentPrepared { choice }; AttachmentRetired { choice_id }; AttachmentCommitted { choice_id, project_revision }. A caller cannot submit a committed event.

`PerformanceSourceAttachmentChoice { id, supersedes:Option<String>, publication:TakePublication }` has a fresh nonzero32lowerhex identity. The publication operation must equal `os-src-attach:` + SHA256(domain `OmniuSong.source-attachment.v1\0`, length-prefixed action ID and choice ID). Reserve this namespace against generic AttachCapture, publish_take, project-operation insertion and identity-preserving inbound archive operation insertion. Outbound archive preservation and restore-as-copy operation remapping remain supported. New generic metadata choices cannot claim it; existing historical metadata bytes remain readable. Only the dedicated fenced bridge may insert it. All historical choice IDs and publication operations are unique across source-action history and cannot reuse a copy recovery operation or a recording-intent attachment operation.

An initial choice has no supersedes. A replacement requires the exact previous retired choice ID, fresh choice/operation identity and an explicit new publication. Pending or committed choices cannot be overwritten. Only one successful attachment per recovery action is supported in this packet. The complete publication binds target/project revision, track/default name, new clip ID, exact Verified take/manifest, audio stream, full selected checkpoint audio range [0,checkpoint.audio_end), matching source sample rate and explicit nonnegative timeline frame. No caller-provided edit snapshot or fades; later clip edits use the normal editor. Never infer target/placement from a linked recording intent or current UI selection.

`PerformanceSourceDecisionState { kept_locally, attachment:Option<PerformanceSourceAttachmentState> }` stores the current derived view. Attachment state retains the immutable choice's row revision/hash, choice and status Pending/Retired/Committed{project_revision}. Keep/Return toggle disposition without clearing the choice or historical commitment. Keep does not cancel an accepted action, retire its publication, delete evidence or change legacy intent.released. Attachment preparation/execution requires Review disposition; historical committed observation remains available when kept local. Before preparing require room for choice, outcome/retirement and a Keep row (`head+3<=16`). Keep/Return require a real toggle and must leave one settlement row while an attachment is pending. Exact current metadata-request replay is allowed without append; stale historical requests cannot reapply a decision.

Commands: `SavePerformanceSourceDecision { id, revision, payload_sha256, decision }` uses exact current head, returning `PerformanceSourceDecision(Box<ActionState>)`; `AttachPerformanceSource { id, revision, payload_sha256 }` and read-only `ReconcilePerformanceSourceAttachment { ... }` refer to an exact retained AttachmentPrepared row, returning `PerformanceSourceAttachment(Box<PerformanceSourceAttachmentReceipt>)`. The receipt keeps state, exact publication, historical committed boolean, replayed flag, and current `Option<DocumentView>` plus optional current-document error. Do not erase historical commitment if latest files/document are unavailable. A structured current-document StorageUnavailable error still retires the session worker after delivering that receipt. No automatic attachment or UI continuation.

## Atomic publication and retirement

Root store APIs:

- `take_publication_receipt(&TakePublication)->Result<Option<EditReceipt>>`: exact historical postcondition, metadata-only, no take/file open. Existing bool API delegates to it. A history-fenced read variant observes the receipt and validated ledger in one metadata snapshot.
- `save_performance_source_action_if_history_matches_and_unpublished(id, expected_revision, review, payload, expected_history, publication)`: full history fence and exact publication receipt ABSENCE in the same IMMEDIATE transaction before appending retirement. A receipt/corrupt receipt refuses; absence is never inferred from a source error.
- `publish_source_attachment(publication, id, expected_revision, review, committed_payload, expected_history)->Result<(EditReceipt,StoredPerformanceSourceAction)>`: one IMMEDIATE transaction fences all source history, requires the exact current prepared choice/operation to remain eligible through the service contract, and commits project, project history, operation receipt and source AttachmentCommitted row atomically. Rollback all SQL on any mismatch. No separate Started attachment row is needed. Return a known revision conflict without any project/ledger write; ingested originals may already be retained.

A retired choice is barred from this bridge by its history fence and active-choice validation; generic namespace guards prevent stale bypass. An in-flight ingestion may finish retaining an owned object after another service retires the publication, but its old history can never publish afterward. Retirement establishes publication absence and blocks later publication, without claiming that no owned copy or recovery was written. An uncertain failure permits retry of the same immutable choice; explicit retirement is possible only after the atomic absence/fence proof. Do not manufacture a replacement recovery copy/action/manifest.

## Bounded original ingestion and ownership

First query the exact historical receipt, before requiring any original, evidence, action lease, working or owned path. Committed replay loads the current document rather than installing its historical postimage. A recorded Committed must have the exact receipt; a missing/damaged receipt is not an uncommitted choice. Reconcile only observes: never ingest, append, retire or publish.

For a fresh uncommitted attachment, acquire the existing action lease. If the take is registered, prefer and authenticate the owned object with one sticky source governor, including descriptor, manifest, selected checkpoint/count/index, deterministic recovery operation and all original-row identity against Verified. A damaged/different owned object never falls back to working artifacts. Otherwise hold RecoveredCopyView and existing engine reconciliation under the same governor, then explicitly export its working bytes into an exclusive new owned stage. `RecoveredCopyView::export_working_copy(destination)->Result<BackupReceipt>` copies anchored raw working bytes, verifies exact hash/length/identity before and after, syncs target and parent, preserves typed cancel/limits and retains any partial. It never uses SQLite backup, creates an owner lock, cleans an error, or enables generic bounded exports.

Root `NativeStore::ingest_recovered_copy(view)->Result<TakeObject>` registers an exact raw copy with full original-row/manifest checks even on dedup or a concurrent same-take registration. `open_take_with_budget(reference,budget)->Result<SealedJournal>` must use bounded open, full physical hash/metadata checks and shared-governor full-original inspection. Hold the action lease and authenticated view/owned snapshot through publication. Preserve source/evidence/working bytes, unknown tails, faults and original stream data. The additional owned copy has a separate file ceiling; the earlier two-database reservation is not a total storage quota. Do not raise governor ceilings; extra proof may refuse below size ceilings.

Source/owned-file errors remain local. Actual main-catalog errors retain fatal handling. Cancellation is the distinct exact source-action token, never inspection/Drop; retain worker credit through completion. Worker EOF/protocol failure on attachment reconciliation preserves prior publication uncertainty. UI dispatch rejects all added backend commands until their separate integrated acceptance. No native input, main-store migration, new package, paid calls or Fuego changes in this source packet.
