# Retained projection source closure

This contract governs the Rust read-only `NativeStore::inspect_retained_projection_closure` diagnostic. Its version-1 summary reports the selected project and bounded snapshot, history, operation, associated-proof and distinct-binding counts. Counts are not a stored proof, adoption permit, archive admission token or current playback result. The complete native workstation goal remains open.

## Held live-catalog scope

The diagnostic owns one retained-file coordination lease and a deferred transaction on the actual live catalog. The same caller-supplied sticky inspection governor covers SQL VM work, raw metadata prepayment, source collection, source authentication, geometry, binding interpretation, lineage checks and final fences. It cannot reset the account between passes or sources. Fixed transaction controls and filesystem stalls retain their existing timing limitations. Private archive handles must not enter this live-catalog error domain.

The first pass streams the current project, both sides of every retained history edge, every operation result and all associated ancestor-proof results. It retains exact source roles and a bounded asset union rather than whole documents or histories. Raw row lengths are checked and charged before materialization; hard SQL `CASE` bounds remain as an independent row fence. Existing document, request, proof, history, operation, object and aggregate metadata ceilings are preserved. Hidden redo history and disconnected retained operation results remain in scope.

The source collector upgrades only the original actually used as a performance source. Ordinary audio recordings remain ordinary, schema-1/2 opaque lookalikes remain opaque, and conflicting exact references refuse. The holder opens the complete registered union, authenticates each distinct performance original once and retains those readers through the semantic pass and final registration/source-identity checks.

## Every retained occurrence

Every document occurrence receives reference and clip geometry validation. A bounded canonical binding memo uses unchanged projection identity as its key. A first binding is admitted to that memo only after actual original-performance rederivation. Every later occurrence must match the complete canonical binding bytes; a different but individually source-valid choice under the same identity refuses. Current edited notes or deleted lanes do not replace the retained original binding.

Every distinct binding, including one found only in an ancestor result, must link to the selected live project's deterministically named typed publication. Ancestor document project IDs remain historical. Every projection operation result must have its exact canonical request/result hash, adjacent revisions, final registry append, retained request/review/source pins, original lane choices and complete initially muted lane postimage. Metadata consistency is checked separately from real source authentication. A pruned before-image is not fabricated.

Each retained forward history pair must preserve the registry or append one matching publication whose complete candidate reconstructs from the actual before document. The old opaque-field promotion fence remains. Undo does not reverse the meaning of the stored forward edge.

Associated lineage checks retain strict bounded canonical proof envelopes, result digests, complete ancestor associations, copy-admission identity, framed mapping digests, live mapped-operation hashes and transitive parent mappings. Ancestor results receive source/binding checks; missing ancestor requests or preimages do not become claimed historical execution. These records establish internal consistency, not who originally confirmed an operation.

Dense sorted ancestry uses merge comparisons with governor credit before each bounded hash comparison. Parent lookup, cycle checks and immediate-edge selection are also prepaid. Deterministic receipt lookups bound and prepay the stored project namespace even when that row belongs to a foreign project excluded by the selected operation scan. Missing typed history requests refuse semantically while actual SQLite failures retain their domain.

Success requires final exact take registrations, held original identities and a final governor checkpoint before rolling back the read transaction. Errors preserve actual live-catalog fatal/cleanup classification and source-journal error separation. Failed inspection publishes no project, history, receipt, copy or source authority.

## Qualification boundary

The verification packet must identify actual real-source tests, coherent rehash attacks, cancellation/quota refusal, connection reuse and exact no-mutation comparisons. Synthetic sealed performances establish device-free source semantics; they establish no native input, listening, inference or sustained capacity result.

This diagnostic does not validate a complete OSAR file's schema, global row set, archive index, imports, byte transfer or destination postimage. Public nonempty projection export, identity restore, copy, guarded readers/list and unmigrated attachment paths remain closed until coherent route integration passes. Private archive SQL error isolation, typed completion/cleanup outcomes, final installed-path authentication and exact expected SQL postimages precede that activation. A separate schema-3 inert OSRE roundtrip, durable native admission and a named-binary walkthrough follow. No catalog/archive/musical schema or installed bundle changes here.
