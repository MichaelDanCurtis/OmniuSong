# Durable copied-recovery execution and reconciliation

October 22, 2026. Extends immutable [Prepared choices](NATIVE-PERFORMANCE-SOURCE-ACTIONS.md) and [copied recovery](BOUNDED-COPY-RECOVERY.md). This gate adds backend execution, not project publication. The native UI remains closed until its distinct acceptance.

## Frozen history and requests

Keep schema 6, all exact review bytes and Prepared revision 1 unchanged. No migration/new table/eviction. The existing append-only source ledger accepts these additional canonical payloads only: revision 2 ExecutionStarted, then revision 3 Verified. Each execution payload denies unknown fields and binds version 1, action ID and the exact Prepared payload SHA. Started records a submitted/authorized attempt, never proof that a file was copied or a manifest committed. It remains durable uncertainty after a refusal, crash or lost reply. No invented later revision or replacement Prepared is legal. Saving a Prepared choice after execution started refuses without appending it again. Listing Prepared choices returns their immutable revision-1 receipts; separate states expose the latest history.

`PerformanceSourceExecutionRevision { version, id, prepared_payload_sha256, phase }` uses `PerformanceSourceExecutionPhase::{Started, Verified { result, usage }}` with nested `#[serde(tag="state", rename_all="snake_case", deny_unknown_fields)]`. `RecoveredPerformanceSourceResult` is a compact stable summary: take_id, descriptor_sha256, original_rows_sha256, evidence_sha256, evidence_bytes, working_sha256, working_bytes, manifest_sha256, selected_chunk_count, selected_chunk_index_sha256, unknown_tail. Validate summary identities/bounds against the exact retained review; unknown_tail must be true. Usage is retained diagnostic evidence within compiled limits, separate from stable-result equality on later replay. Full manifests remain in the authenticated artifact, not a 16-KiB ledger payload.

`PerformanceSourceActionState { prepared, revision, payload_sha256, execution }` exposes the immutable Prepared receipt plus current row and optional execution revision. `PerformanceSourceExecutionReceipt { state, observed, usage, replayed, original_reopened }` separates recorded phase/result from a fresh artifact observation. `original_reopened=false` means reconciliation did not require the original path; it does not say that path is missing. Lists/rows stay bounded by existing 32 identities, 16-KiB payload and 576-KiB reply ceilings.

Commands are ListPerformanceSourceActionStates; ExecutePerformanceSourceAction and ReconcilePerformanceSourceAction, each taking id, revision and payload_sha256. Require an exact retained historical row of this same immutable action. Only a current Prepared request may start fresh execution. A historical retry after Started/Verified may authenticate the same existing result; it cannot restart copying. Read-only reconcile never appends an outcome, creates a namespace/lock, continues a partial action or executes recovery. Explicit Execute may append Verified for an authenticated existing result or return the exact recorded Verified state with a fresh observation. No automatic attachment/adoption follows.

## Ordered execution and ownership

Load and validate the whole bounded history/reviews/origin relationships first. For current Prepared, open/authenticate the source read-only with one sticky governor, retain its existing owner and compare the complete fresh source-admission projection excluding diagnostic usage. Refuse busy/stale/cancelled/invalid sources before Started. Append Started with the entire validated history fence and verify its exact committed receipt. A lost/uncertain Started acknowledgement must not perform filesystem writes. Only that winning fresh append may create a new action; another process with an older history conflicts before exact-payload replay.

After confirmed Started, validate/create root-derived source-actions parent, exclusively create the empty `<id>.execution.lock` outside the action directory, acquire/anchor its OS lock, then invoke the fresh copied-recovery library while retaining source ownership. Hold the execution lease through result authentication and catalog outcome publication. Existing action/lease files never authorize fresh work and are never overwritten or cleaned up.

After a retry/restart, acquire only the existing execution lease and inspect the same evidence/working paths before touching the original capture path. Missing, partial, unsealed, aliased, changed, unsupported or sidecar-bearing artifacts refuse unchanged. **Started plus absence is not proof no mutation occurred; never recreate it**, even if the original remains available. Completed replay authenticates the exact original image SHA/length, all original rows, source semantic review, selected checkpoint, recovered manifest and versioned operation derived from the original admitted review. No new ID/manifest/normal authority is minted.

`CopyActionOwner::{create,open_existing}(parent,id)` binds ordinary single-link empty lease identity. `RecoveredCopyView::open(&owner,image_sha,image_bytes,&budget)` opens the image read-only without creating image.owner.lock and holds the working CaptureReader owner. Its evidence inspection/ordinal reader and working reader share the same governor. It requires canonical schemas, exact descriptor/all-original identity, normalized full interruption evidence and recovered-only state, and rechecks frozen bytes, identity, lease and all sidecars before receipt. It never opens the original capture path.

The fresh copy API releases its working owner when returning its receipt. Retain the execution lease, then reacquire the working owner with a complete fresh RecoveredCopyView proof under the **same** governor, and hold that view through Verified publication. Do not claim continuous working ownership across that documented reacquisition. Initial copy→mutation ownership remains continuous. Root ordinary directories/cooperative owners remain the supported model; Unix identity qualification and existing resource ceilings apply. Extra proof passes may refuse below size ceilings.

## Errors, cancellation and publication

Source/artifact faults remain local and do not quarantine the project catalog. Real catalog failures retain existing fatal handling. After Started, even a known no-commit metadata conflict must not imply the recovered file did not commit: retain recovery outcome uncertainty and every artifact. A read-only reconciliation failure carries uncertainty about that prior execution, without claiming the reconciliation request wrote anything. A cancellation kind alone is never proof of rollback. Preserve historical Verified bytes when current files become unavailable. Do not silently regress to an older project or substitute a new source.

Recovery uses a distinct correlated cancellation token/API. cancel_source_inspection, stale IDs and the read-only Drop token cannot cancel an accepted execution. Pending request/worker credit remains occupied until exact completion; no detached replacement worker after observation timeout. Cancellation/limits reach physical/semantic/SQL proof with typed sticky errors. Closing a caller does not promise rollback. Keep exact operation/receipt/review IDs and distinguish recorded success from current source availability.

Test actual synthetic writer→Prepared→Started→copy→Verified and reopened same-artifact proof with original removed, all catalog/original invariants, both acknowledgement gaps, separate-process ownership, stale/malformed requests/histories, source-local failures, complete/partial/missing/changed artifacts, cancellation/credit correlation and result-CAS conflict after recovered commit. No main-store migration, new package, native input, paid calls or Fuego changes belong to this source gate. Keep-local, explicit attachment/conflicts and complete evidence export/restore remain required subsequent work.
