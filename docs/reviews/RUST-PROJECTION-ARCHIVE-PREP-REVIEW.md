## Source collection and held authority

`RegisteredSourceSet` collects references incrementally without retaining documents. It borrows the opening governor, charges each traversal even when references deduplicate, groups exact references by take identity and unions ordinary/performance roles monotonically. Schema-1 opaque lookalikes do not acquire native source ownership. Conflicting manifests remain distinct references until the registered-object check rejects them; collection does not silently select a preferred manifest.

An unsuccessful addition poisons the collection, including ordinary validation failures that do not themselves stop the governor. `open_collected` consumes the collection and refuses a failed partial set before opening source paths. Source owners retain the opening budget borrow; authentication checks governor identity independently of whether the source map is empty. This closes the empty-set loophole in relying only on per-reader governor checks. Existing reader identity, exact registration, reference/clip geometry and retained-binding validation remain in place.

Collection itself is neither proof nor an archive completeness check. The current active load/edit/publication call sites use the same wrapper semantics as before. The new streamed entry point enables a later row-by-row archive visitor; it does not implement that visitor, a binding memo, all-history closure or a relocation capability.

## Canonical operations and copy identities

`ArchiveOperation` is crate-private and distinguishes ordinary edits, wrapped take publications and strict projection publications. Input and canonical ordinary-edit output are bounded by the existing 64 KiB worker ceiling. Destination IDs are length-checked at 96 bytes and validated before cloning/remapping; the unused ordinary ID is deliberately ignored for a projection. Every parsed request must equal its typed canonical encoding, and explicit row identity validation binds operation ID, project ID and previous revision. Direct enum construction is revalidated before comparison or remapping. The helper grants no source or postimage authority.

Projection remapping changes only the destination project and its deterministically derived operation ID. It preserves the interpretation request, source pins, review digest, lane choices, projection ID and revision. Ordinary remapping preserves opaque extensions and nested clip fields. Reserved prefixes alone do not reclassify historical ordinary receipts.

The actual copy helper checks the selected operation against destination operations, copy admissions and pending-map destinations; source operations and, where present, source copy admissions; and the outer reserved restore request. The version-1 branch avoids querying absent lineage tables. Deterministic projection collisions refuse rather than obtaining another identity. These checks select an admissible name; they are not a reservation independent of the caller's transaction and pending-map insertion.

I found one compatibility blocker in the initial classifier: presence of top-level `projection_id` selected the projection DTO, but `ProjectEditIntent` has flattened extensions and legitimately permits that opaque key. Previously valid ordinary archive receipts could therefore be rejected. The corrected classifier first recognizes an edit's `scope` and `edit` fields and still requires complete valid canonical edit decoding. Bare malformed projections do not gain an edit fallback without those required fields. A canonical ordinary edit carrying projection-looking opaque fields remains an ordinary edit, not a projection publication.

The corrected tests serialize actual edit DTOs with top-level `projection_id` null/string, `request` and `lanes` extensions, rather than relying on a generic JSON map's noncanonical field order. The public regression exports an ordinary project, restores exact identities, copies, replays the mapped edit, reexports and identity-restores that copy. It checks the exact original request bytes, unchanged source document, all copied extension values and correctly remapped owned identities. The shared older copy fixture also retains these flattened fields. The output-ceiling test uses valid 96-byte IDs and requires the specific bounded-writer error, so unrelated identifier rejection cannot satisfy that assertion.

## Admission remains closed

Archive `validate_request` explicitly refuses a parsed projection publication. `Bundle::references`, `Proof::document` and the guarded global metadata/reference readers retain their nonempty-registry refusal. Existing note/clip postimage checks and supported ordinary edit checks remain after shared parsing. The copy route still performs complete existing metadata validation before remapping. There is no public path from successful syntax/remapping to admitted projection ownership.

The proper name for this slice is **archive preparation**, not source-semantic archive completion. No schema migration, archive format change, new native control or installed package follows from it.
