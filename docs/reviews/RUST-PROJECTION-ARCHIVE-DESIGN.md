# Source-semantic projection archives: implementation design

Date: 2026-10-22. This is a source-informed design, not implementation or test acceptance. I inspected the current [archive](../../crates/omniusong-store/src/archive.rs), [copy/lineage](../../crates/omniusong-store/src/archive_copy.rs), [held sources](../../crates/omniusong-store/src/projection_sources.rs), [publication](../../crates/omniusong-store/src/projection_publication.rs), [portable intentions](../../crates/omniusong-store/src/projection_publication_types.rs), [catalog scope](../../crates/omniusong-store/src/catalog_transaction.rs), OSRE closure and [next implementation slice](../IMPLEMENTATION-PLAN.md). No tests, stores, applications or devices were opened. Only this design document was changed.

## Delivery decision

First implement and test the reusable bounded semantic closure and canonical operation/remapping helpers while retaining every public OSAR nonempty-projection guard. Then activate export, identity restore and restore-as-copy as one coherent integration. The first slice is a consequential prerequisite, not complete archive support; export alone must not be presented as completion. This separation follows concrete differences in installed-source lifetime, SQL/error ownership and publication outcomes. It introduces no new framework, catalog migration, archive format, native control or dependency requirement.

Keep OSAR v2 and existing strict v1 reads. Current project IDs, native take/stream references, physical original bytes, immutable reviews, projection/lane/note IDs and opaque metadata remain portable. Copy changes only the identities its existing contract owns. NativeReader/list/attachment admission remains guarded until separately integrated. The full Mac-first Rust workstation, later Windows, MIDI 2/MPE and recording requirements remain unchanged.

Coordinator decision for the later typed restore route: choose final-path authentication after content-addressed object installation, consistent with the existing retained-orphan failure contract. Failed admission may retain diagnosed unregistered objects and staging; it must leave no committed project/history/operation authority. Hold final-path proofs through exact expected-postimage, registration, asset and identity checks before the sole commit. This decision is not an activation or a new orphan-cleanup action.

The first preparation gate covered the role-aware streamed `RegisteredSourceSet` and canonical `ArchiveOperation` parser/remapper with collision checks. The later [retained source-closure contract](../contracts/NATIVE-RETAINED-PROJECTION-CLOSURE.md) adds the live-catalog streamed snapshot validator and exact binding memo as a separate qualification scope. Private-input error isolation, typed archive completion/cleanup outcomes, installed-path authentication and expected destination postimages remain required. Public nonempty projection guards remain closed until the three routes are activated together.

## Small private interfaces

Use a new store-private `archive_projection.rs`, with focused child tests, plus narrow changes in `projection_sources.rs`, `projection_publication.rs`, `archive.rs` and `archive_copy.rs`. Suggested interfaces are implementation contracts, not new public authority:

```text
SourceRole = Audio | Performance                 // union upgrades to Performance
ArchiveSourceClosure::observe(document, budget)
ArchiveSourceClosure::finish() -> bounded source/reference and binding inventory
RegisteredProjectionSources::open_closure(root, catalog, closure, budget)
sources.authenticate(budget) -> ProjectionProofs borrowing sources
ArchiveSemanticValidator::new(closure, proofs, budget)
validator.document(document)                   // geometry plus exact binding reuse
validator.publication(request_row, result)
validator.forward_pair(catalog, before, after)
validator.finish(catalog)                       // complete linkage and final identity
classify_archive_request(exact_json) -> Edit | TakePublication | ProjectionPublication
remap_projection_request(intent, destination_project) -> canonical intent
```

The inventory has no proof authority. Only a validator borrowing actual held source proofs can qualify semantics; do not serialize it or accept a caller-created receipt as its substitute. Keep a convenience read-only validation entry point for synthetic tests, returning only bounded counts/digests. Integration must retain the source owner and borrowed proofs through its final fence instead of returning a success token and reopening paths later.

Split archive metadata traversal from admission privately. Do not weaken global `load_document`, `check_references`, `visit_document_takes`, `Bundle::references` or `Proof::document` guards. A new archive-only metadata reader may decode untrusted snapshots under prepayment; its output becomes eligible only through the held validator. Existing ordinary routes keep their compatibility wrappers and qualification until migrated.

## Complete retained closure

Stream each bounded row rather than collecting documents or history in memory. Visit current project, both sides of every retained edit, every operation result, and every associated lineage proof result, including ancestors whose project identity is historical. Continue validating original imports, contiguous history sequence/cursor constraints, operation request/result hashes, archive indexes, complete lineage associations and mapping closure. History hidden by Undo and results from pruned redo branches remain in scope.

The first pass accumulates exact references grouped by `TakeId`. Clip-only references have ordinary recording semantics; any projection reference upgrades that take to performance authentication. Preserve every exact stream/manifest reference and check conflicts. Current `RegisteredProjectionSources::open` cannot receive `bundle.takes` through its `extra` parameter: that parameter marks every reference as performance. An ordinary audio journal must not be required to contain performance records. A mixed audio/performance original receives one performance proof, while all its clip windows still receive geometry checks.

The second pass validates every document against held sources. Memoize each successfully rederived exact binding, keyed by its unchanged projection identity; compare complete bounded canonical binding bytes on every recurrence. A hash is only an internal lookup aid after actual validation. Every appearance of one projection ID across current/history/results/ancestor proofs must preserve its original binding. This prevents a source-valid but different lane choice or original binding from hiding in an otherwise disconnected operation result. Current editable note values and lane presence may differ or disappear, as permitted by core ownership; they are not substituted for the immutable original binding. Validate document/reference/clip geometry on every occurrence even when binding interpretation is cached.

Resolve each encountered binding to its typed publication row for the live project namespace using `projection_operation_id(project_id, projection_id)`, including bindings found only in historical results or ancestor proofs. Copy retains those IDs and remaps all live operations, so it can maintain that linkage without adopting historical ancestor project IDs. A missing or incompatible row refuses instead of manufacturing a publication.

## Publication and historical meaning

Add a strict finite request classifier. A projection publication has top-level `operation_id`, so the current archive branch that treats every such request as `ProjectEditIntent` is insufficient. Decode the matching strict DTO, require its exact canonical bytes, and validate its own version/identity rules. Do not infer publication merely from an operation-ID prefix or loosen unknown-field handling. Preserve existing legacy operation support and explicit source-attachment namespace restrictions; a historical ordinary identifier cannot acquire projection authority through dispatch.

Extract the bounded metadata consistency check presently inside `recorded_commit_with_budget`: exact request and deterministic operation identity; adjacent revisions; canonical result bytes/hash; last appended binding; exact retained request/review/source pins; tempo bits; lane choices; and complete initially muted note-lane postimage. It remains a consistency check, not source proof. Pair it with the validator's independently rederived bindings for every typed publication result, including results without a retained preimage.

For every retained forward history pair, require unchanged registry or exactly one append. Reuse `validate_forward_transition` to require the matching typed request/receipt and reconstruct the complete candidate from the recorded before document. Preserve the opaque-promotion refusal. Undo is checked in stored forward order. Do not reconstruct a missing preimage by deleting tracks from a result: the old bars, extensions and upgrade context are not recoverable that way.

Ancestor copy proofs contain a result and operation mapping hashes, not complete ancestor request/preimage rows. Authenticate each ancestor result's bindings and geometry, preserve exact proof bytes and validate existing transitive mapping linkage. Require the retained live typed publication linkage described above. Do not claim to reconstruct absent ancestor execution or prove historical user confirmation. A coherently authored archive can be semantically consistent; neither its hashes nor its lineage records are cryptographic evidence of who performed the original action.

## Budgets and SQL ownership

Use the same sticky `InspectionBudget` across closure scanning, metadata decoding/copies, private SQL, source authentication, binding interpretation and final verification. Prepay raw lengths before materializing project/request/proof/manifest/asset data; cap each row before deserialization. Bound canonical memo bytes and charge allocation before retaining them. Cache exact repeated bindings so duplicated history does not repeatedly interpret the same original. Never reset the governor for a document, source, remap or second validation pass.

Retain the existing ceilings: 8 MiB native document, 64 KiB publication request, 512 KiB manifest, 256 MiB aggregate archive metadata, 4,096 distinct objects, 10,000 edits, 100,000 operations, 256 lineage proofs and 1,000,000 total mappings. Keep existing OSAR chunk/payload limits separately. The performance governor still caps inspected files at 512 MiB and cumulative work at 1 GiB; it may refuse an archive below the outer archive limits. Do not raise limits or pretend outer byte limits guarantee semantic admission. Exact binding caching does not remove charges for traversing repeated metadata or checking each occurrence.

Private archive connections need private read-only progress ownership and guaranteed teardown; the existing no-reuse recording hook is usable only on handles actually discarded after the operation. `CatalogTransaction` remains for the real live catalog, with its own-hook interruption, detachment and cleanup rules. All substantive destination SQL must share the same budget; fixed controls and filesystem stalls retain their stated time limitations.

Tag errors at the connection boundary. The old public archive APIs stringify every failure into `Invalid`, losing cancellation and main-catalog fatal classification. Conversely, passing a private archive `Database(NOTADB)` through a live `CatalogTransaction` would wrongly retire a healthy generation. A private archive SQL error must become a distinct archive-input failure before it crosses that scope; source-journal errors remain `Recording`. Queries against an export's separately opened real studio catalog are still live-catalog failures. Use an explicit wrapper/variant rather than SQL-text or phase heuristics. A typed outer archive failure should preserve operation cause, actual live cleanup failures/unusable state, sticky budget stop and publication phase independently. Legacy flattening wrappers can remain explicit compatibility paths. Main fatal codes and unusable cleanup cannot disappear behind a later cancellation.

## Route lifetimes and final fences

**Export:** hold the existing retained-file coordination owner and a consistent live catalog snapshot; collect closure, open registered originals once, authenticate and validate all snapshots/typed transitions. Copy exact original bytes into the private output, checking chunk and whole-object digests against the held registrations. Keep source identities/registrations fenced through output completion. Independently verify the produced metadata/object closure, not just the source summary. Publish only after complete validation and private archive commit/sync. A post-link sync or cleanup failure records possible/known artifact publication and the exact path; it does not imply rollback or authorize another target.

**Identity restore and copy:** acquire one immutable private input snapshot, bind its bytes/hash, validate schema/index/counts and reconstruct strict staged object files. Identity restore should reuse the held acquisition pattern already used by copy rather than repeatedly following the original pathname. Perform destination identity/collision checks before installing objects. Existing source acquisition or structural validation never grants project authority.

Current `install_objects` hard-links a staged original and removes the staging link to restore the required single-link invariant. This changes metadata and removes the old pathname. Held staged readers/proofs cannot silently follow it. The smallest one-authentication integration is: after structural/chunk/hash checks, install final content-addressed objects and tentative registrations inside the destination transaction, then authenticate their final owned paths once and validate the entire closure before admitting project/history/results. Invalid semantic input may leave unregistered content-addressed orphans after rollback, matching existing restore retention semantics; report them, never adopt them automatically. If policy requires semantic refusal before any owned-file placement, authenticate the stage first, drop those proofs, install, and authenticate final paths again under the same cumulative budget. Do not invent a relocation permit to avoid accounting for that second pass.

Prepare an expected complete destination postimage from the authenticated input. For identity restore this preserves exact rows; for copy it applies only the declared remap and adds the newly constructed proof/mappings. After all SQL writes, independently compare actual project/history/operation/import/lineage rows, counts and a framed index against that expected postimage. Rechecking semantic validity alone would accept a trigger-changed but still valid document. Recheck referenced asset bytes, exact `TakeObject` registrations and held source identities last. This includes `INSERT OR REPLACE` trigger attacks. Only then use the catalog scope's final checkpoint, detach and sole commit.

Construct and validate the result before commit. Existing `proof.receipt(false)` and staging cleanup after commit are fallible; the new typed route must preserve successful catalog commitment separately from cleanup trouble or later cancellation. Do not return a historical document as the current document or reinstall it during replay. Existing copy replay may continue requiring owned-source authentication because its receipt includes a document: absent input archive is acceptable when the owned closure survives, while absent owned originals is not source authority. A new compact copy-fact API is optional future work, not required to open complete archives safely.

## Copy identity rules

Allocate one fresh destination project ID. Ordinary supported operation remapping retains its existing policy. For each typed projection publication compute `projection_operation_id(destination_project_id, unchanged_projection_id)`; never use `fresh_operation` for that row. Change only `project_id` and `operation_id` in the portable intention, then revalidate and serialize canonically. Remap only the document root project ID in current/history/operation results. Preserve source pins, review bytes, tempo/timing interpretation, projection/lane/note identities, original media and all opaque metadata.

Check the derived destination operation against live `operations`, `archive_copies`, the reserved copy request and pending-map destinations; refuse collisions rather than silently choose another ID. Recompute request/result hashes and existing framed mapping hashes. Preserve ancestor proof JSON and source-side mapping hashes verbatim; associate them with the new project, append exactly one new proof, and verify the complete transitive mapping closure. Test a second copy generation, since a valid first copy is insufficient to establish inherited mapping behavior.

## Executable acceptance matrix and ownership

The coordinator owns shared APIs, error domains, route integration, contracts and final gates. A Sol implementation can own `archive_projection.rs` plus child tests after interfaces freeze; an independent Sol test task can own an engine integration file using real device-free sealed sources. Existing archive/copy modules should have one integration owner. No additional runtime or package is needed.

- Positive real sources: v1/v2 performance, audio-only take, mixed-role take, repeated references, multiple projections sharing an original, edited/deleted notes and lanes. Check one authentication per distinct held original and cumulative interpretation charges.
- Hidden closure attacks: individually corrupt current, before, after, operation-only and ancestor-proof-only bindings; recompute JSON/object/index hashes. Include a false pitch and a different but source-valid binding under the same projection ID. All must refuse at the appropriate semantic/linkage check.
- Initial publication: missing/wrong typed row, wrong deterministic ID, noncanonical request/result, mismatched review/tempo/lanes, altered mute state, false complete candidate, registry rewrite, opaque promotion and valid pruned-history standalone publication result.
- Route qualification: complete export, identity restore, two copy generations, exact originals, histories and operation/proof closure; Undo/Redo and active authenticated load on restored projects. Preserve original binding/note IDs and verify deterministic copied operation IDs and mapping digests.
- Failure qualification: cancellation/quota during metadata, source and SQL work; source replacement; wrong existing object; destination collisions; trigger-altered current/history/operation/asset/registration rows; rollback and same-connection reuse; private NOTADB stays local; actual/injected main fatal domains retain retirement evidence with injection labelled. Assert complete catalog rollback and report permitted retained stages/orphans.
- Completion/replay: removed archive with intact owned closure, missing owned original, stale receipt after edits, late cancellation/cleanup after successful commit, exact replay without a second project, and no ID/path regeneration after uncertain completion.

Run a **separate schema-3 inert OSRE regression** after OSAR integration: full logical catalog plus captures/source-actions/takes closure; current/history/operation/copy-proof rows exact; complete object hashes; reviewed restore and archive-absent inert reconciliation. Destination remains numbered inert objects with no active store owner, adopted project or executable source action. OSRE preserves a coherent or incoherent retained catalog as evidence; it must not require or manufacture active projection authority. Its raw closure does not substitute for OSAR source-semantic admission.

This design does not claim executed tests, native archive controls, current package acceptance, hard-power-loss or elapsed-time guarantees, playback/listening, long-performance scale or full milestone completion. Durable session admission and the named-binary original-versus-derived editing/history/archive/restart/audition workflow remain the next musician-facing integration after these archive gates.
