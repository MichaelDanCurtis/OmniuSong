# Scoped catalog VM governor: independent source review

Date: 2026-10-22. **Decision: bounded source acceptance.** No unresolved serious correctness finding remains in the inspected scoped catalog implementation. This accepts the Rust prerequisite and the focused evidence below; the final stable gate and preservation packet remain separate requirements. No native job, package or complete projection workflow is accepted here.

I inspected the current post-format [transaction scope](../../crates/omniusong-store/src/catalog_transaction.rs), [recording callback](../../crates/omniusong-recording/src/budget.rs), store load/save/edit/history/publication integrations, session error propagation, and [scope contract](../contracts/NATIVE-CATALOG-VM-SCOPE.md). I also checked the locally installed pinned rusqlite 0.40.2 transaction/hooks implementation and bundled libsqlite3-sys 0.38.2 SQLite source. I executed no tests, SQLite readers, applications or devices and changed only this report.

## Accepted source boundary

The callback API retains a private shared `InspectionBudget`, charges one VM step per invocation, and provides neither a connection nor source authority. A replacement callback cannot reset counters or a sticky stop. The private source-reader installation API retains its no-reuse contract.

`CatalogTransaction` preserves the exclusive writer borrow while keeping its transaction and hook owner as separate fields. Deferred reads use the private shared connection and reject an already-active transaction before replacing hooks. Fixed `BEGIN` precedes hook installation, with a budget checkpoint before it; constructor errors receive explicit cleanup. This avoids SQLite's ability to establish a transaction and then report a final progress interruption before rusqlite returns a transaction owner.

All substantive SQL in the scoped branch, including preparation and triggers, receives the same cumulative governor as source authentication and derivation. The rollback observer changes only an atomic flag. It never calls back into the connection. Automatic rollback disables further progress interruption; error cleanup then checks autocommit before deciding whether an explicit rollback is needed. Detachment is idempotent, disables the callback first, and unregisters both scoped hooks before explicit cleanup. Normal errors flow through `run`/`abort`, preserving cleanup failures; `Drop` supplies the unwinding backstop.

The final checkpoint and hook detachment precede `COMMIT`. The implementation deliberately avoids calling a consuming rusqlite transaction commit while its cancellable hook remains installed. Bundled SQLite can run progress catch-up after its commit work, so this ordering is consequential. Current publication/save/history callers return prepared values after successful commit, without a subsequent fallible validation or budget checkpoint. Real commit failure remains an error and receives cleanup.

`CatalogFailure` retains the operation error, returned cleanup errors and residual transaction state. Actual returned main-catalog fatal codes keep priority; unusable cleanup also requires session retirement when its code is not an ordinary fatal code. Source-journal SQLite errors remain `Recording` failures and acquire no catalog authority. The scope mapper translates only its own requested `SQLITE_INTERRUPT`; existing source-helper sticky-stop handling remains distinct. Both source-attachment error routes preserve `Catalog`, and evidence problem conversion retains a nested recording stop.

The [typed publisher](../../crates/omniusong-store/src/projection_publication.rs) first performs exact historical receipt lookup under an independent bounded metadata governor. A hit remains a compact recorded fact despite cancelled callers or absent originals. A miss switches the still-open transaction to the caller's existing governor before retained-file acquisition or source authentication. Active load/edit/history use that same budget throughout; no per-source or per-binding reset was introduced. Ordinary legacy branches explicitly release the governor and retain their previous unbounded qualification.

## Remaining limits

VM accounting and cooperative interruption do not bound busy waits, locking, filesystem stalls, arbitrary native SQLite work, or fixed `BEGIN`/`COMMIT`/`ROLLBACK` fences in elapsed time. One-instruction callbacks incur off-realtime overhead. The scope assumes exclusive ownership of progress/rollback hooks on the store's private connection; it supplies no general stacking/restoration API. Normal failed cleanup is returned for retirement; failed cleanup during unwinding and physical disconnect/power loss remain separate qualifications.

Generic save/edit/history currently use bounded default budgets; only the relevant explicit-budget methods accept caller cancellation. This is not yet a universal session/native cancellation API. Legacy paths, archive/NativeReader/list/attachment integrations and their existing guards are not newly VM-qualified. Complete projection archive closure, durable exact-request admission, actual native responsiveness and the exact-binary review/confirmation/edit/history/restart/audition workflow remain required. No native input/output or listening, long-performance capacity, MIDI 2/MPE, AI/model/plugin integration, Windows or full-goal completion follows from this slice.
