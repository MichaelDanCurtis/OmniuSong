# Independent projection consumer source review

Verdict: **accepted for the bounded source integration described here**, with no unresolved serious source finding after the corrections below. This is an independent source review of the continuation from `5f849e5`, not an independent execution audit or native acceptance. The final source-stable gate and protected-store preservation packet remain separate requirements.

The reviewer read repository Rust source, test source and the [consumer contract](../contracts/NATIVE-PROJECTION-CONSUMERS.md), then reviewed the corrected Reader lifecycle and incremental row reader against the local pinned rusqlite 0.40.2 and libsqlite3-sys 0.38.2 source. The latter bundles SQLite 3.53.2. The reviewer ran no Cargo, formatter, test, SQL, app or device operation, and did not open or fingerprint default catalogs, protected originals or installed binaries. Only the assigned design and this review were written.

## Metadata is not source authority

The shared `project_metadata_view` implementation requires an active caller-owned transaction. It bounds stored identities in SQL, obtains payload length/type first, prepays full decoding, then fetches with an exact-length and maximum-length predicate. SQL and governor errors stop the call; only document damage becomes a damaged-summary row. Output allocation is prepaid. The 513th row refuses before decoding, rather than silently dropping a project. The wrappers in `store/src/lib.rs` own a deferred `CatalogTransaction` and finish it explicitly.

The new summary flag is true only for a structurally valid nonempty musical-schema-3 registry. Its absence or a healthy summary does not authenticate a source. A coherent rehashed false-pitch claim may be readable metadata while active load still refuses it. Old schema-1/2 opaque fields retain their existing interpretation; the metadata helper does not promote them. The native row notice describes checking originals on open, without installing a new conversion control.

Reviewed anchors: `project_metadata_view.rs` (`active`, `decode`, `summary`, `list`, `load`); `lib.rs` (`ProjectSummary`, `list_with_budget`, `check_project_metadata_admission_with_budget`); native `main.rs` summary notice. The former global guarded decoder remains available and guarded.

## Reader and selected waveform

The follow-up lifecycle review found a serious existing acquisition defect: the old `NativeReader::open` opened a separate raw catalog descriptor for its header and dropped it after opening SQLite. On the POSIX VFS, that raw close can release another same-process SQLite connection's external file locks. The coordinator reproduced the failure with an isolated no-DML transaction and external-process probe; Reader acceptance was withheld until the correction. This was an actual synthetic regression, not evidence of damage to a real project or the protected store. SQLite documents the [raw-close hazard](https://www.sqlite.org/howtocorrupt.html), and the pinned `unixClose` defers its own descriptor close while the inode still has locks; a Rust raw `File` close bypassed that protection.

The corrected `catalog_header` (`reader.rs:60`) borrows the eventual read-only connection's main `sqlite3_file` through `FILE_POINTER`. The pointer and stack output stay local to the synchronous helper. Checked version/method pointers, typed scalar outputs, fixed 20-byte reads and connection ownership make the unsafe boundary narrow; no ownership transfer, pointer retention, `xClose`, free, raw fallback or mutating I/O method is present. Direct VFS result codes are retained as SQLite failures rather than replaced with a stale connection error. `HAS_MOVED` absence is an explicit unsupported-identity refusal.

`open_checked` (`reader.rs:141`) acquires that eventual connection with `READ_ONLY | NO_MUTEX | NOFOLLOW`, validates the held header/length/path before any schema SQL, and repeats held checks after schema validation before the final ordinary-path metadata comparison. The deterministic after-open seam receives no connection handle and is private to the crate. Connection RAII covers every early error. Pinned rusqlite's open wrapper runs no schema SQL before returning; pinned SQLite's initial pager header read precedes WAL activation. A WAL header observed by the initial probe is refused before schema SQL; this is not a universal guarantee against an external journal-mode change between checks. The new checks do not freeze a mutable catalog or replace a later consistent transaction and source proof.

`NativeReader::load_document_with_budget` owns one deferred scope and reuses the current-document held-source admission path. It verifies referenced assets, union registered originals, actual projection derivations, current geometry, registration identity and held original paths before ending the read transaction. The source owner and its proofs remain alive through the final checks. It does not authenticate every retained history or ancestor proof merely because it returned a current document.

The explicit `load_document_metadata_with_budget` requires the existing caller-held short snapshot and provides metadata only. The old guarded `load_document` remains unchanged. Nested standalone authenticated reads are refused by the catalog scope rather than replacing another scope's hooks.

Waveform metadata now uses the explicitly weaker method. The later selected-media path still compares project/revision, exact clip/source/stream/rate, current and original windows, owned object identity and its existing byte/chunk/sample/channel limits. This may produce valid peaks for a selected original while unrelated false projection claims remain unusable as music. It is not a bypass for active project authentication.

Reader SQL is deliberately classified as this studio catalog's SQL. The current engine waveform worker reports it locally; this is not permission to retire a different reusable writer on another reader's cleanup failure. The metadata snapshot retains legacy SQL-control behavior. Its metadata cancellation token is a construction-time observation, with the existing callback checks before and after the snapshot; there is no newly established whole-waveform cumulative budget, latency or deadline guarantee.

Reviewed anchors: `reader.rs:60` (`catalog_header`), `reader.rs:141` (`open_checked`), `reader.rs:200` onward (new consumer methods); `reader_tests.rs:636` onward (external-lock helper and four new regressions); `active_projection_edits.rs::load`; `waveform.rs::metadata` and `prepare_waveform`; `catalog_transaction.rs` scope lifecycle. The existing active-load source-helper error-priority qualifications are not expanded into a universal physical-error-retention claim.

## Normal and recovered publication

The new `projection_attachment` path is a complete fresh publication sequence rather than removal of a schema guard. It reads bounded current metadata, checks the exact expected revision, constructs the candidate with `append_take_clip`, and proves registry equality. It collects current and candidate references under one caller governor, opens the union with the explicit preserving source-origin helper, authenticates each distinct performance original once, validates current bindings, then validates candidate geometry without rederiving the same immutable registry.

A registry still retains its originals after current note/audio/lane deletion. Incoming audio does not acquire a performance role from its filename or placement. A damaged registered original does not fall back to a recovered working copy. Final referenced-asset checks, exact `TakeObject` comparisons and held path/file checks remain necessary after SQL mutations.

Normal `publish_take_with_budget` performs exact historical receipt lookup under a separate finite metadata budget before switching to the caller's fresh-publication governor. It does not touch an original for an exact replay, even if the caller's source budget is already cancelled. The fresh projection-operation namespace restriction follows the absent-receipt branch; existing exact ordinary historical identities are not retroactively excluded. The dedicated source-attachment namespace remains confined to its history-fenced bridge.

The recovered bridge compares complete source-action history before and within fresh publication and rejects an existing receipt that should instead be reconciled. Its private action plan uses exact pre-mutation history, immutable review bytes and committed payload. The actual project/edit/operation/source-action changes commit together. Source history is still opaque at this store layer; the session caller supplies the actual typed source choice and held recovery view. That opaque history never substitutes for original-source authentication.

Reviewed anchors: `projection_attachment.rs` (`prepay_history`, `planned_action`, `publish`, `publish_take_with_budget`, `publish_source_attachment_governed`); `source_attachment.rs::publish_source_attachment`; `takes.rs::attach_capture` and `publish_take`; `projection_sources.rs` source collection, authentication and final fences.

## Full SQL postimages and bounded finalization

The ledger captures all thirteen persistent catalog tables and their schema before live mutation. Its new replacement/removal operations require an untouched baseline key and full typed row digest. Replacement cannot silently change its primary key; mismatches and conflicting plans poison the builder. Remove followed by insert at the same known key intentionally supports replacement of a pruned future edit edge.

Expected project/history/operation and optional review/action rows are independently planned and frozen before application. Final verification includes unrelated rows, not just the selected project or row counts. A trigger cannot substitute an unrelated valid project, alter source history or swap an asset/registration merely by preserving a valid local result. The source/asset final fences remain separate from this logical SQL comparison.

The project-row preimage now uses exact bounded stored JSON bytes. Valid noncanonical whitespace or layout is preserved for the CAS comparison; new edit/result serialization remains canonical. Expectations are not derived from already-applied rows.

Fresh attachment no longer decodes its just-written full operation result a second time. `plan_edit` independently includes all eight operation columns, including exact request/result bytes and hashes, in the frozen ledger; the actual saved document must equal its planned candidate. The fresh receipt is constructed before the final full-table verification and commit. Historical lookup still runs the complete exact receipt check. The new genuine-projection regression substitutes a different valid same-project/same-revision result with its correct SHA while retaining the requested clip, and separately ignores the operation insert. Both must fail the frozen row comparison, restore all thirteen tables/schema, preserve originals and permit the same request after the malicious trigger is removed. These are stronger independent receipt postconditions than accepting a result merely because it parses and contains the clip.

The capacity investigation found a separate genuine regression: each 64 KiB SQL substring reinterpreted the complete large field and paid for that work again. Repeating this across baseline and final thirteen-table scans exhausted the unchanged 1 GiB governor on the existing valid 2,000,000-byte opaque-metadata fixture. Removing the redundant receipt decoder alone did not fix it; the subsequent trace located the refusal inside final postimage comparison.

The corrected `proof_row` gathers bounded type/length headers first, then charges `2 * bounded_row_bytes + 8192` before each actual value read. Numeric scalars are fetched only after that credit, because a tiny later scalar can traverse earlier overflow pages too. `read_cell_chunks` uses the same connection and transaction, a read-only incremental handle, exact length comparison, at most 64 KiB of prepaid buffer and sequential `read_at_exact` with per-chunk credit/checkpoints. Pinned SQLite keeps a row-sized overflow-page cache and reuses its offsets for sequential reads; this replaces the per-chunk full-cell CAST work without changing the row digest or resetting a budget. Stored TEXT retains its database encoding, BLOB stays bytes, and storage-class/numeric/key framing remains unchanged.

The row allowance is a conservative logical-work model, not a measured pager-memory, physical-I/O or latency ceiling. Incremental reads use Btree operations rather than VM instructions, so cancellation is observed between chunks and does not promise to interrupt a blocked individual pager read. Schema, table/key/field, row-count and spool limits remain unchanged. Only the existing pinned rusqlite `blob` feature is enabled; no package/version dependency or raw-descriptor access is added.

Every opened incremental handle is explicitly consumed by close after the read closure, including quota/cancellation, length mismatch and SQL failure. `ArchiveSqlFailure` retains same-origin secondary cleanup errors and a distinct close-only marker with the actual close error as its primary. The private enum prevents fabricated primary errors or lossy cloning. Only live origin can report catalog fatal codes or unusability; fatal primary, then fatal cleanup, then ordinary codes have priority, and failed live cleanup conservatively makes that connection unusable. Both `PrivateSql::finish` and `finish_spool` now decline own-INTERRUPT folding when cleanup is present. A successful-only later checkpoint cannot erase an observed read or close error. These rules do not turn constructed error combinations into evidence of physical close faults.

Every remaining complete source-history materialization is reserved before private planning or live append, including private population and each append's internal pre/post reads. The existing row/field, 512 MiB private-main-file, postimage and inspection ceilings remain effective; large valid histories/catalogs may safely refuse. No new budget is created between source authentication, plan/ledger work and fresh commit.

The private SQL scope records whether its own callback interrupted. Both plan DDL and later population/append map only that matching private INTERRUPT to the sticky stop. Actual physical and semantic errors keep their original domain. The main catalog scope continues to disable/detach hooks before rollback or commit and preserves actual catalog failure/cleanup authority. No new cancellable verification runs after successful commit.

Cleanup is best effort after a completed commit, using remembered file identities and an empty-directory removal. It neither recurses through unknown members nor adopts a replacement plan file after close. Failed stages remain diagnostic. The private plan retains its exclusive-created file identity through connection close. Non-Unix identity checks conservatively refuse held-plan admission and retain scratch until that platform is qualified; this is not merely a cleanup difference. Cleanup warnings are not transported by this receipt, and fixed filesystem/control operations are not a hard-time guarantee.

Reviewed anchors: `archive_postimage.rs::expect_replace`, `expect_remove`, `proof_row`, `value_credit`, `read_cell_chunks` and `finish_spool`; `archive_boundary.rs::ArchiveSqlFailure` and its read-close constructors; `projection_attachment.rs::plan_edit`, `publish`, `plan_action`, `Stage`, `same_identity`; `archive_plan.rs::open_catalog_bounded_held` and bounded DDL finalization; `archive_governed.rs::PrivateSql::finish`; `catalog_transaction.rs` commit/abort behavior.

## Findings resolved during review

The source review identified and the coordinator corrected:

- Fresh projection-namespace rejection had preceded exact historical replay. It now follows an absent receipt.
- Bounded attachment replay paid request/result lengths but not an arbitrarily large stored foreign project identity. The preflight now bounds the stored project ID before metadata materialization.
- Repeated private/live source-history materialization was undercounted. The additional passes are now prepaid before processing.
- Private planner VM interruption initially escaped as generic private SQLITE_INTERRUPT. Tracked own-interrupt mapping now covers both DDL and subsequent work, retaining other failures.
- Canonicalizing the project's preimage falsely rejected valid noncanonical stored JSON. The CAS now uses exact prepaid raw bytes.
- Recursive scratch deletion and post-close adoption of the plan pathname were unsafe cleanup choices. Only captured known identities and an empty directory are cleaned after completion; failed stages are retained.
- The existing Reader's separate raw catalog descriptor could release another SQLite connection's external lock when it closed. The eventual SQLite connection now owns the Reader's only catalog handle throughout the header probe, schema admission and all refusal paths, with explicit held-handle identity checks.
- Repeated full-cell SQL substring reads imposed quadratic accounting on valid native metadata. The header-first, prepaid incremental reader restores linear byte processing with explicit row traversal and cleanup accounting; no ceiling or fixture was reduced or raised to make the test pass.

The source union was also changed from the older finalizer wrapper to the explicit preserving `open_collected_from` path, with the corresponding final registration method. No global source-authority guard was removed to address these findings.

An engine fixture's out-of-window assertion still used a range valid for its enlarged 2,000-frame source; the source was corrected to cross the actual end. A later coordinator-executed diagnostic found that the supposed noncanonical input used the core's already-pretty encoding; the test now uses compact JSON as its distinct valid SQL preimage. These are fixture corrections, not evidence of weakening source or postimage refusal.

The following limitations remain explicit:

- Normal `attach_capture` ingestion still uses its existing authorized legacy export path; only subsequent project publication is newly governed. Bounded read-only journal export remains forbidden. Retained orphans after later conflict are not deleted or retried automatically.
- Normal SessionService `AttachCapture` still uses the generic document/library response. A later current-load/library failure can obscure an earlier commitment there; the source-independent store receipt guarantee is not a new typed normal-session completion guarantee. Dedicated recovered attachment already separates historical commitment and current-document failure.
- Library paging beyond 512 remains required. The source notice and reader integration are not an installed native-window qualification.
- Reader acquisition requires supported `HAS_MOVED` identity control and has no raw fallback. The pinned default Windows VFS lacks that control and fails closed, so this correction is not Windows Reader qualification. Raw acquisition/control calls remain outside a newly claimed VM, cumulative-budget or hard-time guarantee.
- Generic Create, arbitrary registry insertion/removal/rewrite and opaque promotion remain guarded. Musical/catalog/archive schemas and the existing authenticated publication/history/governed archive authority are unchanged.
- Durable native projection and archive admission, confirmation/draft/restart safety, exact-binary walkthroughs, real playback/listening, physical input, sustained recording, Windows, MIDI 2/MPE, plugin/inference roles and the full workstation goal remain open.
