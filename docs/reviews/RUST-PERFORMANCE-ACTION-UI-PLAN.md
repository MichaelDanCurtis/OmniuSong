# Guarded native performance recovery and attachment

October 22, 2026. Next implementation handoff for [implementation-plan step 6](../IMPLEMENTATION-PLAN.md), following the accepted `ba02538` evidence-controls source packet and its separately recorded [7752 native walkthrough](../verification/rust-native-evidence-ui.json). This document is a source investigation and implementation decision, not implementation or native acceptance. Only this new document was written during the investigation; no Cargo, application, device, recording, archive or live-catalog operation was performed.

Deliver the existing copied-recovery workflow in the Rust native application: reviewed source → immutable Prepared → separately confirmed execution → recorded Verified; then explicit Keep/Return and a separately reviewed target/placement/attachment. Preserve the original recording, every retained review and action revision, immutable evidence image, recovered working copy, unknown tail and original event streams. Mac is the first qualification target; the current Unix identity implementation does not qualify Windows. The [complete goal](../GOAL.md) and every outstanding release requirement remain unchanged.

## Existing implementation and the small missing contracts

Use [Prepared storage](../contracts/NATIVE-PERFORMANCE-SOURCE-ACTIONS.md), [execution/reconciliation](../contracts/NATIVE-SOURCE-ACTION-EXECUTION.md), [recovered attachment](../contracts/NATIVE-SOURCE-ATTACHMENT.md), and the [read-only source UI](../contracts/NATIVE-PERFORMANCE-SOURCE-REVIEW-UI.md) as the authoritative storage and source contracts. Earlier plans containing proposed state names do not supersede their implemented Prepared1/Started2/Verified3 model.

Current source boundaries:

- `crates/omniusong-session/src/performance_source_actions.rs` shapes exact review-bound Prepared requests and validates recording-intent origins. `performance_source_actions/execution.rs` loads the complete validated ledger, reauthenticates a fresh source before Started, and reconciles existing artifacts without reopening the recording source. `decisions.rs` folds immutable Keep/Return/attachment choices. `attachment.rs` checks the historical publication receipt first and preserves commitment separately from current-document failure.
- `crates/omniusong-session/src/lib.rs` owns the sole capacity-one worker, distinct inspection/source-action/evidence cancellation tokens, correlated completion, and nested attachment `current_document_error` retirement. These source-action commands currently remain `retry_safe()` at the backend API level; that is not permission for a generic native retry button.
- `crates/omniusong-app/src/performance_source_ui.rs` retains a bounded typed source review with generation, selection epoch and observation serial. Its production UI is read-only; `visible_review` is presently test-only. Add one explicit, bounded review-offer interface, not access to its mutable internals.
- `main.rs` currently rejects every source-action command at submission, and generic reply arms do not install actionable source state. Replace that refusal only for the new exact native route. `evidence_integration.rs` supplies the established context-snapshot, sole-worker, stale-result and terminal-generation pattern; keep evidence-job and source-action state separate.

Two shared prerequisites must land before enabling mutation controls. The coordinator owns both; no migration, new journal, new service or changed recovery algorithm is needed.

### 1. Read one exact retained action and review

Add these public session DTOs and command/reply, with names frozen for the implementation slice:

```rust
pub struct PerformanceSourceActionReference {
    pub id: String,
    pub revision: u64,
    pub payload_sha256: String,
}
pub struct PerformanceSourceActionDetail {
    pub version: u32, // Exactly 1.
    pub origin_root: PathBuf,
    pub state: PerformanceSourceActionState,
    pub review: Vec<u8>, // Exact retained bytes, not a rewritten DTO.
}
Command::ReadPerformanceSourceAction { id, revision, payload_sha256 }
Reply::PerformanceSourceActionDetail(Box<PerformanceSourceActionDetail>)
```

The reference uses the existing nonzero 32-lowercase-hex ID, revision 1..=16 and lowercase SHA-256 checks. Read uses `load_execution_history`, authenticates the reference, then requires it to equal the **current** state head. A stale selection fails without a write; explicitly list/read again. Return the canonical opened store root and exact immutable review bytes from that same loaded history. Recompute their raw hash and Prepared/admission relationship through the existing validators. Reading the latest head is not an artifact observation and supplies no execution authority by itself.

This read is required because the current state/result summaries omit `config.info.sample_rate` and `performance.checkpoint.audio_end`. A restarted UI cannot construct a valid attachment from those summaries or a guessed rate/duration, and must not require the original recording merely to recover those retained facts.

Freeze `PerformanceSourceActionDetail::validate()` as the shared pure validator. Bound before cloning: raw review ≤65,536 bytes, selected state serialization ≤64 KiB, root UTF-8 text ≤4096 bytes, and the **whole serialized detail ≤320 KiB**, measured with a bounded writer. The aggregate explicitly includes JSON number-array expansion of `Vec<u8>`, escaped root text and the entire state/envelope; raw-review length alone is insufficient. Version is exactly1. Maximum-shaped fixtures must exercise all bounds together. Keep raw bytes unchanged; parse them once and regenerate `PreparedPerformanceSourceAction::prepare` with the retained action's ID, operation and origin to check exact equality, including ordinary raw blob SHA and stable admission. Validate the ordinary canonical root's lexical form and exact root-derived capture path without opening that source. Use existing review/codec helpers rather than implementing a second checkpoint codec. Read matching compares the command triple with `state`'s exact current head, so this reply does not duplicate a requested reference.

**Absence distinctions:** the recording `captures/<stage>/take.sqlite3` may be absent while this read and action listing succeed. A Started/Verified artifact check may also succeed with that recording absent. Source-action rows and their review blobs live in the actual studio catalog; if that catalog/root is absent or cannot be opened, this new read cannot recover them. It must not initialize a replacement catalog or search OSRE restored objects. A metadata-only evidence connection is not automatically an initialized source-action connection. Require a successfully established native root/healthy catalog before this UI admits any source-action command. General graphical missing-catalog recovery and inert archive adoption remain separate work.

### 2. Bind source-action reply identities before releasing service credit

Current `Reply::matches_command` checks only the variant for these backend-only replies. Add source-action-specific transport/reference matching before `pending.take()` in `SessionService::try_poll`, and the same reference-only native active-action classifier before consuming its slot. A wrong transport ID, variant, action ID or requested reference leaves both pending slots occupied. A correctly correlated envelope with a semantically invalid state/publication/decision/observation is instead consumed as one bounded Protocol/uncertainty result: install no proof/document, retain the exact mutation in the model, and authorize no continuation. Do not leave an active UI request waiting for another result after the service already consumed its only reply. Make `StudioApp::busy()` include `active.is_some()` as well as service credit, preventing other generic actions from overwriting a native slot even during injected desynchronization.

Add `requested: PerformanceSourceActionReference` to `PerformanceSourceExecutionReceipt` and `PerformanceSourceAttachmentReceipt`. Their `state` may legitimately have advanced beyond the requested historical row, so comparing the requested SHA to the latest head is incorrect. Populate `requested` from the actual authenticated request, including exact historical row SHA. For the decision reply, introduce `PerformanceSourceDecisionReceipt { requested, state }` and retain the existing `Reply::PerformanceSourceDecision` variant with that boxed receipt. The native model pins the full requested decision separately and verifies the resulting state/row against it. These are in-process DTO changes, not alterations to any durable bytes or phase history.

Reference matching rules: Prepared save binds the submitted action identity and revision-1 receipt; detail compares the command triple to its exact current state head; execution, decision and attachment compare the complete requested reference and action ID. Separate bounded semantic validation then checks Prepared's complete action/hash/review, state structure, its latest head not predating the requested row, reviewed source/result, and the native model's exact requested decision and expected attachment choice/publication. For a decision the returned head is the requested head on exact-current replay or its immediate successor; derive the expected decision event/envelope from the pinned request, without accepting a caller-authored committed event. An attachment response for an old retired choice can legitimately contain a latest state with a different current choice; compare its publication to the retained requested choice, not blindly to `state.decisions.attachment`. The compact reply does not independently expose that historical choice row to the generic service, so a same-reference wrong-publication body is a correlated semantic failure, not a stale-reference wait. No string parsing is sufficient. List replies have no per-row request identity but must pass their complete count/byte/identity checks before installation.

Keep the existing 576-KiB execution/state metadata limit inclusive of the small reference envelope; no raw review is added to these replies. Enforce the whole bounded representation before returning or cloning, and retain maximum-shaped regression fixtures for the envelope overhead. A decision's existing request/row ceiling is16 KiB. Attachment `current_document` remains under the existing project/`DocumentView` limits and is moved to the coordinator, never cloned into a history card. Bound attachment metadata separately from that document. A document-preparation refusal remains `current_document_error`, preserving the authenticated publication result. Do not add client-only error-text limits to identity correlation: bound diagnostic presentation separately, or apply the same bound at its producer with a truncation indication. Existing nested `StorageUnavailable` retirement survives semantic rejection and must still retire the generation after the correlated result is delivered; retain uncertainty if its body cannot be trusted.

Do not globally reclassify `ServiceError`, source faults or `retry_safe()` for this UI packet. The app excludes every new source-action request from generic retry capture, `retry_last`, automatic continuations and post-error dispatch. Explicit controls below construct their own immutable exact requests. Historical SQLite information does not retire a new generation; actual main-catalog fatal errors and the existing nested current-document fatal do.

### Preparing and executing recovery

Add a production `PerformanceSourceUi::recovery_offer()` returning an immutable app-local snapshot only for its current successful review: generation, epoch, observation serial, stage/take, full review DTO and optional explicitly selected recording-intent receipt. The getter emits no request, mints no identity and performs no I/O. The action model serializes the selected review once with the existing64-KiB bounded writer, retains those exact bytes, and calls `PreparedPerformanceSourceAction::prepare` once when the user chooses **Review copied recovery**. Mint one fresh action ID and recovery operation ID at that point; repeated render/confirmation must reuse them.

An eligible initial review is unsealed Recording/Interrupted with a positive selected checkpoint and supported policy. It retains `unknown_tail=true`; no readable extra tail enlarges the recovery. Show selected audio frames and rate, six stream-prefix summaries, fault/unknown-tail status, original path and copy destination role. Display “Recovered checkpoint copy”; do not claim a normal Finish, all events saved, input acquisition or audible verification. The physical image preserves all original rows/tail, while only the working copy receives the selected recovered manifest.

Link a recording-intent origin only through an explicit exact `(LiveId, revision, payload_sha256)` receipt whose stage/take/config relationship the backend validates. Default to an explicitly labeled unlinked choice if none was selected; do not choose the first similar row or infer a device/target/Finish from its filename or apparent resemblance. An origin never supplies attachment target or placement. Preserve the exact current review blob, its ordinary raw hash, domain-separated review hash and stable-admission hash as distinct identities.

Before offering a new Prepared identity, explicitly load the bounded existing state list. If this view already has any retained action for the same stage/take, direct the user to that action; do not offer a new ID as recovery from a stale review, Started uncertainty, missing artifact or a full ledger. This prevents the native UI from blindly replacing its own unresolved work. It does not claim cross-process uniqueness by stage: the existing backend permits separate action IDs and fences whole history at each write. A future duplicate/supersession policy must be explicit, not inferred from list freshness.

After saving, show **Choice saved; recovery has not been requested**. A separate confirmation binds the returned exact Prepared receipt and explains the immutable evidence image, working copy, selected checkpoint, unchanged original, fixed resource policy and possible retained partial output. Only its confirmation may submit Execute. No `after` continuation is attached to Save or Execute.

After a successful execution, show the original Verified result and current observation distinctly: action/head, physical evidence SHA/length, working SHA/length, manifest, selected chunk index/count, six-stream checkpoint facts, usage and unknown tail. `replayed=true` does not mean a second copy happened; `original_reopened=false` does not assert the original is missing. The subsequent Keep/Return/attachment choices remain separate explicit buttons.

### Placement, publication and conflict

Attachment preparation requires a current exact action detail with Verified, Review disposition, and no current Pending/Committed choice. To start a replacement, require the successful atomic retirement receipt and a fresh current detail; set `supersedes` to that exact retired choice ID. A failed or uncertain retirement cannot authorize replacement. Preserve room for choice/settlement/Keep (`head+3<=16`) and the backend's pending-settlement reservation. Capacity refusal leaves the originals and current choice intact.

Require explicit selection of the currently open saved target session and its recording track, or an explicitly requested new recording track. Freeze project ID/revision, track ID/name and fresh clip ID. A new choice ID is minted once per reviewed choice; derive its operation only through `attachment_operation_id(action_id, choice_id)`. There is no arbitrary operation-ID or source-path field. Never reuse the copy operation or an old placement identity.

Build `TakePublication` from the authenticated retained source and Verified result: exact take/manifest, stream `audio`, range `AudioFrames { start:0, count:checkpoint.audio_end }`, the retained sample rate, and an explicit nonnegative integral timeline frame. Show zero placement as a choice, not inferred synchronization. Validate integer parsing, signed conversion and checked end-frame arithmetic; display seconds separately without a floating-point round trip into authority. No fades/edit snapshot, extra source trim, automatic resampling, note projection or unproven tail is part of initial publication. Reuse existing validators.

Saving a choice and publishing it are two separate confirmations. The publication confirmation shows the saved target/revision/track/clip/placement and the current target revision if available. A changed current revision does not rewrite the saved choice; an explicitly repeated exact attempt can report a known `RevisionConflict`. Reconciliation and atomic retirement then allow a separately reviewed replacement with new choice/operation/clip identities and fresh target revision. Ingested owned bytes may already exist after conflict; never report “nothing was saved.”

Handle `PerformanceSourceAttachmentReceipt` as three facts: historical `committed`, current action/choice state, and optional latest `current_document` or its error. Historical commitment is not a claim the clip remains placed after Undo or later edits. Never install a historical postimage. Only an explicit Attach completion with an unchanged full native context, the same selected target and no newer drafts may move its current `DocumentView` into `install_document`; otherwise retain a compact receipt and offer an explicit normal Open/Refresh through existing draft guards. Read-only attachment reconciliation never changes the open document. Do not manufacture a Library reply or silently enqueue Refresh.

Keep the committed receipt if the current document/files are unavailable. If its nested error is `StorageUnavailable`, retain that receipt first, then mark the generation unavailable and invalidate current offers in source review, source actions and evidence UI. The existing service already recognizes this nested fatal; the new coordinator must not flatten it into either “attachment failed” or success with a usable worker. An owned-original mismatch remains local and cannot cause a fallback to a convenient working copy.

## Native model, freshness and routing

Create `source_recovery_ui.rs` with a pure `SourceRecoveryUi`, separate from the existing read-only source model and generic capture recovery. Add a dedicated native action carrying `SourceRecoveryRequest` and a coordinator module `source_recovery_integration.rs`. Neither model nor painting accesses a store, path, artifact, engine, native input or worker directly. These private implementation names supersede this plan's earlier `performance_action_*` module proposal; public session names above remain frozen.

Use a private typed request enum containing List, Read, SavePrepared, Execute, ReconcileRecovery, SaveDecision, Attach and ReconcileAttachment. `command()` generates exactly the command above. Requests retain a stamp with canonical origin bytes, service generation, checked view epoch, checked offer/confirmation serial, current detail/list serial and, where applicable, source-review generation/epoch/serial and fresh-reconciliation serial. Execute distinguishes local confirmation modes FreshCopy and RecordExistingProof without adding a backend recovery mode. Attach carries the expected immutable publication in the model for reply comparison; that publication is not a replacement command parameter.

Use `new`, `generation_changed`, `worker_lost`, `context_changed`, `submitted`, `submission_failed`, `completed`, `pending_cancel`, `cancel_requested`, `authorizes`, and `ui(ui, availability) -> Option<Action>` as the implementation interface. The exact current offered request or approved confirmation is required at both dispatch and submit. Raw commands, forged request objects, legacy action routes and every non-None continuation refuse before credit is taken. Constructors, paint, selection, reconnect and result installation emit no follow-up command.

Maintain the context snapshot independently of panel visibility, before completion and before submission. Include current document ID/revision, metadata/note/clip drafts, selected track/clip/source/action/target, canonical origin, ready state, pending save/discard choice, retained musical retry, unresolved edit state, audio/capture/retained-take ownership, generic recovery guard and every close guard. Field/selection A→B→A changes, accepted fresh source Inspect, accepted action Read, target edits, and generation loss invalidate offers; returning to old values never resurrects them. Refused submissions do not invalidate previously successful proof. Epoch/serial overflow disables further offers without wraparound.

On accepted Read or recovery Reconcile, mark the preceding corresponding detail/proof historical immediately. After accepted mutation, invalidate the action's current head snapshot; its matching validated receipt may install a fresh head, but never implicitly authorize a new mutation. Reconcile on Started can retain a separate fresh-proof serial for **Record verified existing result**; source/context/generation changes invalidate it. A completed failure does not revive the earlier proof. A result matching the transport request but stale for the view is a historical card only.

Admission matrix:

| Route | Required guards; fields preserved |
| --- | --- |
| List/Read action metadata | Healthy idle sole service, known canonical initialized studio, no active request or closing window. May preserve unresolved metadata/note/clip drafts and musical retries; no artifact or audio owner access. |
| Recovery/attachment reconciliation | Above plus released audio/live/capture/finalization/retained-recording ownership, following the existing source-inspection barrier. Preserve musical drafts, retries and document. Attachment reconciliation is receipt-first, but use the conservative artifact-read guard consistently. |
| SavePrepared, Execute, every decision, Attach | Above plus ready studio, no dirty family, unresolved musical edit/choice, retained musical retry, pending save/discard/navigation, generic recovery attachment guard or close guard. Revalidate the exact model stamp and context. No automatic Save/Discard then continuation; resolve locally and explicitly review again. |

List/Read may be presented while the source panel is closed or the current document is not selected, but cannot use an uninitialized evidence-history worker to create/open a replacement store. Restore of an OSRE archive provides no action offer. Only live validated catalog state and source reviews through the existing stage-ID route enter this model. Do not map numbered inert objects into capture/source-action paths or trust their imported origin as local authority.

Track a single `Pending { request, RequestId, cancel_attempted, cancel_requested }`. Only Execute, ReconcileRecovery, Attach and ReconcileAttachment use `SessionService::cancel_source_action(id)` after checking both model and native active request. Inspection still uses `cancel_source_inspection`; evidence uses its own token. SavePrepared/decisions/List/Read have no invented cancellation button. Cancel submits no command and releases no credit; stale/repeated IDs cannot retarget work. A success that wins the race stays success. Closing a panel is not cancellation; Drop is not an authorized source-action cancel. Existing busy/close handling keeps the accepted worker alive until actual completion/disconnect and retains musical close choices.

## Uncertainty, restart and history

No source-action request enters the app's generic retry slot. Preserve an unrelated musical retry and its continuation on every source-action outcome. `retry_last` explicitly rejects this action family even though the underlying command may be backend replay-safe. Submit-time disconnect, worker EOF, source-action nested retirement and unrelated terminal catalog failures all notify/invalidate this model; stale payloads cannot free its active slot. No timeout starts a second service or grants new capacity.

| Durable/observed state | Permitted UI conclusion and next step |
| --- | --- |
| SavePrepared reply lost | Retain exact request/IDs/review locally. Explicit List/Read locates that ID; a same-request save may be offered only as a separately confirmed exact metadata replay. No Execute until a confirmed retained Prepared receipt exists. |
| Restart, no saved Prepared row | No recovery was authorized through this flow because Execute requires the persisted row. Do not invent a missing request or claim a known save result. A new explicit Inspect/review can begin only after current list validation and without bypassing another retained action for the stage. |
| Prepared observed | No confirmed Started in this catalog observation. Offer fresh reviewed execution after guards; backend still reauthenticates source. A prior failed execute does not reuse a stale source observation. |
| Started, artifacts missing/partial/busy/changed | Execution remains unresolved. Preserve the exact action and artifacts; Inspect metadata, Reconcile again or export complete evidence if possible. Never recreate the namespace, restart copying or mint a substitute action. Keep-before-Verified is not implemented. |
| Started, complete existing artifact reconciled | Show recorded Started plus fresh matching recovered proof. A distinct confirmation may Execute the same historical reference to publish Verified; reconciliation itself wrote no outcome. |
| Verified, current artifact check fails | Recorded Verified remains historical proof. Do not erase it, call it a fresh playable result or recover again. Keep/Return metadata remains possible; attachment's backend proof may still refuse. |
| AttachmentPending, result unknown | Explicit same-choice Reconcile first. A fresh exact-choice Attach is a separate confirmed action; no automatic retry. Keep only changes disposition and cannot settle the publication. |
| Reconcile says uncommitted | This is a metadata observation, not a reservation. Same choice may be explicitly attempted; replacement requires successful atomic Retire and a new review. |
| Committed, source/artifact removed or later project edits | Keep historical commitment; backend receipt-first replay/current-document observation can succeed without the recording/evidence/working files. Never duplicate placement or reinstall the old document. |
| Retire reply lost / head changed | List/Read current state. Do not prepare a replacement until exact retired state is authenticated. Corrupt/conflicting receipt is not absence. |

After application restart, start/open only the normal configured studio through existing lifecycle rules, then explicitly List and Read action metadata. Do not automatically inspect, execute, reconcile, attach or reapply a disposition. Recoverable identities are in the catalog before artifact work and choice rows before publication; transient cards are not the persistence mechanism. The action detail supplies retained source facts even with the recording file absent. If the catalog is unavailable, retain uncertainty and direct the user to existing evidence history; do not claim those journals reconstruct source-action authority.

A local collapsed/closed card is only presentation. Do not label it durable Keep. One unresolved local save/decision request may remain separately pinned while its current catalog state is read; do not discard it to admit another mutation. Durable unresolved action rows are never evicted. Display cards may be bounded because exact catalog history remains available; retain any unacknowledged request outside that card ring until explicitly reconciled. Started and attachment uncertainty must never disappear merely because eight newer read cards were shown.

## Bounded rendering and exact identity

Retain at most one state-list snapshot (32 actions, ≤576 KiB), one selected detail (bounds above), one current source-review offer (≤64 KiB exact bytes), one immutable confirmation/pending request, and eight compact result cards. Cards hold no raw review, full manifest, PCM, decoded event array or `DocumentView`; cap each card's metadata at8 KiB plus validated fixed-size identities. Keep the one unresolved request outside the evictable ring. Reject malformed/oversized data before cloning or installing it; check row IDs, canonical payload identities, revision arithmetic, references, enum versions, all SHA values and scalar lengths.

Prepare previews once on receipt, never serialize full state/history in `paint`. Virtualize action rows. Show one selected checkpoint, six stream summaries, one primary fault, ≤16 diagnostic rows plus an omitted count, and the existing eight usage counters. Summary text ≤512 Unicode scalars; full path fields ≤4096 UTF-8 bytes; ID/SHA text is never truncated into a different copyable identity. Provide expandable exact review/action/choice/reference details with copy controls. Decimal placement and overflow errors are local field errors, not worker requests.

Keep primary status, explicit confirmation and pending Cancel visible at narrow widths in both light/dark themes. Keep transport Stop available outside the panel. The initial surface belongs beside Saved performances and should use its selected source only through the explicit offer. A separate recovery-choice list exposes actions whose source was removed. A selection click reads nothing; buttons state whether they save metadata, check existing output or publish a clip.
