## Request and commitment boundaries

[`ProjectionPublication`](../../crates/omniusong-store/src/projection_publication_types.rs) contains the complete typed request, expected project revision, projection identity, reviewed digest, ordered lane choices, loop policy and explicit schema-upgrade permission. It accepts no caller-authored notes or retained review blob. Strict version/field checks, source-pin validation, adjacent signed SQLite revisions, canonical lowercase digests and the existing lane/name/identity limits precede publication. Bounded serialization caps the request at 65,536 bytes.

The operation ID is `os-perf-proj:` plus a domain-separated SHA-256 of the exact project and projection identifiers, each framed by an unsigned 64-bit little-endian byte length. The publisher requires that derived ID. Generic fresh edit, take attachment and archive-copy paths refuse the reserved namespace before new mutation or ingestion. Exact preexisting ordinary receipts remain replayable where their original APIs already support replay; they cannot be reinterpreted as typed projection requests. The active generic edit path also preserves the source-attachment namespace restriction.

[`recorded_commit_with_budget`](../../crates/omniusong-store/src/projection_publication.rs) checks bounded stored request/result bytes and their hashes, exact request equality, project/revision identity, canonical result serialization, the retained review's internal encoding, exact initial lane contents and the request/tempo agreement. Its compact receipt is capped at 8,192 bytes and contains identities, hashes, adjacent revisions, source reference, counts and replay status. It contains no playable document or source-authentication token.

These checks establish a recorded catalog fact. A coherently forged catalog can contain internally consistent false music; the receipt is deliberately insufficient to activate it. Exact publication replay precedes caller cancellation, source-file lease acquisition and source opening. The separate metadata-only receipt method likewise needs no original file. Neither route reinstalls an old document or silently changes a newer branch. A subsequent current load has its own source-authentication result.

## Registered originals and cumulative proof

[`RegisteredProjectionSources`](../../crates/omniusong-store/src/projection_sources.rs) groups exact references by registered take ID across relevant documents and the new requested original. It loads bounded `TakeObject` metadata, checks referenced streams/manifests, ordinary owned-object paths and registered lengths, and retains the opened readers and file identity stamps. It borrows no catalog connection. The borrowed `ProjectionProofs` holds private `AuthenticatedPerformance` values rather than accepting a supplied inspection or receipt.

Each distinct performance original receives one full authentication during that holder's authentication pass. Its actual inspected physical journal SHA must equal the registered object SHA, alongside take, manifest, descriptor and selected-prefix agreement. The performance path avoids composing the older full-file verifier with another complete performance authentication. Ordinary nonperformance takes retain their existing verifier. A performance original also used by an audio clip is grouped once, with every current and retained-original clip window still checked.

Every held reader must share the same governor identity. `InspectionBudget::shares_governor` only compares the private shared state; it creates no proof and cannot reset counters or a sticky stop. Different retained interpretations consume cumulative derivation work. Same-registry Save validates retained bindings once and separately validates candidate geometry. History validates the forward `after` bindings once, validates `before` geometry and proves its entries are the exact retained prefix. It does not rederive the same bindings for four revision-adjusted document copies.

Final checks compare the current catalog registration to each entire held `TakeObject`, then recheck owned paths, file stamps and the bounded reader's source identity. This closes the identified `INSERT OR REPLACE` trigger case, which can bypass ordinary delete triggers when recursive triggers are disabled. Files and registrations are both necessary; neither comparison substitutes for the initial source authentication.

## Atomic active paths and history

The publisher authenticates current ownership, requires exact current tempo bits and revision, derives the new binding from the held original, compares the reviewed digest and calls the existing pure complete-candidate constructor. All new lanes start muted. Existing notes, clips and opaque metadata remain intact, and the original PCM/events stay authoritative.

[`write_save_metadata`](../../crates/omniusong-store/src/lib.rs) writes one complete next revision and one before/after history row. The same transaction inserts the exact operation request and complete result. Final fences check the actual project/cursor/history bytes, absence of surplus redo rows, recorded operation result, referenced legacy asset contents, registered originals and held files. Only then does COMMIT run. There is no fallible serialization, source check or governor checkpoint after a successful COMMIT that could turn acknowledged success into cancellation. A COMMIT error remains an error/possible uncertainty; the caller must reconcile the same exact request and identity.

[`active_projection_edits`](../../crates/omniusong-store/src/active_projection_edits.rs) requires exact registry and schema equality for generic Save/Edit when either side has ownership. Generic edits cannot insert, remove, reorder or rewrite original entries. Ordinary notes may be edited or removed, and lanes/audio clips may disappear while the registry retains its original dependency. Core continues to reserve original IDs. Old-schema opaque-key promotion refusal remains in force.

Undo/Redo validates both stored history sides in their original forward order, their project identities and adjacent original revisions. Current content must equal the selected side after adjusting only revision. A registry transition is either unchanged or exactly one append. For an append, the validator derives one operation primary key, loads its bounded exact request/result and reconstructs the complete original candidate from `before`; the result must equal `after`. It does not scan operation history or infer authority from a matching hash alone. The already authenticated `after` bindings provide musical proof. Navigation updates the current monotonic revision without interpreting Undo as a new publication or re-promotion.

The metadata decoder is separated from the legacy guarded loader. Active paths deliberately use the former under a transaction and obtain source proof before return or commit. Ordinary empty-registry paths retain their existing source/file behavior; the change does not globally impose the new bounded-source route on every legacy project.

## Resource and error qualification

[`projection_metadata`](../../crates/omniusong-store/src/projection_metadata.rs) uses a thin `IgnoredAny` probe to avoid building arbitrary JSON trees merely to choose the active path. Raw dispatch bytes are prepaid; active document/history/operation materialization is prepaid from bounded stored lengths before full decoding. Final postimage reads use the same budget. Referenced legacy assets are deduplicated, size-checked and prepaid before BLOB materialization/hash. Mutating paths perform asset verification after all SQL writes, so an asset-changing trigger cannot receive success based on an earlier check. Existing compiled work/file ceilings are unchanged.

The bounded source helper preserves actual live-catalog `StoreError::Database` IOERR/CORRUPT/NOTADB codes, including extended codes, if a later sticky budget stop also exists. Source-journal SQLite failures remain nested `RecordingError` failures and do not acquire main-catalog retirement authority. Other results retain sticky budget-stop precedence. This is typed origin handling, without error-message heuristics. Actual worker retirement/correlation for new projection commands is a later integration responsibility.

**Reusable live-catalog SQL cancellation remains between statements only.** The existing source-reader SQLite VM governor is not installed on the reusable `NativeStore` connection. A large redo-history DELETE or existing catalog trigger can run until the statement returns before the next checkpoint. This review therefore does not qualify a catalog-VM ceiling, a hard response-time bound or immediate cancellation of such work. A scoped main-catalog VM/cancellation mechanism with safe hook lifetime, rollback and typed interruption handling, plus responsiveness tests, is required before native projection jobs are enabled. The current private-connection progress API must not simply be installed permanently on the shared catalog connection.

Maximum metadata/cardinality values are refusal ceilings, not a promise that every combined maximum fits the cumulative work budget. No measured maximum-capacity RSS, throughput, whole-operation latency or zero-reread claim follows from this source review.
