## Scope and retained coverage

`NativeStore::inspect_retained_projection_closure` validates the bounded project identity, acquires the retained-file coordination lease, and enters the existing deferred live-catalog scope under the caller's budget. The private inspector requires an active transaction. It returns only a versioned project identity and counts; its internal framed digest does not escape as a reusable proof. No source reader, authentication token, document, publication permit or new catalog receipt is returned.

Both streamed passes visit the current project, both sides of every retained history edge, every retained operation result and every associated ancestor-proof result. They retain bounded reference/role sets, asset identities, parent metadata and canonical binding bytes rather than all project/history documents. Counts, raw metadata totals and a domain-separated, length-framed digest must match between passes. The held read transaction supplies the consistent catalog snapshot; the digest is an additional equality check, not external authenticity.

History sequences and cursor bounds, project/revision identity, adjacent forward revisions, canonical operation requests/results and their hashes are checked. Disconnected retained operations and redo history hidden by Undo remain visited. Schema-1/2 opaque projection-looking fields retain their old meaning. All typed projection results receive initial-publication metadata checks even when no before-image remains. Each retained forward pair separately proves registry equality or one exact append and reconstructs that complete candidate from its actual before document. Absent ancestor requests/preimages are not reconstructed or represented as historical user confirmation.

Associated lineage validates the canonical bounded proof envelope and result digest, complete live-copy ownership and ancestor associations, framed mapping count/digest, live destination-operation hashes, acyclicity, transitive ancestor closure and inherited mapping linkage. Historical proof result project IDs remain historical; binding publication linkage uses the selected live project's deterministic namespace. The validator does not silently use an ancestor project as a new operation owner. Its lineage implementation is private and leaves the existing guarded archive proof parser untouched.

## Held source and binding authority

The first pass uses `RegisteredSourceSet` to collect exact references and distinguish ordinary audio from performance roles. Multiple references to one take do not choose a preferred manifest. The existing holder opens the collected original union and authenticates each distinct performance original once with the same governor; multiple distinct bindings may still require their own semantic derivations. The test's `file_bytes` statistic is not treated as an authentication-call counter.

Every document occurrence receives exact-reference and clip geometry validation. A binding enters the memo only after held-original `validate_binding` succeeds. Every repeated projection ID must have identical complete bounded canonical binding bytes. This protects immutable source interpretation while allowing later note edits, note/lane deletion and other changes permitted by the core registry rules. Successful metadata receipt parsing or coherent rehashing cannot populate the memo without source derivation.

Every memoized identity, including a binding found only in a proof result, resolves to its live deterministic typed publication row. All operation result documents have already passed the same memo/geometry checks, so the linkage receipt's source/review comparison cannot substitute for complete binding equality. `validate_publication_result` remains explicitly metadata consistency: canonical request/result, adjacent revision, final registry append, exact retained request/review, original lane choices, tempo and initially muted lane contents. Source authority comes from the held semantic pass, not this helper or its compact receipt.

Assets are unioned across all occurrences and their bounded stored bytes authenticated once under the held catalog snapshot. After semantic traversal and linkage, exact take registrations and held source identities are rechecked, then the governor is checked before read rollback. Missing or replaced originals refuse without repair, ingestion or adoption.

## Resource and error boundaries

Raw variable row lengths are bounded and prepaid before fetching and decoding their contents; fixed fields retain independent SQL `CASE` ceilings. The same sticky governor covers the two scans, SQL VM work, source authentication, memo encoding/retention, binding derivation, assets and final checks. Metadata, objects, history, operations, proofs and mappings retain their explicit caps. The cumulative governor may refuse input below an outer row/count limit; acceptance does not promise every combination at those ceilings will fit.

I found and root fixed two consequential resource issues:

- The initial ancestry check nested linear membership searches without governor calls inside the comparison work. Dense transitive ancestry could multiply work far beyond a raw-byte prepayment. The final code uses a sorted merge subset check that charges before each bounded hash comparison, prepaid map lookup and binary cycle search, a charged streamed immediate-parent search, and prepaid final ancestor equality. The dense-subset regression checks valid/missing subsets, precise work refusal and sticky cancellation.
- The shared recorded-publication helper prepaid request/result bytes but allowed its metadata reader to materialize an unbounded stored `project_id`. A forged foreign namespace was excluded from the selected operation scan yet reachable through a deterministic forward-history lookup. The final shared preflight includes `octet_length(project_id)`, requires 1–96 bytes, and includes it in the charge before metadata materialization. A real-publication regression keeps foreign keys valid and requires the exact metadata-bound refusal through both history inspection and compact receipt lookup.

Only the real live catalog enters `CatalogTransaction`. Actual catalog fatal errors survive a later budget stop; source-journal failures remain in the recording domain. Normal errors and panics use the existing hook-detach-before-rollback lifecycle, and a successful diagnostic finishes rollback before returning. The read-only diagnostic does not have a commit/publication outcome to infer. Fixed transaction-control calls, lock acquisition and filesystem stalls retain their documented timing limits; this is not a hard wall-clock or native responsiveness qualification.

The missing deterministic history request now maps `QueryReturnedNoRows` through `OptionalExtension` to `Invalid("Stored projection history has no publication request")`. Actual SQLite failures remain typed. This narrowly repairs semantic diagnostic classification; it does not weaken missing-link refusal or hide a catalog I/O failure.

`Bundle::references`, `Proof::document`, archive projection-request admission, guarded metadata/reference readers and unmigrated reader/list/attachment consumers retain their nonempty-projection fences. This slice adds no schema migration, public archive permission, native control or installed package. A separate schema-3 inert OSRE regression, remaining consumer integration, durable native admission and named-binary workflow acceptance remain open.
