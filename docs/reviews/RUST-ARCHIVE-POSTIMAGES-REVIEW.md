## Independence and the publication fences

Identity restore acquires a no-overwrite private archive through `archive_copy::acquire` before validation. `archive.rs:1663` onward reads that acquired path; the observed hash is retained separately from the requested pathname. The acquisition binds the bytes actually copied, not a caller-supplied pin or an assertion that a concurrently modified input was one coherent historic file. Existing schema, checksum and closure validation remains necessary. The pathname-replacement regression exercises the actual restore entry point and requires restoration of the acquired project after the original name points to a different valid archive.

The live writer transaction precedes complete baseline capture. A separate fixed-DDL catalog plan contains the selected rows before final-path object placement or live SQL writes (`archive.rs:1702–1769`; `archive_copy.rs:882–1075`). The plan is application-defined, never constructed by executing input DDL, and is tagged as private output. Copy identities, operation requests, mapping digests, proofs, associations and admission rows are prepared there using the immutable input and actual destination collision checks. The live catalog's pending rows are not used to authorize the mapping.

The digest ledger combines all baseline rows with the planned additive overlay. Exact existing-key reuse is limited to assets, native take registrations, copy proofs and proof-operation mappings; a second planned occurrence or any differing cell refuses. Project, history, operation, import and copy-admission collisions refuse. Both restores freeze the expected digests and prepare their result before installation. Their plan connection becomes query-only. The final full live scan and comparison precedes the sole commit, and completion state changes only after successful commit. The copy attack test deliberately rewrites the private plan coherently after freezing, including canonical request/proof hashes and lineage, proves that altered plan passes its ordinary semantic validator, then requires the frozen comparison to reject it. This is a meaningful check against deriving an expectation from an already changed destination.

Export expectations derive from the held live source transaction, fixed archive metadata or the exact original object buffer. Project/history/operation/import, asset, registration and chunk expectations are recorded through source-parameter paths; none are inferred from the written output. Lineage expectations are read independently from the same held source after `read_lineage` has bounded and validated the source. In the reviewed source that call also writes the lineage output before `expect_export_lineage`; independence still holds because the expectation reads only the held source, and all expectations precede freeze and publication. The final contract explicitly distinguishes this ordering from the other before-insert expectation paths. `archive.rs:1201–1208` compares the frozen rows, then independently applies strict fixed-format OSAR schema validation before private commit. The receipt precedes the output-link attempt, and durability precedes private success cleanup.

## Complete logical SQL comparison

`archive_postimage.rs` defines all thirteen current persistent catalog tables, including unrelated recording intents and performance source reviews/actions, and separate archive-v1/v2 layouts. The final scan is not a selected-project-only or row-count-only check. Physical `NOT INDEXED` rowid traversal reads each logical row, stores its bounded typed key and row hash in the observed index, and compares sorted per-table key/hash digests and counts with the frozen expectations (`archive_postimage.rs:990–1125`). A valid substituted project, unrelated same-count swap, extra local row or missing row cannot pass merely by remaining semantically valid.

The row encoding includes a domain, table identity, ordered column count, storage-class tag, length and exact value bytes. NULL, INTEGER, REAL, TEXT and BLOB remain distinct; INTEGER uses exact signed bytes and REAL uses the returned floating-point bits. TEXT is hashed as bytes, including embedded NUL. Composite primary keys have typed, framed ordering and a 256-byte encoded cap. A rowid is only a scan locator, not declared logical identity. The independent test oracle constructs the framing separately and includes extreme integer/real values, negative zero at the direct value boundary, TEXT with NUL and binary data. This does not claim SQLite preserves every incoming real encoding through storage or prove physical database-byte identity.

The schema fingerprint retains persistent table/index/trigger definitions, application ID and user version. Static layout checks reject unknown persistent tables, views, virtual/WITHOUT ROWID layouts, extra/generated/hidden columns, declared-type/default/primary-key changes and missing required columns. Existing supported live triggers and indexes are retained in the baseline fingerprint; any schema change before final verification refuses. Export additionally has the fixed OSAR schema check, so an extra harmless trigger cannot become part of a published archive merely because it existed when the ledger captured the output schema.

The private builder poisons itself on failure. Freeze consumes it into a one-shot expected value with in-memory digests, and verification consumes that value. Partial plans cannot subsequently be frozen as complete. The disposable spool has ordinary-file checks and Unix device/inode/link-count checks. These are trusted/cooperatively owned staging protections; they are not a qualification against arbitrary hostile same-user replacement or corruption of every private SQLite file, and provide no Windows filesystem-identity acceptance.

## Bounds and SQL/error ownership

The plan's full-value database and the ledger's combined expected/observed database each have a separate 512 MiB main-file ceiling. They do not bound temporary files, filesystem overhead, journals or retained failed staging as one aggregate. A 4,194,304 counter covers observations and ledger insertions cumulatively, so one catalog row consumes multiple credits. It is not a promise to admit that many distinct baseline rows. The layouts enforce existing per-field ceilings, at most sixteen columns, bounded keys, at most 256 schema objects and 64 KiB DDL definitions. The raw-byte accumulator checks arithmetic overflow rather than granting an unlimited-budget cancellation promise. These are explicit new safe-refusal boundaries for previously admitted oversized ordinary catalogs.

Large TEXT/BLOB values use at most 64 KiB Rust substring results after length/type checks. Each separate substring/CAST query now prepays full-cell interpretation as well as its returned buffer when a governor is supplied (`archive_postimage.rs:632–653`), since SQLite can rematerialize the full cell on each query. The three-chunk test distinguishes this accounting from charging a full cell only once. The optional helper governor is borrowed, never reset, and owns a progress hook only on the disposable spool. Source/destination connection hooks remain caller-owned. The actual three ordinary routes deliberately pass `None` and use legacy catalog scopes: there is no new cumulative work/VM/cancellation/time guarantee for those routes, and no bound on every SQLite internal allocation or filesystem stall.

Every new spool/plan SQL call is private output. Input archive reads remain input-origin errors; actual destination/source-catalog SQL remains live-catalog origin. `Destination::sql`, explicit lineage destination origins and `plan_objects` preserve the distinction when a mixed helper is enclosed in another domain wrapper. Postimage verification receives the actual connection's explicit origin. With a helper governor, finalization preserves actual fatal main-catalog codes and unusable-connection state ahead of a later sticky stop (`archive_postimage.rs:317–328`). A malformed private SQLite fixture tests the tagging API with both supplied origins; it is not an executed corruption of the user's live catalog.

Existing `CatalogTransaction` failure handling still owns live rollback. Refusal before commit retains diagnostics and any installed content-addressed orphans; it does not claim final-path objects were rolled back. Success-only cleanup occurs after commit/durable link, and cleanup problems remain warnings under the prior [outcome contract](../contracts/NATIVE-ARCHIVE-OUTCOMES.md). No fallible post-commit revalidation is added. Export removes its known archive/spool files and then only the empty stage; restores clean their owned stage after completion. Legacy wrappers continue to omit successful cleanup warnings from their old return types.

## Review corrections and the inspected tests

The initial source review identified three corrections, all present in the final source: repeated full-cell work prepayment, query-only copy plans after freezing, and strict export schema validation after exact-row verification. The new harmless-trigger test requires refusal without publishing a destination even when every expected cell matches. Placing that strict schema check after row verification also preserves the stronger coherent payload/hash and native chunk replacement oracles: those tests must reach the row mismatch, not succeed merely because a trigger is an unsupported format object. Lineage values now pass the existing bounded validation before expectation materialization. The contract correctly describes the multi-credit row cap and the actual None-budget route limitations.

Inspected tests cover independent typed framing and exact SQLite cell values; missing/extra/substituted rows; narrow shared reuse and poisoned duplicate plans; private-plan streaming; unrelated local action rows; unsupported schema changes; field/key/counter overflow; a real lowered spool page limit yielding private-output `SQLITE_FULL`; private malformed SQLite origin tagging; sticky cancellation, work and private VM limits; and v1/v2 layout coverage. The page test lowers the limit to exercise a real refusal; it does not allocate a full 512 MiB file. Counter tests exercise the boundary directly rather than allocating millions of rows.

Actual-route test source includes identity and copy project replacement, same-count unrelated changes, unplanned recording intent insertion, exact SQL rollback and subsequent successful retry, pathname replacement after immutable acquisition, coherent export payload/hash substitution, and a real device-free one-frame recovered native original with coherently rehashed archive chunk substitution. The latter retains a positive successful export control and compares the original journal bytes and current source project after refusal. The earlier attempted manifest-whitespace attack was reported by the coordinator to hit the existing canonical-registration validator and was replaced by this stronger final-row attack; it is not counted here as postimage evidence. Existing copy replay and multi-generation ordinary archive tests remain relevant compatibility gates, not nonempty projection-copy evidence.
