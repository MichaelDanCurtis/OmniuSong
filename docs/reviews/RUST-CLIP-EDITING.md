# Native clip-edit backend: independent review

Reviewed against working-tree source based on `e1e8d9d31c48170dfdfc831ff60a1d73c52c6190`, on October 20, 2026. The bounded backend packet is accepted on source inspection and the coordinator's recorded software tests. This is not acceptance of native clip controls, a new packaged application, recording, or physical playback.

The reviewer authored only `crates/omniusong-store/tests/clip_edit_review.rs` during implementation and this review during the final audit. The coordinator ran formatting, builds, tests, and Clippy. The reviewer ran no Cargo command, native stream, GUI action, or live-catalog query. Fixtures use unique isolated directories and synthetic originals; deliberate corruption and SQL faults affect those fixtures only.

The implemented contract is [NATIVE-CLIP-EDITING.md](../contracts/NATIVE-CLIP-EDITING.md). Its final status header identifies the implemented, software-qualified backend and separates it from the unchanged note-editor package; this documentation-only status refresh changes no contract semantics or qualified source. Source review covered `clip_edit_types.rs`, the new clip scope/operations in `contracts.rs`, `clip_edit.rs`, recording payload validation in `native.rs`, store operation admission and take validation, archive postconditions and the existing copy remapper. The session's existing narrow `EditRejected`/`RevisionConflict` classification and conservative mutation uncertainty remain applicable; this packet adds no separate clip-specific UI or service policy.

The following design requirements are resolved in the reviewed source:

- **Exact changes and identity.** Legacy track keys retain their existing Unicode, empty-string, and control-character domain. Native track/clip keys keep the strict ASCII domain. Lookup uses equality keys and checks track kind, lock state, clip existence, and audio-frame units. `Keep`, `Set`, and `Remove` are explicit typed operations; a legacy decimal remains a `serde_json::Number`, rather than being rewritten through `f64`. Mutation clones the document and changes only the selected raw settings. Source IDs, rate, unit, bytes, recording observations, unrelated notes/expression, and opaque metadata remain outside the patch.
- **Strict wire shapes.** The first core run exposed a real Serde issue: internally tagged unit variants accepted unknown fields despite the enum annotation. The coordinator replaced deserialization for `FieldChange`, `ValueChange`, and `ClipTimelinePolicy` with strict empty-struct wire variants. Their serialized forms remain unchanged. The subsequent integrated run passes the missing-field, arbitrary-field, representation/scope, numeric-bound, and exact-decimal roundtrip cases. The initial failure remains recorded rather than being represented as an uninterrupted pass.
- **Immutable first settings snapshot.** Legacy snapshots preserve originally present fields and exact numeric values. Native recording payload v1 remains readable and rejects a raw `editSource` slot, including null. Payload v2 permits the owned snapshot, validates its version and allowed original-setting keys, rejects nested snapshots and event-unit originals, and requires the same sample rate as the current view. The first settings change promotes only the selected payload. Extent-only changes do not create a snapshot or promote v1. Restore retains the entire snapshot, including unfamiliar outer metadata, and preserves absent/null/object fades. Untouched sibling clips are never replaced by a typed serialization.
- **Source authenticity covers both views.** `takes::check_clip` checks the current clip and `original_view()` against the same authenticated take/manifest/stream. Both windows must start at or after the descriptor's initial source position and end within the verified sealed prefix, with matching PCM rate. Bytes physically present in a damaged unselected tail do not extend that prefix. Recovered originals and their bad tails remain available unchanged. A valid reference spanning a declared gap remains a renderer rejection, not fabricated silence.
- **Arrangement extent is explicit.** PreserveLoop does not quantize settings or change bars/schema. Native ExtendLoop uses checked signed-frame addition and the exact binary ratio of the validated tempo in `u128`; integer ceiling is applied before narrowing. Legacy ExtendLoop uses the documented ordered floating-point seconds estimate, without replacing the stored numbers. Neither policy shrinks the loop. The existing source-relative fades and full-content native one-shot rendering remain unchanged; browser loop-shortening behavior is not transferred to this backend.
- **Admission and rollback.** The new operations use the existing replay-first, expected-revision transaction. Only errors returned by the pure mutation are mapped to `EditRejected`; source verification and SQL errors retain their original classifications. A repeated identical operation returns its original receipt without reverting a later project. Changed requests and stale new operations reject. A failure on the final operation insert rolls back settings, payload promotion, history, cursor, and revision.
- **Archive/copy closure.** The whitelist explicitly includes both clip operations. Postimage checks verify target/type/lock, every authored Set/Remove, exact Restore field presence/value, and requested extent coverage. They do not claim to establish the historical Keep preimage, source originality, or necessity of an earlier schema upgrade from a lone receipt. Source validation visits retained results as well as both history sides and the current document. Copy continues to remap only root project and typed operation/project identities; track/clip/take identities, original imports, snapshots, opaque identity-like strings, and full owned object bytes remain unchanged.

Historical format compatibility has a precise boundary. New original publication still emits recording payload v1 and refuses a supplied snapshot. `TakeClip.edit_source` is appended as an optional field with `skip_serializing_if = "Option::is_none"`; when absent, the previous canonical field order and wire output are unchanged. Existing schema1/2 and v1 publication/archive paths pass in the integrated tests. The new independent operation-only test also exercises retained v1 publication alongside v2 edited and restored results, identity restore, copy mapping, and re-export/restoration of the copied lineage. This review does not claim a fresh execution against a historical packaged binary or a previously archived external fixture; the omission compatibility above is additionally established by source inspection.

The 11 independent store tests passed. They cover exact imported JSON and encoded-source bytes without decoding, long decimal lexemes and omitted defaults, uncalibrated recordingTiming and guide-note retention, signed preroll, native null fades and unchanged siblings, retained outer snapshot metadata, both source-window bounds and rate authentication, exact retry/conflict/history/reopen, final SQL rollback, wrong scope/kind/lock/fades, complete recovered-object retention through operation-only archives and copy, and replay refusal after owned-file damage. Nine native and two legacy rehashed archive mutations must fail for their explicit semantic contradiction, including two decimal strings that round to the same `f64`. Separate rehashed ledger-result cases place the retained original before the source origin or beyond the verified prefix and must block replay and fresh archive export. These latter cases deliberately avoid mistaking an aggregate archive-index mismatch for proof of range validation.

The separate eight-test renderer review uses the production `prepare` and `RenderCursor` implementations with synthetic PCM. It checks legacy half-frame rounding, exact stored decimal spelling, overlapping rounded fades without rescaling, full-content rendering independent of bars, chunk-crossing native windows, preroll cropping without restarting fades, equal-power/linear endpoints, integer conversion, planar channel order, unsupported conversion/rate rejection, declared-gap rejection, and restoration of the original rendered PCM. Original files, raw observations, and muted expressive notes remain unchanged. This proves agreement for the exercised software cases; it does not qualify a device callback, audible quality, latency, arbitrary codecs, or streaming long-arrangement playback.
