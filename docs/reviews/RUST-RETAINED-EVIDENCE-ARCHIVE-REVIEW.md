# Retained native evidence archive review

October 22, 2026. [Contract](../contracts/NATIVE-RETAINED-EVIDENCE-ARCHIVE.md); coordinator test packet is recorded separately after the integrated gate. This review covers the explicit full-root Rust storage API, not native archive controls or complete milestone 2 acceptance.

The coordinator owns OSREv1, catalog snapshot/closure validation, replay/restore, shared governor additions and integration. One agent implements raw ownership/inventory, another independent agent writes byte/SQL oracles, and a third reviews persistence/resource correctness without editing or running Cargo. Only actual coordinator runs count as test evidence.

The selected closure is the entire native catalog plus every retained file/empty directory under captures, source-actions and takes. This includes unassigned/failed recording attempts, pre-recovery images, partial/completed working copies, exact original rows and unknown ordinary files/sidecars. The catalog is a logical SQLite Backup retaining exact SQL cell types/payload bytes, all lifecycle revisions, project relationships, operation receipts and unknown unrelated tables/cells. Recording databases are never opened or repaired by this archive path. Restore creates numbered inert objects and historical metadata; it never installs a live catalog, intention, operation or action.

Consequential findings and corrections:

- History parsing/hashing, manifest processing and both payload hashes need the same sticky work credit. The complete compiled history read/parse/hash bound is reserved before loading; private catalog SQL uses the same VM/cancellation hook. Catalog allocation/copy credit precedes bounded reservation. Cursor over already complete bytes avoids this rusqlite version's fallible-reader allocation leak. The serialize feature adds no new crate or runtime.
- Output directory identity and bytes require independent proof. Private root/objects directory anchors, exact membership, full numbered-object hashes and canonical manifest checks now precede the exclusive completion marker. Late directory substitution, object corruption, symlinks and surplus members must refuse completion.
- Checksums do not alone prove known catalog closure. Inspection, historical export replay and restore all revalidate schema 6, known ordinary linkage tables, exact required members and optional absence facts using a read-only in-memory catalog copy. Rehashed omissions with unchanged catalog bytes refuse. Hidden/generated/default columns and unsupported layouts are rejected before value projection; a generated builtin can allocate outside a few VM steps.
- A source-review assumption about independent OS/SQLite locks was contradicted by actual macOS tests: locking the active studio.sqlite3 caused DatabaseBusy failures. The live catalog now has metadata-only identity/mtime/ctime checks and same-connection data_version fencing; no extra raw catalog FD or std file lock interferes with SQLite's locks. SQLite Backup supplies the logical snapshot.
- A committed-WAL fixture exposed copied WAL-mode header bytes. Only the new private catalog snapshot is reopened and normalized to rollback mode. All committed SQL cells and the live catalog/original bytes remain exact; the live catalog is not checkpointed.
- Same-process file coordination must account for overlapping roots and arbitrary archive destinations, not just exact root keys. The first exact-root design was rejected in independent review. Active multi-path RAII leases now cover source roots, cross-root archive I/O and the private catalog destination parent, with nonblocking admission and descriptor-before-lease cleanup. New nested catalog opens require writer admission before SQLite; preexisting ASCII-case variants of studio.sqlite3 refuse metadata-only raw inventory. Disjoint roots remain usable.
- Invalid archive input must not open a live native database merely to reject its header. Native SQLite names/sidecars and existing recording-owner siblings refuse metadata-only; exact-input exclusive leases cover active ownerless partials. An overly broad input-parent lease initially broke historical sibling replay during ingestion; the exact-file correction restores that behavior while covering the opened inode. This is the native naming/cooperative lease contract, not arbitrary uncoordinated same-process SQLite safety.
- Raw owner acquisition must precede opening database data descriptors. Otherwise refused work can close extra FDs and release a same-process SQLite transaction's POSIX locks. All existing owners are acquired first; data descriptors must also close before owner release on success/error. A separate-process SQLite writer probe, rather than a second connection masked by SQLite's process-local bookkeeping, is required evidence.

The [formal packet](../verification/rust-native-retained-evidence-archive-tests.json) records actual commands, source stability and live preservation after these corrections. The actual pre-fix separate-process probe failed because SQL BEGIN unexpectedly succeeded after a refused raw acquisition; owner-first acquisition and ordered Drop make the same probe pass, with a positive control after ROLLBACK. Two-handle ownerless-ingest, nested catalog, cross-root archive destination, cancellation/release, wrong native catalog/WAL/SHM input and misnamed-owned-input checks provide separate regressions. The actual typed six-stream version-1 recovery and version-2 Finish attachment/Keep/Return integration is separate from the opaque store-catalog fixture tests. Earlier pre-gate failures are retained as failures; no passing test or agent report supplies native acceptance.

The evidence boundary remains Unix cooperative owners and trusted ordinary directories, on small isolated synthetic material. All-source scope is explicit, rather than selected-song scope. Unsupported/missing required bytes refuse; partial archives, failed catalog stages and incomplete restores are retained. No total disk quota, hard power-loss, long-session or descriptor-capacity qualification follows. The 512 MiB per-file/archive and 1 GiB cumulative-work limits remain, with conservative metadata credits and bounded extra catalog RAM. This host filesystem rejects invalid UTF-8 names before file creation; that is not physical qualification of the raw inventory branch on another Unix filesystem.

Checksums are not signatures. Complete creation is established by the admitted finite inventory, ownership, full raw hashes and catalog/file-set fences; a coherently rewritten catalog plus index or an omitted unreferenced file by a malicious archive author cannot be authenticated. Historical replay binds the same export ID/destination/origin path, not a cryptographic catalog identity. Native session/job controls, selected-source/combined-song exports, explicit imported-source adoption, a complete operator schema-5 rollback, complete native source-review/recovery/archive walkthrough, long capacity and actual Windows remain subsequent work.
