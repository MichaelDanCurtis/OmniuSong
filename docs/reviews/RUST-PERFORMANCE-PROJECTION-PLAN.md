# Performance projection integration plan

October 22, 2026. Continue milestone 2 through the [projection contract](../contracts/NATIVE-PERFORMANCE-PROJECTION.md). The complete Rust workstation goal remains unchanged. This plan records dependency and authority decisions; implementation and acceptance are separately evidenced.

1. **Shared reader and read-only projection kernel.** Extract pure owned performance types, codec and contextual six-stream verifier into `omniusong-performance`, beneath engine/store. Preserve engine API paths and existing format bytes. Keep realtime queues, writer lifecycle and private normal-seal authority in the engine. Authenticate a held sealed original with one cumulative governor, derive bounded frame-selected note interpretations, disclose conversion losses and retain exact observations. Qualify with real device-free recovered v1/v2 sources, fixed pre-extraction bytes, independent semantic-tampering tests, cancellation/limits and exact regular-studio preservation. This stage creates no project operation, native control or new installed bundle.
2. **Explicit musical schema-3 ownership.** Add a versioned root `performanceProjections` registry while ordinary notes tracks retain their editor/render paths. Schema-1/2 unknown fields remain opaque. Explicit promotion refuses a preexisting opaque registry key instead of overwriting it. Core owns a strict outer registry, stable projection identity, typed take reference, original lane/note bindings and a bounded immutable review; the shared library validates complete review semantics. The registry describes the original interpretation, not a claim that later edited notes still match it. Removing notes or the audible original clip must retain its source dependency. Reserve original projected note IDs against later AddNote reuse and lane IDs against retained registry collisions. Musical schema 3 is distinct from the current SQLite schema 6; this change need not introduce a SQL table.
3. **One typed atomic publication.** A bounded request carries stable operation/project/revision/projection identities, source/interpretation request, expected review digest, lane choices and explicit timeline/format policy. It carries no UI-supplied note array. The store performs replay-first exact request matching, opens the registered owned source under a held governor, recomputes the review, compares its digest and constructs one candidate through core. Project, history and operation receipt commit together. One Undo removes publication; Redo restores it. New lanes initially remain muted while original PCM stays audible. Audition mode must make original-versus-derived playback explicit and prevent accidental doubling.
4. **Complete archive and copy closure.** Extend core/store ownership enumeration to registry sources independently of recording clips. Export full physical take bytes, including unselected/damaged originals. Recognize the new versioned operation shape, validate exact result/source/lanes and recompute source semantics with the shared verifier against held archived originals. Reject malformed versions/fields/postimages before publication. Restore-as-copy remaps owned project/operation identities only; projection/source identities, raw ordinals and content-review digest remain exact. OSRE retains the updated catalog/source closure inertly without adopting projection authority.
5. **Native review, publication and editing.** Preview is a separate read-only command with exact source and current-context correlation. Show selected frames/sources, note/omission counts, policy, exact timing origin, hard cuts and conversion differences. Confirmation sends a fresh explicit publication request; successful commit installs only the correlated current document and preserves drafts. Exercise note selection/edit/Restore, Undo/Redo, complete archive/copy, restart and original-versus-derived audition in the actual app. Software kernel results cannot replace this native walkthrough.
6. **Durable uncertainty and subsequent recording work.** Complete durable exact-request admission before enabling stage 5's restart retry/reconciliation. The existing operation ledger records committed requests; an in-memory UI draft cannot recover an uncommitted lost operation ID after restart. Persist the bounded exact request before execution in an explicitly owned admission record and include it in schema/evidence closure. A proven absent operation must not cause automatic rebasing or new-ID replay. After the integrated projection workflow, continue metronome/count-in, monitoring/overdub/compensation, waveform manipulation and segmented/progressive recording capacity, then the remaining MIDI 2/MPE, instruments/plugins, Rust inference, choir and platform/install gates.

An Astra architecture agent owns extraction and independent kernel/publication review. A Sol implementation agent owns the projector and focused tests. A separate Sol reviewer owns device-free renderer/writer integration and adversarial oracles. The coordinator owns shared manifests, format decisions, integration, all Cargo/native verification and final evidence. Agents do not open devices, mutate the regular studio, run concurrent builds or modify each other's files.
