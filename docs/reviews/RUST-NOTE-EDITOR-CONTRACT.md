## Findings and adopted decisions

1. **Existing document keys need their own exact address type. Resolved in the frozen DTO.** `ProjectDocument` permits empty, Unicode and control-bearing track/note keys, while transport `TrackId`/`NoteId` require a restricted nonempty ASCII string. Using transport IDs for existing notes would make valid imports uneditable or force identity rewrites. `DocumentNoteAddress` retains the legacy character/byte limits and performs exact equality lookup. Note identity is the pair of track and note IDs within one project, not pitch, start time or array index. The same note ID on another track remains legal; duplicate IDs within one track are rejected by document validation. New Add IDs retain strict `NoteId` validation. Sources: `core/src/lib.rs:120`, `core/src/lib.rs:477`, `core/src/note_edit_types.rs:9`, `core/src/contracts.rs:900`.

2. **First-source capture and Restore must preserve expression representation and opaque metadata. Resolved in current source.** The browser prototype normalizes missing/null expression to `[]` and removes `editSource` on Restore (`public/note-edit.js`). Neither behavior is appropriate for lossless native editing. The native implementation captures expression only when present, retains the first whole snapshot permanently, and restores its exact known fields and expression presence without replacing source identity, input clocks, physical key duration, release velocity, raw packets or model estimates. An existing snapshot's unrelated fields remain exact. Restore concerns an existing edited note; durable Undo restores a deletion. Sources: `core/src/note_edit.rs:55`, `core/src/note_edit.rs:144`, `core/src/note_edit.rs:183`.

3. **Musical bounds and loop extent are distinct. Resolved by the explicit timeline policy.** The prototype's 128-bar editing limit cannot be applied to otherwise-valid imported native note values. PreserveLoop permits those values without changing bars/schema. ExtendLoop may grow, never shrink, and requires explicit permission when extending a schema-1 document beyond 128 bars. A schema change cannot silently bypass the metadata cap. Extent-only changes are valid and create no first-source snapshot. Exact integer odd ticks and every u16 velocity, including zero, remain representable. Active expression points constrain shortening; a longer immutable source curve does not constrain a different shorter active curve. No curve rescaling or quantization is implicit. Sources: `core/src/note_edit_types.rs:37`, `core/src/note_edit.rs:76`, `core/src/lib.rs:96`.

4. **Known semantic rejection must not masquerade as an uncertain committed edit. Resolved by the narrow error type.** Session handling previously marked every mutating failure except revision conflict as an unknown outcome. Locked targets, missing notes, unchanged values and rejected expression shortening all fail before saving. `StoreError::EditRejected(DocumentError)` now wraps only pure note-mutation errors, and the service maps it to a known `FailureKind::EditRejected`. Database, receipt, file-verification and postcommit projection failures retain their own conservative classification. Do not globally exempt ordinary `Rejected`/`Document` errors: a projection can fail after a commit. Independent store tests distinguish these pure failures from injected final SQL failure; the integration agent's separate service tests cover the surfaced outcome. Sources: `store/src/operations.rs` note dispatch; `session/src/lib.rs:406` and final mutation-error handling.

5. **Archive checksums alone do not prove a note receipt agrees with its request. Correction implemented, source-reviewed and independently tested.** An untrusted archive can recompute a canonical request/result checksum while contradicting the typed edit. `store/src/archive.rs:236` now inspects the bounded result: exact existing unlocked note track; Add/Update target values match; Delete target absent; Restore active values and exact expression presence equal the retained snapshot; ExtendLoop covers the note end. Add's frozen authored shape is exactly ID, four values and empty expression, with no invented performance fields. The helper does not demand a source snapshot for an extent-only Update, infer an unavailable original schema, or pretend these postconditions reconstruct a complete preimage. Both identity restore and copy restore use the check. Independent regressions alter requests or results, recompute their SHA-256, and require the specific semantic rejection before project publication, so a later aggregate-index mismatch cannot produce a false pass.

6. **Current UI inspection state is not a safe edit address or bounded edit projection. Required for the later interface packet, not a library defect.** `app/src/main.rs:150` stores selection as an array index; `piano_overview` also uses index selection, iterates the selected track's notes during paint, and formats the complete expression JSON (`main.rs:1198`). A future draft must capture exact project/track/note identity plus expected revision, preserve integer values in its controls, and never retarget after Delete, refresh, import or Undo. Its display projection must cap expression/opaque summaries, escape control-bearing keys for display without changing their stored equality keys, and show truncation rather than serialize up to the full metadata limit every frame. Virtualized exact-value rows should keep coincident notes individually selectable. Full-document cloning/validation belongs on the worker.

7. **A note draft must join existing session and audio guards. Required for the later interface packet.** Current dirty state concerns metadata; adding fields without extending that state could discard a draft on selection, Save, archive, Undo/Redo, close or reconnect. Use an explicit draft and stable operation ID. Save/Discard/Cancel must cover metadata and note changes coherently. A conflict must preserve the draft and exact failed intent, require an explicit refresh/new decision, and never silently rebase or reuse its operation ID for altered values. A lost-ack retry reuses the original request; its original receipt must not replace a newer displayed project. Audio/recovery guards and callback-acknowledged Stop remain applicable; a note edit must not start live output or device input implicitly.

| Boundary | Independent cases |
| --- | --- |
| Exact targeting | Empty/control/Unicode legacy keys; repeated pitch/time; same note key on another track; strict new Add ID; no index/pitch lookup |
| Source preservation | Absent/null/empty expression; immutable first snapshot; unknown source fields; raw UMP and clocks; original input/model metadata; literal greater-than-u64 integer and long decimal |
| Musical semantics | Odd ticks; velocity zero/full precision; active expression tail; source curve independence; exact Restore; unchanged-result rejection |
| Timeline/schema | Valid long schema-1 notes under PreserveLoop; explicit denied/allowed promotion; no shrink; extent-only update without snapshot |
| Refusal/limits | Locked/audio/recording tracks; scope forgery; fractional/out-of-range DTOs; snapshot growth crossing schema metadata cap; original unchanged on failure |
| Durable admission | Exact replay after later Delete/reopen; changed request and stale revision refusal; final receipt SQL fault rolls back current/history/cursor/revision; typed precommit rejection |
| Complete archives | Delete and Restore results retained after redo truncation; exact original import bytes; original raw/opaque fields; identity restore; fresh copy IDs with unchanged document note keys and opaque IDs; mapped replay; source/archive bytes unchanged |
| Untrusted receipts | Rehashed Update/Add values, contradictory Delete/Restore results, locked target and uncovered ExtendLoop; identity/copy rejection without project publication |
