# Performance-aware retained-source service plan

October 20, 2026. **Planning only; no implementation or qualification is asserted.** This review reads the current schema-5 intent service, performance checkpoint scanner, recording inspection primitives and generic recovery UI. It proposes one bounded next packet through the existing `SessionService`. It does not authorize a normal seal, resumed recording, input device, editable-note projection, or automatic attachment.

The coordinator reports that package `4981d54a` is built from the pinned 136-source gate with 750 passing tests, but its actual Mac startup is waiting for the external-drive permission prompt before catalog migration. Those are coordinator-reported boundaries, not an actual recovery walkthrough observed in this review. Preserve the existing 16 projects, 338 rows, four owned takes, old catalog and installed package. No source, catalog, device or package changes were made for this plan.

## Discovery, identity and ownership

Add a distinct performance discovery action on the sole session worker. Read at most 128 directory entries **in total per requested scan**, without opening journals. Report `truncated` conservatively, bounded problems, and explicit invalid/unavailable rows; do not pretend every stage was searched. Durable intent cards can additionally be opened by exact known ID even when the bounded directory scan omitted their entry. Never automatically inspect every discovered file.

Classify names before source access:

- Canonical hyphenated UUID: existing generic capture workflow, unchanged.
- Exactly 32 lowercase hex digits, nonzero: performance candidate only; path is `<canonical opened root>/captures/<stage>/take.sqlite3`, and expected take ID is `performance-<stage>`.
- Everything else: unsupported entry, with no path traversal, alternate spelling, case folding or lossy identity conversion.

A filename is not a performance proof. Inspect the owned descriptor via `descriptor_profile` and `from_descriptor`; accept only supported strict v1/v2 configurations. Reject dual, null, future or malformed owned markers instead of treating them as generic captures. The actual take ID must match the stage. A linked durable Start must also match the exact GUI clock/take; do not infer its selected output endpoint or parent generation from filenames or callback observations.

Before SQLite sees a stage, repeat the existing ordinary canonical root/captures/stage/file checks, reject symlinks and Unix multi-link journal/owner files, require the existing owner sidecar, and preflight the SQLite signature/rollback-mode header plus absence of `-wal`/`-shm`. `CaptureReader` must return `Owned` without changing state when a live writer holds the lock. Do not create a missing directory, catalog, journal or owner sidecar. Do not remove a rollback journal or attempt SQLite repair: a hot/ambiguous `-journal` must be reported unavailable; ordinary read-only SQLite handling must not be advertised as power-loss repair. Windows alias guarantees remain unqualified.

Hold the reader's owner and read transaction through semantic scanning and its conversion to checked recovery. Recheck confinement/ordinary identity before conversion; do not release ownership between review validation and the first mutation. The current filesystem contract still excludes hostile same-user replacement of trusted parent namespaces; canonicalization is not a sandbox. A main catalog reconnect uses existing-only opening; a missing mount is never initialized as a new store.

## Proposed service DTOs and actions

These names are proposals for root/type freeze, not landed APIs. Use strict serde wrappers and explicit byte budgets; never return PCM, raw envelope vectors or a full project to the UI.

`PerformanceStageScan { stages, problems, truncated }` contains at most 128 bounded rows. Each row has stage ID, root-derived journal path, optional linked intent identity, and discovery state (`Uninspected`, `Owned`, `Unavailable`). Recording/sealed classifications require actual inspection, not a directory name.

`PerformanceSourceReview` should bind version, stage/path/take identity, descriptor SHA, physical file SHA/byte length, normalized **all original rows** SHA, observed journal state, supported profile, optional linked intent ID/revision/payload SHA, full `PerformanceInspection`, optional authenticated manifest SHA/mode, selected audio range/configuration, bounded problems and a canonical `review_sha256`. The nested inspection retains the exact selection, checkpoint body/SHA, generic verified count, Finish cut, first capture fault/pending marker, unknown-tail and problem. Do not collapse those into a success boolean. Separate selected six-stream prefixes from the generic verified suffix so a longer audio-only tail cannot enter the song.

Compute the review hash with a versioned domain over every field except its own hash. Recompute it from caller DTOs before use. All integer units remain explicit: audio frames, event ordinals, callback indices, GUI ticks and chunk ordinals are different axes. Show source start/count rather than treating the end as a duration. Performance descriptors currently establish audio origin zero, but validate that fact rather than copying the generic UI's assumptions.

Proposed commands/replies:

| Command | Reply and effect |
| --- | --- |
| `ScanPerformanceSources` | `PerformanceSources(scan)`; directory discovery only. |
| `InspectPerformanceSource { stage_id }` | `PerformanceSourceInspected(review)`; read-only, exclusive stage review. |
| `SavePerformanceSourceIntent { expected_revision, intent }` | Durable exact receipt; no source mutation or engine action. |
| `ListPerformanceSourceIntents` | Latest bounded typed receipts after validating every retained revision; no automatic inspection or resume. |
| `RecoverPerformanceSource { id, revision }` | Load only the stored immutable recovery choice, revalidate exact source/review, call `recover_performance`, return correlated manifest/review/checkpoint receipt. |
| `InspectStoredPerformanceSource { id, revision }` | Read-only normal/recovered source reauthentication, including authenticated owned source when available. |
| `AttachPerformanceSource { id, revision }` | Execute only the stored explicit publication after normal/recovered-specific admission; existing project/history/operation ledger owns publication and replay. |

Every response must match session generation, request ID/kind, selected stage and exact durable source-action revision. No caller-supplied arbitrary path or replacement publication reaches recover/attach. Scan and inspect are read-only; save/recover/attach are mutating and retry-safe only for their exact retained request. The UI must not send a new operation ID after an uncertain completion.

## Durable review and operation choices

Root must freeze the storage/version decision before implementation. **Recommended:** a separate bounded append-only source-action envelope, leaving `PerformanceIntent` v1 and its history unchanged. A v2 equivalent is viable only if it can represent both linked and orphan origins without manufacturing a `PerformanceStart` or changing old immutable fields. The source ledger is studio-local lifecycle evidence, not automatic song/archive closure.

Proposed record: `PerformanceSourceIntent { version, id, origin, project_id, review, recovery, attachment, released }`, with `origin` either an exact existing intent reference or explicit discovered-stage evidence. `review` is immutable. `recovery` is absent or `{ operation_id, reviewed_sha256 }`; `attachment` is absent or one exact publication plus its source receipt binding. Optional fields are append-only, release is irreversible, and released rows remain counted. A normal reviewed source needs no recovery operation. A changed review requires a fresh source-action identity and explicit UI choice; never rewrite an uncertain action.

Proposed bounded starting budget: 32 source-action identities, 16 revisions each, 64 KiB per payload/request, at most 32 MiB retained history. Root may choose a tighter encoded shape after maximum-checkpoint fixtures. Do not silently force a complete checkpoint review into the existing 16-KiB intent field: a checkpoint's own envelope already has a 16-KiB ceiling. Preserve every old v1 byte/history row during any schema migration and prove rollback/future-version refusal. This plan does not implement eviction, salvage of damaged intent history or a superseding attachment-conflict workflow.

Persist the exact recovery operation and complete reviewed source before mutation. `recover_performance` already derives its journal operation from `(operation_id, expected inspection)`. Wrap that admission with the canonical full service review, then retain both identities. First attempt requires full current equality including the physical review hash. After an intentional interruption/seal write, physical file bytes legitimately change: exact retry authenticates normalized all-original rows, descriptor, selected checkpoint/index, recovery operation and recovered mode, rather than demanding the old physical hash. A changed unselected bad tail must still reject. Re-reading a fresh review and substituting its token is a new action, not the same retry.

After recovery, return selected bounds and `unknown_tail=true` even when every retained chunk is currently readable. Retain all later valid, incomplete, corrupt and unselected rows, original clocks, rejected/discarded batches, transitions and cause evidence. Never invent NoteOff, calibrated clock anchors, missing PCM, or a complete GUI event count. No-checkpoint/empty-audio sources remain inspectable but cannot become playable recovered originals. Partial review can report a valid earlier checkpoint plus its later problem; it must not call that a clean normal recording.

## Attachment admission after restart

**Normal reopened v2:** authenticate the existing manifest and descriptor, strict config, complete six-stream semantic selection equal to the manifest count/index, positive audio, Finish/cut closure, and no captured/pending fault. Compare a linked persisted Finish if present. A newly discovered normal source may offer a fresh explicit attachment based on its authenticated stored Finish, while clearly stating that the original parent Start/output choice is unavailable. Do not fabricate a durable Finish intention or new native shutdown capability from it. Normal v1 without Finish is inspect-only in this packet. No existing source is normally resealed or promoted from recovered to normal.

**Recovered v1/v2:** require the durable exact reviewed recovery action and its authenticated recovered manifest, selected complete checkpoint, whole-original digest and six-stream prefix. Attachment uses only selected audio, not generic source end or every readable later row. Known capture faults, pending-cause markers and unknown tail remain disclosed; they do not disappear because the retained prefix is playable. A preexisting recovered manifest without the old reviewed-action proof remains inspection-only until a separate explicit adoption policy is frozen. A manifest's `interrupted` field alone does not prove this service reviewed its selection.

In either case, preserve the full sealed SQLite original during ingestion, including unselected/bad rows. Prefer a registered authenticated original to staging; never fall back when the owned source is corrupt. Resolve an exact committed publication receipt before unavailable-source access; then retain existing physical owned-source verification and return the current project on replay. Ingestion may commit before publication conflicts; report that retained library original truthfully. The publication, expected project revision, operation/track/clip IDs, source bounds and sample rate must all be persisted before explicit attach. Source inspection and recovery do not publish, autosave a dirty draft or silently retarget another song.

## Resource, cancellation and error boundaries

The scanner currently bounds working groups (8 MiB, 63 members plus checkpoint), individual chunks and records, but `CaptureReader::open` hashes the whole file/all original rows and the scanner has no overall work/cancellation parameter. Streaming memory bounds are not a bounded-response-time guarantee. Do not reuse the 120-second playback or 64-MiB playback-object limit as if it constrained recording originals.

Freeze explicit review limits and refuse over-budget sources intact. A proposed first service limit is 512 MiB physical file, 262,144 retained rows/chunks and 1 GiB cumulative original-field scan work, with 64-KiB returned DTOs and the existing group scratch ceiling. These are proposed review limits, **not writer/duration limits**. Larger originals need a later scalable review path; no truncated scan may authorize recovery. Add checked counters before loops/allocations and cancellation checks between hash blocks/chunks/groups; current readers need parameterized bounded variants to enforce this before the initial full scan. Existing OS reads/SQLite calls may still block. Drop must not join the UI, and no replacement worker starts while an old owner may remain active. Reliable engine Stop stays independent of the storage queue.

Keep stage errors wrapped as `StoreError::Recording`/source-specific errors. A local stage `CORRUPT`, `NOTADB` or `IOERR` must not impersonate main-catalog `StoreError::Database` and quarantine a healthy library generation. Main-catalog typed fatal errors keep existing quarantine behavior. Add known source-busy, review-changed and over-budget rejection categories (or equally explicit nonterminal payloads); do not parse strings. Prewrite semantic rejection is known-safe `IntentRejected`; mutation/commit/response uncertainty remains conservative. Preserve the existing global wrapper: errors from postcommit document preparation cannot be reclassified as known prewrite rejection.

Parent loss, worker loss and a recovered checkpoint are separate facts. The source may retain a valid checkpoint while GUI-staged or parent-queued events were never captured. Keep finite GUI-local discard counts when known and parent loss count unavailable until actual telemetry exists; never derive event counts from sequence subtraction. Inspection cannot retroactively prove native quiescence or what was heard.

## Disjoint implementation ownership

1. Root freezes service DTOs, ledger representation/schema and budgets; migration tests retain schema-5 history and exact originals.
2. Recording owner adds only parameterized bounded/cancellable inspection where necessary, preserving owner handoff and low-level security boundaries. Engine owner adds bounded checkpoint scan adapters; neither gains normal-seal authority.
3. Session owner implements source-action persistence/admission and new commands on the existing worker, including local-stage error mapping. Store owner provides shared stage classification/guard helpers without broadening generic recovery semantics.
4. App owner extends the retained review surface with distinct performance cards, selected-checkpoint/unknown-tail disclosure and durable exact retries. Main retains draft/project/modal/uncertain-intent guards. UI performs no file access.
5. Independent reviewer owns adversarial service/storage/UI tests and acceptance review; coordinator alone runs gates, migrations, package and actual Mac actions. No parallel editor should share these production files.
