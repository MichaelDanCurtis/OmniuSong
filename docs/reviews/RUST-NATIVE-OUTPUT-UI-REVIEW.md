## Actionable finding: heartbeat can hide a device fault

**P2, fault-path acceptance blocker; not a blocker for the limited observed fault-free start/completion/Stop sequence.** In the reviewed binary's source, an internal heartbeat sends Status when no GUI request is pending (`transport.rs:396–413`), but only replies to a pending GUI request are forwarded (`transport.rs:427–431`). `matches_result` treats an error as a valid result (`transport.rs:175–177`). If that heartbeat encounters an output error, `Runtime::status` removes/stops the playback and returns the error once (`worker.rs:489–493`); the following status is idle. The GUI then sees idle while its playback phase remains Playing because only `playback_finished` clears it (`audio_ui.rs:308–316`). The cause is lost and session controls remain locked until explicit Stop. A normal device demonstration does not exercise this race.

The coordinator's narrow correction is now visible at `crates/omniusong-engine/src/transport.rs:432–437`: an unrequested heartbeat error returns its exact cause from the actor, retiring the owned child before the existing supervisor delivers its terminal event. That event remains behind any queued successful completion, without becoming an idle status. Two independent real-private-socket subprocess fixtures were added to `crates/omniusong-engine/tests/engine_process_review.rs`: successful user Stop queued before a one-shot heartbeat fault, and a heartbeat fault with no user request. The helper remains responsive and would answer idle if another request were admitted. Tests demand child retirement, exact terminal cause once at request ID zero, rejected new admission and no subsequent request. The coordinator's final focused run passes all five process tests, with zero failures and one ignored helper, in [heartbeat-process-tests-final.log](../../.runtime/rust-capture-recovery/heartbeat-process-tests-final.log), SHA-256 `16f601e15c4535b36acc8c49fd629bf96a9e61673461e801eda47be06e62012a`. Initial helper-only JSON-shape assertion failures are retained in the earlier log; the final fixture reads the actual nested Action representation. This resolves the finding at source/focused-regression level. The coordinator subsequently passed the [280-entry full source/build gate](../verification/rust-native-output-tests.json), formatting/Clippy and signature verification. The latest rebuilt binary still needs its actual reopen check; the prior 278-test gate and cb64 binary do not include this correction.

## Limited acceptance and required evidence labels

No additional concrete blocker was found for the coordinator's limited normal-output sequence. Prepared PCM completion is latched after rendering; the worker waits until a later callback clock reaches the predicted presentation endpoint before stopping (`realtime.rs:299–318`, `worker.rs:137–168,495–499`). Explicit Stop intentionally interrupts output and acknowledges only after the worker's stop path (`worker.rs:466–482,519–521`). A failed native pause retires the process instead of allowing another device session. These mechanisms support a bounded control/state observation, not measured audible completion or latency.

Record the actual device ID/name, displayed rate/channels, frame count, native process/binary identity and separate normal-completion/explicit-Stop observations. Actual hardware buffer size and latency are not in `EngineStatus` (`engine/src/lib.rs:43–50`), and its meter frames count rendered source frames. A `108000` total at 48 kHz describes 2.25 seconds of prepared content; it does not measure wall-clock playback or listener delivery. No microphone/input, physical listening, under-10-ms response, sustained recording, device-disconnect recovery or Windows acceptance follows. New post-fix binaries need their own identity record; do not transfer the cb64 UI observation to them silently.

## Proposed first live keys/pads boundary

This is a recommendation only; no new contract or production implementation is adopted here.

- Start an explicit audition session that creates one output stream, a fixed voice pool and queues before activation. Keep it mutually exclusive with the current solo capture. Use the procedural audition voice initially; reject unsupported expressive/instrument behavior visibly. Computer/on-screen keys and pads can exercise this boundary first; native CoreMIDI source connection and physical controller delivery need separate evidence. Starting audition must not open a microphone or create a recording.
- Give live events a separate bounded, sequenced ingress from the one-pending-request control RPC. That RPC is appropriate for Start/Stop/configuration but would reject fast key/pad bursts. Suggested initial configuration: at most 32 events and 16 KiB per wire batch, fixed ingress capacity, one producer per SPSC queue and bounded merging outside the audio callback. These are proposed ceilings, not throughput/latency measurements. Stop/Panic has an out-of-band atomic latch so full queues cannot strand a note-off.
- A fixed process-local packet needs session/output epoch, source handle and connection generation, monotonic sequence, observed host-clock ticks, and a tagged fixed-size payload. Keep note and voice handles separate from MIDI key, group and channel. Off callback, map string identities and validate/admit the packet; at the block boundary, convert it into existing `RealtimeEvent`/`RealtimeBatch` and `RealtimeControl` (`core/src/contracts.rs:1556–1739`). Do not serialize Rust enum layout as a wire ABI. The existing batch ceiling is 256 events/2,048 frames; split larger native buffers into bounded sub-blocks rather than assume the device uses that size.
- Begin with NoteOn/NoteOff, explicit velocity/release velocity and Panic, adding sustain and per-voice pitch/pressure/timbre through typed supported operations. Repeated same-pitch presses require distinct internal voices. Native ingress retains endpoint/generation, UMP group/channel and original words independently of the interpreted event. Preserve `CapturedEvent`'s host domain/epoch and optional alignment when later recording is enabled; do not invent calibrated audio coordinates from IPC arrival. MIDI 2 transport, MPE interpretation, project expression and Clip File export remain separate capabilities.
- A queue overflow, source disconnect, session epoch change or focus-loss policy must release voices without relying on a queued note-off. Report the loss and reject/reconcile later stale events. Test overlap, sustain release, note-off under saturation, panic priority, stale generations, variable callback sizes and exact no-allocation callback behavior before any physical-controller or latency claim. Audition alone must not mutate the saved project; eventual recording journals original events and publishes explicit reversible edits separately.
