# Governed projection archive integration: independent source review

The reviewed production design supports bounded source acceptance for the three new governed OSAR routes together. No unresolved source-authority blocker remains after the corrections described below. This verdict is conditional on the coordinator's execution and preservation gates; it is not a claim that the new real-performance fixtures, full workspace gate or native workflow have passed.

This review used repository Rust source and documentation only. I did not run Cargo, formatters, tests, SQL, applications, devices or audio, and did not read or hash the default catalog, protected source objects or installed application. Only this review document was written. The implementation reviewed comprises `archive_governed.rs`, `archive_metadata.rs`, the governed paths in `archive_copy.rs`, the reusable retained-closure/source modules, private plan/postimage helpers, catalog scope changes and the performance finalizers. Existing [archive design](RUST-PROJECTION-ARCHIVE-DESIGN.md), [postimage review](RUST-ARCHIVE-POSTIMAGES-REVIEW.md) and [outcome review](RUST-ARCHIVE-OUTCOMES-REVIEW.md) remain relevant at their stated scopes.

## Coherent route ownership

`export_archive_bounded_outcome`, `restore_archive_bounded_outcome` and `restore_archive_as_copy_bounded_outcome` accept the caller's `InspectionBudget` and perform actual export/installation/publication. They are not diagnostic-only wrappers. The original ordinary entry points remain separate with their previous limits and projection guards. Private metadata traversal can now decode projection-bearing snapshots, but does not grant authority to global load/check-reference, list, NativeReader or attachment consumers.

`CollectedClosure` and `RetainedWalk` retain a bounded namespace/layout-specific first-pass digest and role inventory. They grant no source permission. `RegisteredProjectionSources` owns readers at final registered paths without borrowing a catalog connection. `ProjectionProofs` borrows that owner, and one `RetainedValidator` borrows those proofs and retains an exact canonical binding memo. These lexical owners avoid a self-referential wrapper or a serializable proof token. `CatalogTransaction::prepare` permits constructing such non-catalog-borrowing owners while keeping the same live transaction; failed preparation follows the explicit abort path.

Every namespace gets its own first/second walk comparison. An acquired input is not compared byte-for-byte to a legitimately remapped copy plan. The same validator authenticates each encountered binding once, compares subsequent exact binding bytes, checks geometry on every appearance and resolves the encountered projection IDs to typed deterministic publication rows in the current namespace. The memo persists across namespaces; the namespace's encountered-ID set is cleared between walks. OSAR v1 explicitly lacks lineage tables; catalog and OSAR v2 still require them.

The reused walker covers current project, both sides of retained history, all operation results and all associated ancestor-proof results. It retains canonical operation identity, initial publication-result checks, stored forward transition reconstruction and complete selected lineage/mapping checks. A proof-only or pruned-history binding still requires a compatible live deterministic publication. Copy preserves original source/review/projection/lane/note identities while remapping the owned project and operation identities, recomputing exact request/result/mapping hashes and adding one copy proof. Private metadata consistency and a claimed review digest are never substitutes for actual original rederivation.

## Final-path authentication and publication ordering

Governed restores acquire and hash one private input, validate its fixed archive structure and hash columns, reconstruct chunk bytes with exact sequence/length/checksum/whole-object checks and collect the complete retained input. Reconstruction is structural; it opens no staged performance proof. Independent full-value planning and full thirteen-table baseline/overlay freezing precede live SQL effects and final-path object placement.

Installation verifies exact shared asset/registration metadata and raw final object hashes. A newly placed staged hard link is removed before the single-link source reader opens. Existing registered-but-missing objects refuse; arbitrary existing objects must pass the same byte and later semantic proof. Tentative registrations and placed objects confer no committed project authority. Only then does one source owner open the final content-addressed paths, authenticate each distinct required performance take and retain ordinary audio proof for audio-only roles. A mixed-role take receives the union of exact references with the stronger performance role. The implementation calls the held authentication constructor once per distinct performance take; this is not a claim of one physical read, nor an executed authentication-counter measurement.

The input, mapped plan and resulting live namespace are validated against the same proof owner and binding memo. The source set collected from the input bounds references in later namespaces; an unexpected source cannot be introduced through the plan. The final complete SQL postimage comparison, asset verification, exact registration check and held-file identity checks precede commit. Receipts are constructed before commit. The last observable test boundary is followed by another registration/file check, then the catalog scope's final checkpoint, hook detachment and sole COMMIT. No fallible validation or budget checkpoint follows successful commitment.

Export holds its live read snapshot while it authenticates sources, builds exact expected output rows, copies original bytes and validates the written namespace with the same proofs. Raw original copies are checked against the held registration and whole-file digest, with held identities rechecked afterward. The full output postimage and strict OSAR schema checks precede private COMMIT. Private output and live read cleanup/close finish before link publication, preventing a subsequent read-cleanup error from disguising a durable export as rollback. Output hashing and a final held-identity/governor fence precede the no-overwrite link. A late stop after link does not suppress required directory sync or erase successful durable completion. Existing attempted/link/commit phase and post-success cleanup-warning semantics remain intact.

Failed restore admission may retain diagnosed stages and unregistered content-addressed files after live SQL rollback. This is the previously selected retention policy, not an automatic adoption or cleanup mechanism. Input source paths are never reopened as authority after private acquisition. As before, acquired bytes are not proof that an externally changing pathname represented a single coherent historic source, and cooperative/private staging is not a hostile same-user filesystem sandbox.

## One governor and explicit SQL domains

The new routes share the caller's governor across acquisition, metadata and JSON work, private SQL, actual live SQL, structural I/O, source authentication, repeated semantic passes, remapping, ledger scans and final verification. The source set and proofs reject a different governor even when empty. No source, namespace or validation pass receives a fresh default budget. New paths enforce finite identity/path fields and prepay large payloads before requesting their materialization.

The compiled recording limits still include a 512 MiB **per-file** ceiling, 1 GiB cumulative work and cumulative rows/chunks/records/groups/VM ceilings. FileBytes records the maximum observed individual file, not a cumulative file-byte total. Archive acquisition and output hashing participate in the per-file limit. The ordinary archive's larger outer payload/metadata ceilings do not guarantee admission under this stricter governed family. The separate 512 MiB private-plan and combined expected/observed-ledger main-file ceilings, multi-credit row cap and field limits from the postimage stage remain. Temporary files, filesystem overhead and retained failure staging are not one aggregate disk allowance.

`PrivateSql` owns hooks only on disposable input/plan/output connections. It disables its callback before unregistering hooks, and its rollback observer disables further callback work during SQLite's automatic rollback. Normal errors discard those handles; no stopped private connection is reused for another operation. The disposable postimage spool separately records whether its own hook requested interruption. Its finalizer translates only a directly tagged PrivateOutput/Database SQLITE_INTERRUPT with that flag and an actual sticky stop; other private errors, source errors and unrelated interrupts survive. A failed operation poisons the ledger, and no stopped spool is reused. The real live connection alone uses `CatalogTransaction`, including explicit rollback cleanup, connection-usability reporting and commit fences. The new `prepare` method does not bypass required finalization. Tagged live SQLITE_INTERRUPT becomes a typed governor stop only when this scope's own hook requested it; private/source interrupts and main fatal/cleanup authority do not acquire a false domain through an outer wrapper.

Input SQLite, private-output SQLite and actual live-catalog SQLite are tagged at their respective boundaries. A private NOTADB cannot retire a healthy main catalog. `ArchiveFailure` keeps the operation error and a separately observed sticky governor stop, with the existing path, identity, phase and cleanup/retirement context. Governed store/performance/postimage finalizers now preserve an error they receive rather than replacing it with a later checkpoint failure. Already-stopped calls still refuse at entry, and successful work still checks the governor before becoming authority.

That retention guarantee has a precise lower-level limit: recording's shared `InspectionBudget::finish` compatibility remains unchanged and can replace an underlying reader error with a later stop before returning to these finalizers. The archive envelope cannot recover an error it never received. This review does not claim universal preservation of every physical source error. Likewise, fixed transaction controls, busy waits, filesystem operations and kernel stalls have no hard elapsed-time or responsiveness guarantee. Governing the statements does not qualify native responsiveness.

## Findings resolved during review

The initial governed export reused the legacy lineage-expectation pass, which requested large proof payloads before this separate pass had prepaid them. It now scans bounded proof identities/lengths, prepays, then requests each payload. Fixed lineage identity/hash rows receive their own row credit after the same held snapshot has been bounded and validated.

The original bounded copy history/operation planner and snapshot-hash checker selected lengths and large JSON payloads in the same statement, then charged before Rust `get()`. SQLite had already materialized the payload at `rows.next()`. Those scans now select fixed identity/type/length metadata first, prepay, and use bounded point reads afterward, with exact counts and length/hash checks. The existing `archive_metadata` and proof-reader helpers follow the same two-step discipline.

Bounded replay originally set `RecordedReplay` only after current owned-source validation succeeded. It now records that phase immediately after the exact canonical stored proof matches the requested operation/archive/project identity. Missing or replaced owned originals, later budget exhaustion or current semantic refusal therefore remain attached to a known recorded copy. Invalid or mismatched proof metadata is not marked as recorded. No failure falls through to acquisition, new identity allocation or another copy. The historical receipt includes a document and still requires current owned closure before a successful reply; this slice adds no unrelated compact-fact API.

The shared postimage finalizer initially replaced private physical failures with a late cancellation. It and the performance/inspection finalizers now retain received errors. Recursive live fatal/cleanup classification and the separate governor-stop envelope remain independent. The recording compatibility limitation above is intentionally explicit rather than hidden behind a broader guarantee.

A preliminary execution then exposed the complementary spool case: unconditional error preservation returned the spool's own raw INTERRUPT rather than its typed VM stop. `archive_postimage.rs::finish_spool` now uses the narrow own-hook mapping described above. The coordinator reports that the actual SQLITE_FULL-plus-late-cancellation regression passed; that result is reported evidence, not an execution by this reviewer.

The genuine strict OSAR-v1 route fixture exposed two accidental uses of the live catalog receipt reader, whose mandatory copy-admission collision check queries a table absent from v1. Both corrections are explicit layout branches: `archive_projection.rs::validate_links` separately prepays and reads the exact result from the same walked v1 snapshot, then calls shared typed initial-result validation; `projection_publication.rs::validate_forward_transition_archive_v1` binds the stored fixed-size hashes and revisions to the history afterimage and reconstructs the complete initial append. The full walk still checks the operation's raw bytes, canonical identity and revisions before authority is returned. Catalog and OSAR-v2 branches keep the existing receipt reader and collision guard. The format exception is private and cannot weaken active catalog admission.

## Test evidence and remaining qualification

The source contains new actual-route ordinary roundtrips, missing-input replay, VM/initial-stop and late-success cancellation cases, private corruption/live trigger failure and exact-plan rollback cases, plus reusable-walker tests for namespace, source-set and memo fences. These tests are inspected source, not executions by this reviewer. Directly constructed source-free metadata/memo cases qualify those algorithms only.

The new engine fixture inspected during this review uses the real device-free performance writer for v1/v2 records, recovers the original, creates an actual authenticated projection publication, adds a separate ordinary recovered audio take and preserves opaque fields. Its positive route case exercises governed export, identity restore and two copy generations, comparing original bytes/registrations, unchanged projection ownership and deterministic copied publication mappings. It is materially different from fabricating a review or memo. Additional actual-route cases cover hidden/pruned results, coherently rehashed false music, the initial muted lane, registration/asset trigger substitution, wrong existing objects, exact replay, cumulative limits and unchanged legacy refusal. A separate strict OSAR-v1 fixture removes the lineage tables and calls both governed restore entry points; v1 performance records alone do not establish that archive-format compatibility.

At this review's freeze, the coordinator has reported five governed store cases passing, including held final-path replacement at all three publication hooks with complete catalog preservation and an explicit retry. The first engine run reported ten passes and one strict OSAR-v1 failure; the two layout corrections above were inspected, and the corrected focused strict-v1 case subsequently passed for both performance profiles and both restore routes. These focused reports neither establish a final source-stable gate nor independently audited artifact totals. The complete frozen gate and packet remain the coordinator's evidence responsibility.

Before full route acceptance, execution evidence must establish genuine source negatives, final installed-path replacement/wrong-object refusal, rehashed retained/initial-result attacks, actual trigger/postimage rollback, governed cancellation/limits and same-connection reuse, exact replay and known-commit failure context, and late successful publication preservation. Existing legacy archive tests and the complete stable gate must also pass. No gate total or default-store preservation claim is made here.

These new backend routes do not activate legacy projection admission or guarded readers/list/attachments. A separate schema-3 inert OSRE regression, durable exact-request admission, native confirmation/restart/warning transport and the exact-binary musical editing/history/archive/audition workflow remain required. No package, device/input/output, listening, hard power-loss, long-capacity, Windows, AI inference or MIDI 2/MPE transport acceptance is implied. The complete Mac-first Rust workstation goal and full milestone 2 remain open.
