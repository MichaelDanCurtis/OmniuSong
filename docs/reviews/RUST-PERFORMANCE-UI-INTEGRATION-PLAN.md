# Recorded keys/pads: native UI integration plan

October 20, 2026. Read-only source planning for the next bounded milestone-2 packet. This is not implementation, runtime qualification, native-recording acceptance, or H09 acceptance. The coordinator is still resolving actual startup revision/deadline behavior. The installed `0978` application is the earlier arrangement UI; it does not contain these new worker controls. This review ran no Cargo, UI, device or catalog operations.

The next musician-facing workflow should be **Record keys/pads → wait for output readiness → perform → Finish recording or Stop → review retained source → explicitly attach audio**. It records the procedural output bus and original callback evidence. It opens no microphone or native input, including virtual input. Editable-note derivation remains a separate, later operation.

Existing `AudioUi::captured` creates a `SealedCapture { auto_attach: true }`, and `main::poll_audio` consumes `take_auto_publication`. **The new performance route must not call this path.** Keep its explicit source/attachment card separate, or first generalize it so the recorded-performance route never schedules automatic publication.

## Bounded state and actions

One retained performance card should own the exact Start intent, latest authenticated `PerformanceIdentity`/status, target-session identity captured by an explicit attachment choice, one immutable Finish command, reliable Stop ticket, and at most one unresolved attachment intent. Preserve the card when the engine port is dropped. Use existing bounded text/error rules; keep raw hashes/path/details in a collapsible evidence area. Do not accumulate status history, event payloads or repeated receipts in paint.

1. **Record keys/pads.** Resolve existing drafts through the main guarded pipeline; do not silently save. Allocate the stable Start ID once and call `LiveUi::begin` once to obtain the original GUI clock. Submit `StartPerformance` with the selected output. Show “Preparing recording” and retain the attempted ID; a busy or failed submission does not mint another ID automatically. Computer/pointer/pad routing remains closed.
2. **Asynchronous Ready.** A prompt `Starting` completion is not readiness. Poll `try_performance_update` as well as ordinary replies and `try_poll_update`. Only the first authenticated Ready activates `LiveUi`; apply any newer cumulative fault/progress before enabling controls. Later heartbeats update observations, never call `activate` again, reset note handles, rewind sequence, rotate the clock, or restore an earlier Panic generation. Show the actual output name, rate, channels and `native_sample_format`.
3. **Record.** Reuse current key/pad, repeated-voice, sustain and accessible Pulse behavior. Display callback-rendered frames separately from writer-durable frames. The six original streams are `audio`, `gui-1` through `gui-4`, and `control`; GUI time is an original observation, not calibrated musical or device alignment. Lease renewal remains GUI-issued; status polling does not renew it.
4. **Finish recording.** First close new local human input and lease generation, then flush the finite staged GUI events once with their original fields before submitting the stable Finish command. If that flush fails, retain the failure/drop evidence and interrupt; do not retry an unknown subset. Do not call existing `LiveUi::cleanup`: it clears staged events and requests Panic. Held/sustained notes must stay held in the original event stream; the callback-owned hard cut explains their termination. The UI supplies Start ID/current scope/Finish ID, never an accepted-sequence fence or cut frame. A pending Panic must resolve before a fresh Finish choice; no automatic scope rebasing.
5. **Finishing/sealing.** Keep the note gate closed and show progress without blocking the serialized UI. `Finishing`, callback `TapFinish`, native-retirement observations and `Sealing` are distinct. `FinishedCut` is not a sealed take. A timeout, terminal error or `SealUncertain` retains the exact Finish request and stage; only an explicit exact Finish retry may retry sealing. Polling Status must never do so.
6. **Stop.** Always use queue-independent `request_stop`, including during Starting, Finish, storage busy state or a modal. Stop preempts unsent Finish and leaves interrupted evidence unless the actual seal transaction already won. Keep the ticket until the exact cumulative acknowledgment or typed actor retirement. A `Stopping` performance reply, zero voices, `native.complete()` or an enabled button is not a Stop acknowledgment. New Start stays disabled. A confirmed normal finish can request reliable session release after the sealed result as part of its cleanup, but that request must still wait for the real acknowledgment; it never publishes audio.
7. **Source ready.** For a checked normal `Sealed` result, retain its `CapturedTake` and show “Original saved locally · not attached”. For Interrupted/Failed/SealUncertain, retain path/take/descriptor, first error and complete/durable counters, with unknown-tail wording. Never show “nothing was recorded” when a prefix may exist. Reopening an existing stage is inspection/recovery-only, never recording resume.
8. **Attach audio explicitly.** The musician chooses the retained audio and target session, then presses “Attach recording to session”. Create one stable `TakePublication` referencing stream `audio`, the actual sealed manifest, source frames `0..frames`, actual sample rate, placement frame zero, `fades: None`, `edit_source: None`, and fresh track/clip IDs. This v2 profile starts at source frame zero; format-aware recovered attachment must instead use its proven selected bounds, not a guessed duration. Label frame-zero placement as uncalibrated. Use `Command::AttachCapture` after Save/Discard/Cancel; Finish itself does not add a track or save drafts.

Attachment completion installs `Reply::Document` through the normal app path. A `RevisionConflict` is a known rejected publication and must retain the exact old intent/evidence; it may already have ingested the original. Offer suspend/review/release-then-new-choice using the existing recovery pattern. A Backend/Disconnected/Protocol/StorageUnavailable result with uncertain outcome must keep the original operation ID and complete request for exact retry. Never change expected revision, track ID, source or operation ID in place to “fix” a failed request.

## Required missing boundaries

**Parent events not captured.** There is currently no finite parent-discard receipt in `EngineUpdate` or `PerformanceStatus`. `LiveQueued` proves only parent enqueue; worker accepted/applied watermarks and worker rejected/overflow counts cannot supply this count. `LiveUi::clear_local` drops up to 32 staged events without a count. The actor's urgent Stop/Panic path drains up to 16 parent batches without recording their event counts/dispositions. One wire batch can also have an unknown acceptance outcome. Generation/Panic resets prevent safely subtracting arbitrary watermarks.

Before labeling a performance complete in the UI, root must freeze a bounded disclosure primitive: per-Start/scope checked cumulative counts for known GUI-staged losses and known parent-queued batches/events discarded before worker admission, plus the identity/count bound of any one in-flight unknown batch. Keep those categories distinct from worker-accepted but not callback-retained originals. Count actual discarded `batch.len` only after bounded shape validation; never infer event count from sequence distance or assume empty lease batches contain events. Preserve the first reason and surface counter exhaustion as unknown/fault. This is off-callback telemetry, not synthetic events inserted into the original six streams. Until it exists, display an explicit unavailable/unknown parent-loss count, not zero or “all key/pad events saved”.

**Durable retained intent.** Existing `AudioUi`, `LiveUi` and recovery attachment retries are in-memory. The project operation ledger makes committed attachments durable; it does not persist a not-yet-submitted UI choice or recover its ID after app exit. The next packet must preserve exact intent/stage identity across worker retirement and draft conflict immediately, and must not describe that RAM card as restart-durable. For a restart-durable choice, add a bounded, versioned session-worker-owned intent receipt before the corresponding side effect: Start ID/full GUI clock/output, later actual stage/take/descriptor, immutable Finish ID/scope, and an attachment operation/target/revision/track/clip/source tuple once chosen. Write it outside immutable journal originals, with checked replacement/receipt identity and explicit committed/uncertain state. Extend the existing `SessionService`; do not introduce UI filesystem writes or a second persistence service. Root must freeze the exact receipt/API and distinguish it from cross-worker Start replay: an existing stage still cannot resume.

**Performance discovery/recovery.** `captures.rs::canonical_stage` and session `validate_stage_id` currently require hyphenated UUIDs. `PerformanceStart::directory_name()` produces 32 lowercase hexadecimal characters, so current `ScanCaptures` lists these directories as Invalid. Generic `recover_capture` also deliberately refuses performance markers. A bounded service extension must recognize only the exact performance-owned naming/profile, preserve root confinement/live ownership/symlink and hardlink guards, and run `inspect_performance`/`recover_performance` off UI. Do not broaden generic path validation to arbitrary strings. Normal sealed sources may be explicitly attached through the existing service. Interrupted sources require reviewed format-aware checkpoint recovery; all later/bad/unselected rows remain in the original and whole owned backup. Neither generic recovery nor `CompletePrefix` is native normal-seal authority.

## UI quality and acceptance

H09 requires a beautiful, crisp, easy-to-use and highly functional native UI. Put one obvious **Record keys/pads**, one **Finish recording**, and always-available **Stop** near the existing keyboard/pads. Use a readable state badge and a restrained progress row: preparing, recording, finishing, saving original, retained/unknown, ready to attach, attached. Keep audition explicitly labeled “not recorded”. Hide the unrelated input selector in this output-only workflow. Use real contrast/focus styling, accessible names, clear enabled/disabled reasons and stable IDs; source paths and hashes should not dominate the musician's primary controls. Retained failure/attachment cards must remain visible without covering Stop or the instrument. This visual/workflow quality needs an actual Mac review, not just successful AX labels.

Required headless/injected-worker cases:

- Delayed or failed Ready; newer fault before older completion; mismatched Start/clock/output/worker/stage/descriptor; exactly-once activation across repeated status and healthy Panic.
- Computer/pointer/pads, repeated same-pitch voices, sustain, velocity zero/full 16-bit, original GUI ticks, and no invented NoteOff on Finish. All 16 parent batches precede Finish; bounded local flush succeeds once or exposes interruption/loss.
- Stop during Start/Finish/sealing, full normal control credit, delayed exact Stop ACK, stale completions, receiver/actor retirement and terminal cause retention. No new Start or automatic audio retry while quiescence is unproven.
- Explicit attachment only: sealing never emits a storage command. Save/Discard/Cancel across metadata/note/clip drafts; target navigation; revision conflict; uncertain lost reply; exact retry after staged path disappears but owned ingestion/receipt exists; release/new choice gets new IDs without rewriting the old request.
- Pending source and immutable intents survive worker failure and conflict; restart tests authenticate the proposed persisted intent receipt. Generic capture guards remain strict; performance-aware recovery rejects stale original-row/checkpoint review and never resumes recording.
- Undo/Redo/reopen/complete archive restore preserve the full six-stream journal, PCM, local event envelopes, Finish/checkpoints and unknown metadata. Attachment selects audio for arrangement playback without dropping the other original streams. No editable notes are fabricated.

Then the coordinator must qualify the same newly built bundle with actual Mac output only: real keys/pads → asynchronous Ready → Finish → retained normal source → explicit attach → Undo/Redo/reopen/archive closure; separately Stop/interruption → performance-aware review/recovery → explicit attachment. Exercise startup failure/retirement, draft conflict, keyboard/text/focus cleanup, close choices, contrast and display scaling. Retain screenshots/AX, exact build/source and original hashes and backend receipts. Do not call the older `0978` walkthrough evidence for this workflow. No native input, listening/physical latency, long-run stability, MIDI/UMP input, AI inference, plugins, Windows or final-song acceptance is implied.
