## Held original authority

[`AuthenticatedPerformance`](../../crates/omniusong-performance/src/projection.rs) has private fields and borrows an existing bounded `SealedJournal`. It exposes no constructor from a supplied inspection, no mutable inspection/source setter, and no `Clone` or deserialization implementation. `open` obtains the reader's governor, decodes the descriptor/profile, performs the existing full snapshot and performance semantic inspection, and binds the complete selected checkpoint/index to the sealed manifest. It retains exact take, manifest, descriptor, original-row, reviewed-journal and checkpoint/index identities. Final source identity is checked before returning the context.

`project` validates the request, compares the entire source pin, checks the selected frame extent, and checks the held reader before interpreting. Each interpretation rereads and rederives the authenticated control records through the existing lifecycle. The context reuses its completed inspection; it does not replace subsequent derivation with a cached review or accept a claimed review digest as proof. The final identity check follows lifecycle output and digest construction. `source_pin()` exposes retained identity metadata, not a fresh availability or publication proof.

The same reader governor remains cumulative across context construction, projections, binding construction and held validation. There is no reset or new default budget inside those methods. Full inspection is not repeated for each call to `project`; control reads, decoding, record visits, allocation, comparison and serialization still consume work on each interpretation. This does not promise a single physical pass over the source, zero rereads, or measured latency/RSS. In particular, an unchanged file-size usage counter is not evidence of zero further I/O.

The original free `project_sealed_performance_bounded` API remains available and checks request shape before creating the context. The extracted control walk and lifecycle remain the same, including source positions, original record locations, cut/omission interpretation, exact timing conversion and the review digest convention. Its output representation remains compatible; the extra conservative validation/identity charges mean usage counters and the precise point of budget exhaustion need not be identical to the earlier wrapper.

## Encoding is deliberately weaker than source authentication

[`projection/binding.rs`](../../crates/omniusong-performance/src/projection/binding.rs) separates `check_retained_binding_encoding_bounded` from held `validate_binding`. The encoding checker returns only `Result<()>`; it returns no source-free authentication capability. It bounds the retained input and lane/note cardinality before full typed decoding, checks the core envelope, rejects alternate typed JSON serialization, checks the existing domain-separated review digest with its digest field emptied, and checks take/manifest/audio-stream agreement.

The checker also validates selected voice identities and their digests, result/omission cardinality and accounting, sorted unique nonempty source/instrument groups, complete group membership and original order, original values, and deterministic document-note IDs. Canonical comparison includes all serialized fields, so unknown/discarded fields, whitespace/layout changes and alternate encodings cannot silently become retained canonical bytes. Structural or internal consistency is not proof that any field describes a real performance.

Held `validate_binding` first performs those encoding checks, then derives the requested interpretation from the actual held original and compares the complete typed review. This includes source pins, note values and identities, counts, omission/cut details, disclosure fields and record locations, not merely the stored digest. It checks source identity again before success. The independent tests intentionally construct false music, source pins and voice identities with coherent replacement hashes and bindings: encoding consistency is expected to pass for these internally consistent records, while held validation must refuse. This is the essential authority boundary.

`build_binding` accepts a request, exact reviewed digest and lane choices, not caller-supplied notes or note IDs. It rederives once, compares the reviewed digest, requires exactly every nonempty `(source, original patch)` group, constructs complete original bindings in derived order, serializes the exact review and checks final source identity. Display names affect only initial presentation; they are not substituted for original instrument/source grouping.

## Stable IDs, bounds and cancellation

Document-note IDs use the exact `OmniuSong.performance-projection-document-note.v1\0` domain, followed by the projection ID and original voice-identity SHA-256 ASCII. Each field has its own unsigned 64-bit little-endian byte-length prefix. The output is `pn-` plus 64 lowercase hexadecimal characters. This prevents concatenation ambiguity and gives separate explicit projections distinct note namespaces without depending on destination track or project identity. Independent test code reproduces the byte framing without calling the production helper.

Source handles remain 1–4; choices are sorted by source and then Keys, Bass, Drums, Pad. There are at most 16 nonempty groups and 20,000 retained selected note/omission rows. The binding and core registry maintain their separate original-note and aggregate registry limits. Native identifiers are bounded before use; lane names require at most 640 UTF-8 bytes and 160 Unicode characters, nonblank content and no control characters. Retained review bytes remain capped at 8 MiB, and final whole-document limits still include escaping, note duplication and unrelated metadata.

The bounded writers charge before buffer growth/copy or hashing, and canonical comparison streams against retained bytes rather than allocating another canonical JSON string. Decoding and bounded tree/set work are prepaid. Checked additions protect input totals and offsets; remaining ordinary arithmetic is constrained by already checked 16-group/20,000-row/input bounds. Group indexing occurs only after validating source handles. No file/work ceiling is raised: the existing default 512 MiB per-file and 1 GiB cumulative work ceilings still apply, together with the reader's row/record/chunk/group/VM limits. A structurally permitted large review or several interpretations may exhaust work and refuse.

Public bounded methods check the sticky governor before work and again before return. Serializer errors cannot replace a latched cancellation/work stop. Final identity checks after derivation/canonical output protect against path replacement during the operation. These are cooperative bounded operations; the code does not claim that every byte of a JSON decode or operating-system call is independently interruptible. Successful return remains a point-in-time read proof, not a durable lease for a later unrelated commit.

One review finding was corrected: the core candidate's display-name validation originally scanned `trim()`/character count before testing its byte limit. The current implementation checks the 640-byte limit first. No remaining serious finding was identified in this slice.

## Pure complete candidate

[`ProjectDocument::append_performance_projection`](../../crates/omniusong-core/src/performance_projection/publication.rs) is explicitly a pure constructor. Core can validate structural shape and construct a document from a caller-built binding; that creates no original authentication or permission to activate the result. Future store code must independently obtain held-source authority.

The constructor requires the exact ordered complete lane choices, refuses existing or previously reserved track/note identities and duplicate projection IDs, and checks the 64-track capacity. Schema 1/2 promotion requires explicit permission and refuses every same-named opaque registry key. It appends one entry and all ordinary note lanes in one returned candidate. Each new lane is muted, unarmed and unlocked; values retain exact 16-bit velocity including zero, and no expression performance is invented. The original document is borrowed, existing tracks and opaque values remain exact, and project identity/revision are unchanged. No sequence of independently applied AddNote operations is used.

Preserve-loop does not trim or move notes. Extend-loop rounds the largest note end upward to complete four-beat 960-PPQ bars, never shrinks the current loop and enforces the native duration bound. Explicit projection-schema permission controls promotion; this constructor's extension to an already schema-3 candidate does not use the older native-schema permission inside `NoteTimelinePolicy` to grant projection authority. Final `ProjectDocument::from_value` rechecks the complete document, registry reservations and serialized metadata bound before any candidate is returned.

Later ordinary note, tempo, instrument/name and deletion operations do not rewrite the original binding. Retained ownership survives removal of every derived lane; its take reference remains discoverable. The pure constructor does not enforce a fresh target revision or current-tempo review correlation: those are required at future typed store/session admission, not evidence that a historical binding is invalid after editing.

## Inspected tests and explicit limits

The inspected additions comprise seven binding unit cases, six pure core candidate cases and nine independent engine integration cases. I did not execute them. The engine cases use actual device-free renderer/tap/writer records followed by recovered sealed v1/v2 sources, not normal native seals or a device lifetime. They exercise deterministic bytes and groups, full false-record recomputation, exact current-edit/deletion ownership, cumulative work across repeated derivations, sticky cancellation/limits, unbounded-reader refusal, and Unix replacement by a different file containing identical bytes. They compare original source files after closing the held readers. Unit cases separately exercise canonical JSON, complete bijection/order, ID framing, naming/cardinality, streaming serialization and whole-candidate preservation/refusal.

After the initial source review, the coordinator's actual run exposed a fixture setup error missed by that static review. All nine new engine cases stopped with `Faulted` before reaching binding assertions: the synthetic source began note/voice counters at 11, 21 and 31, while the native renderer requires each source's counters to start at 1 and advance contiguously. I inspected the correction in [`binding_review.rs`](../../crates/omniusong-engine/tests/performance_projection_review/binding_review.rs) against the renderer check: source 1 now uses note/voice 1 then 2, sources 2 and 3 each start at 1, and the two explicit Note Off references match source 1 voices 1 and 2. The fixture's source grouping, ticks, pitches, velocities, Pulse/Finish behavior and binding assertions remain in place. Production admission was not weakened to accommodate the fixture.
