# Performance source recovery, reconciliation and complete evidence

October 22, 2026. **Architecture proposal only. No production recovery implementation or acceptance is asserted.** This packet is independent of the optimized app's current native qualification. It edits no Rust, catalog, source journal or installed bundle, and requires no device, model, download or input stream. The coordinator owns schema/dependency/API decisions, integration, Cargo and native/UI qualification.

Read with [the active implementation plan](../IMPLEMENTATION-PLAN.md), [the earlier recovery service plan](RUST-PERFORMANCE-RECOVERY-SERVICE-PLAN.md), [the recording UI plan](RUST-PERFORMANCE-UI-INTEGRATION-PLAN.md), [bounded inspection](../contracts/BOUNDED-PERFORMANCE-INSPECTION.md), [performance UI](../contracts/NATIVE-PERFORMANCE-UI.md) and [the checkpoint contract](../contracts/NATIVE-PERFORMANCE-WRITER.md). Older plans describe some APIs as missing which are now implemented; the source inventory below governs this proposal. The broader recording/editing, long-session and product goals remain unfinished.

## Authority and preservation rules

The musician-facing order is **Scan → Inspect → explicitly recover the reviewed checkpoint on a copy → review the recovered result → choose a song/placement → explicitly attach**. An already authenticated normal original skips recovery and still needs its own explicit attachment choice. Scan, inspection, cancellation, restart reconciliation and opening a card cause no source or song mutation.

1. A persisted Start or Finish records a request. It does not prove the request reached the worker, the callback cut happened, callbacks retired, a transaction committed, or all parent-enqueued input was captured. Do not reconstruct a native permit or normally seal an old stage from requests, counters, an inspection budget, a checkpoint or a guessed manifest.
2. A stored normal manifest is accepted only after actual descriptor, full-original, generic and six-stream semantic authentication. It is evidence of an existing storage result, never permission to create a normal result. No source-recovery service calls `complete_prefix`/`seal_complete_prefix` or fabricates `NativeSealPermit`.
3. Preserve all PCM, all four GUI streams and control records, unknown metadata/columns, exact storage types, rejected/discarded raw records, incomplete callbacks, valid unselected chunks and corrupt tails. Never rebuild a source by iterating only the verified prefix or appending decoded chunks into a new journal. That loses physical evidence and can omit opaque fields, schema, sequence metadata or damaged rows.
4. Recovery selects the **last fully verified performance checkpoint before the first failure**, as the current semantic scanner does. The initial UI does not accept an arbitrary user frame/range or a later plausible checkpoint. No checkpoint/positive selected audio means no playable recovery; the evidence remains inspectable/exportable. A typed budget or cancellation refusal returns no actionable partial review.
5. Recovered mode and `unknown_tail=true` survive attachment, restart and export even if every retained row is currently readable or a stored Finish exists. A recovered result never becomes normal. Preserve capture fault/pending-cause fields and unknown parent/in-flight input; do not replace unknown counts with zero.
6. Keep source errors local. Stage `CORRUPT`/`NOTADB`/IO errors, busy owner, changed review, resource refusal and cancellation cannot become a main-catalog `StorageUnavailable` quarantine. Actual catalog faults during ledger/attachment publication retain the existing fatal storage handling. Error mapping follows which database/file operation failed, not only its SQLite error code.
7. Never delete, rename away or auto-recover `take.sqlite3-journal`, `-wal` or `-shm` to make a reader succeed. Presence of any such sidecar rejects semantic inspection and recovery **before SQLite opens the source**. A header or apparent journal coldness grants no cleanup authority. Retain prior failed stages exactly.

## Choice: recover on a private full-byte copy

The existing low-level in-place operation is valuable but not selected for this UI packet. `CaptureReader::recover_prefix` continuously transfers its owner to `Journal::open_owned`, adds interruption/index/manifest/state metadata and checks unchanged original-row identity. That preserves logical originals, but changes the source database bytes and can leave a rollback sidecar on failure. It would require explicit wording that the failed stage's physical evidence is being changed, plus a prior exact evidence snapshot.

**Recommend copy recovery as the default and only initial performance-UI mode.** Keep the original capture directory untouched. Retain two role-distinct artifacts under a private action-owned namespace: an immutable byte-identical evidence image, and a recovery working copy initially made from that image. The recovery copy alone gains derived interruption/manifest metadata. The extra storage is intentional and must be checked and bounded. Do not silently fall back to in-place mutation when capacity is unavailable.

The source descriptor/take identity is not rewritten for the copy. The copy's action/artifact identity is distinct from its original take identity. Existing `native_takes` uniqueness still applies: if a different manifest is already registered for that take, report a source-identity conflict. Preserve both artifacts, but do not silently replace the registered object, reinterpret a linked normal result, or edit the take descriptor to manufacture a new identity. Supporting multiple attached interpretations of one original would require a separate shared storage/project contract.

Proposed artifact topology, with names frozen by the coordinator rather than supplied by UI:

```text
captures/<original-stage>/...                    unchanged original evidence
source-actions/<action-id>/evidence/take.sqlite3 immutable exact database image
source-actions/<action-id>/recovery/take.sqlite3 derived recovered working copy
source-actions/<action-id>/receipts/...           bounded immutable receipts
```

These action directories are outside `captures`; do not make discovery mistake a working copy for a new recording. Each new file is exclusively created; exact retry authenticates an existing expected artifact instead of truncating, overwriting or creating another recovery ID. Partial files remain identified as incomplete evidence. Final-name publication requires the copy/hash/durability checks; a mere pathname is not completion.

Ordered source-copy protocol:

1. Persist the full reviewed-source reference, exact recovery operation, selected checkpoint/index, destination artifact identities and action version **before any filesystem write**. The returned ledger receipt must match the exact request; uncertain persistence cannot start recovery.
2. Reopen the exact root-derived source with the bounded read-only reader, acquire its existing owner without creating it, recheck confinement/single-link/ordinary-file/header/all-sidecar conditions, and recompute generic plus semantic review. Match the stored review's stable source facts. Hold source ownership through copying and the final source comparison. No UI dialog waits while this owner is held.
3. Copy the complete database as bounded raw bytes to the new evidence artifact, including free/unselected pages. Hash while copying; verify byte count and physical SHA against the reviewed source, and reverify the source file identity/content and stage entry set afterward. Check the opened file identity as well as canonical paths; do not resolve a replaced pathname to a different source. Sync the completed file and its containing directory before recording evidence completion. This is byte preservation under the supported trusted-parent/owner model, not a claim of hardware power-loss durability.
4. Create a separate complete working copy from that immutable evidence image, authenticate equality and create its action-owned lock as part of this explicit operation. The image and source remain read-only. SQLite backup/append-group reconstruction is not the evidence-copy mechanism because physical byte identity is required here.
5. Open only the working copy through a **new explicitly admitted bounded recovery path**, keeping owner continuity into mutation. Recompute complete original-row identity and semantic selection; match the evidence image/source review before any derived write. A private admission object may bind action/copy/review/budget, but it is a storage mutation capability only and must never be called or treated as a native seal permit.
6. Invoke performance-aware selected-prefix recovered finalization, preserving strict source/operation/checkpoint identity and pre/post-write all-original authentication. Keep one cumulative governor across copy verification, generic/semantic rereads and transaction checks. No reset to an unbounded API and no resetting limits between phases. Parameterize lower-layer recovery checks as needed; do not remove `budget.is_none()` from the existing read-only reader as a shortcut.
7. Authenticate the recovered manifest and selected bounds, verify unchanged original-row digest and unchanged source/evidence image, then append the exact outcome receipt. A manifest committed before a lost outcome-ledger reply is reconciled from the same action's copy and operation; it is not a reason for a new operation or another copy. Recovery completion does not ingest or attach.

On exact retry, reconcile the persisted action's existing image/copy/result **before requiring the original capture path again**. A fully authenticated image matching the stored physical source digest can preserve the admitted source when its original drive/path is unavailable; report that availability separately. A recovered copy with the exact derived operation, original-row identity and selected checkpoint replays its existing manifest without mutation. An image alone may support an explicit continuation of the same stored action, but merely listing/reconciling it does not continue automatically.

A partial raw copy may be retained under a bounded attempt identity and retried into another exclusively created partial artifact only when the ledger/evidence proves no recovery mutation was submitted. Never truncate the old partial. If mutation might have started, do not bypass uncertainty by making another pristine copy and normally/recovered sealing it again: that can create a different random manifest for the same operation. Authenticate/replay the one admitted recovery artifact or remain uncertain. Any sidecar on that working copy receives the same refusal policy as a capture-stage sidecar; this packet does not automatically recover or delete it. A later explicit repair/salvage workflow is outside this plan.

No blanket filesystem mutation cancellation is added to `cancel_source_inspection`. That existing API stays read-only and correlated. A future recovery cancellation is its own typed request: before derived mutation it abandons with a retained partial/copy result; after mutation may have started it records uncertain outcome until reconciled. It cannot promise rollback from a UI click. Work limits and cooperative cancellation must reach SQLite as sticky typed errors; blocked filesystem calls still retain owner/credit and cannot be safely killed by dropping a thread.

## Durable source-action ledger

Use a new bounded append-only ledger instead of changing old `PerformanceIntent` v1 histories. All schema/version and migration decisions require coordinator agreement. Proposed names below are interfaces to freeze, not implemented APIs.

Separate immutable **review blobs** from compact action revisions. The current review already has a 64 KiB ceiling, so nesting it with an envelope into another 64 KiB payload is not safe. Retain its exact serialized bytes/hash in an immutable review table/blob; action revisions reference that identity. A proposed first budget is 32 actions × 16 revisions × 16 KiB, plus at most one 64 KiB admitted review per action (10 MiB payload ceiling before database overhead), with separate explicit byte limits for result/evidence manifests. No eviction or silent truncation at capacity. Root may choose a smaller proven representation; maximum-shaped fixtures must precede the freeze.

An action binds:

- Version, fresh action ID, revision and exact current payload SHA.
- Origin: either a verified `(recording-intent ID, historical revision, payload SHA)` plus exact stage, or explicit discovered/imported source identity. An orphan gets no invented Start/output-device/project/Finish fields.
- Immutable admitted review reference; stable original identity (stage/take, descriptor SHA, all-original-row SHA, physical image SHA/size), semantic profile/checkpoint/index/six prefixes, observed manifest/mode and fault/unknown-tail evidence.
- Exact optional recovery choice: operation ID, recovery mode `copy`, destination artifact IDs, resource-policy version and reviewed selection. It is absent for an existing authenticated normal source.
- Append-only observed outcomes referencing image/copy/result receipts; no invented success inferred merely from a submitted request.
- Separate optional attachment choice with the complete `TakePublication` and result/evidence identity; no target project is required merely to inspect or recover.
- Keep-local/disposition and explicit supersession links. Suspending a card is distinct from resolving its uncertain operation.

Validate every retained payload, hash, contiguous revision and transition. Exact **current** payload replay precedes CAS; an older payload cannot replace later history. Optional immutable choices become present once, then cannot change. Source/selection/operation/target/revision/track/clip changes create a new explicit action linked to the retained predecessor only after its outcome is known sufficiently to permit a new choice. Do not forge new history into the original recording-intent rows.

The existing `PerformanceSourceReview.review_sha256` includes usage counters. Preserve the complete original review bytes/hash for audit, but define a versioned **stable source-admission projection** for fresh comparison: physical source image, descriptor/all-original identity, state/manifest, full semantic facts and exact checkpoint selection. Runtime usage is diagnostic and may vary with implementation/SQL preparation; it must not become a false source-change signal or be silently stripped from the stored review. No caller supplies a supposedly matching hash without recomputation.

The image, recovery transaction and catalog ledger are not one atomic transaction. Define explicit states such as `Prepared`, `ImageVerified`, `RecoverySubmitted`, `Recovered`, `AttachmentPrepared`, `Attached`, `KnownRejected`, `OutcomeUnknown`, and a separate `kept_local` flag. A crash at any boundary is handled by read-only reconciliation of the persisted exact identities. Missing/incomplete artifacts do not silently advance state. Source faults while reconciling are local; catalog integrity failures still fail closed.

## Proposed service and UI contracts

| Command / action | Required behavior |
| --- | --- |
| Existing `ScanPerformanceSources` | Directory-only scan, explicit truncated/skipped counts, no auto-inspection. Combine display with known exact ledger IDs without fabricating source state. |
| Existing `InspectPerformanceSource { stage_id }` | Bounded read-only review. UI keeps last reviewed evidence visibly distinct from fresh state. Cancel only the exact pending request, retaining service credit through completion. |
| `ReconcilePerformanceIntent { id, revision }` | Read-only relationship between exact persisted requests, historical attachment receipt and observed source; never submit Start/Finish/Recover/Attach. |
| `SavePerformanceSourceAction { expected_revision, action }` | Persist exact review/choice references before side effects; load and validate stored review bytes. Return exact correlated receipt. |
| `ListPerformanceSourceActions` | Bounded metadata/history validation only; do not open every source at restart. |
| `RecoverPerformanceSourceCopy { action_id, revision }` | Load the exact stored choice; execute the checked copy protocol; no replacement request/path/checkpoint accepted from UI. |
| `ReconcilePerformanceSourceAction { action_id, revision }` | Read-only observed copy/manifest/publication result, including committed-but-unacknowledged outcomes. No automatic continuation into mutation. |
| `AttachPerformanceSource { action_id, revision }` | Execute only the exact stored separate publication after mode-specific admission; preserve committed-operation-first replay and owned-original preference. |
| `KeepPerformanceSourceLocally { action_id, revision }` | Append a disposition without deleting/moving original evidence or pretending an uncertain operation is canceled. |
| `ExportPerformanceEvidence { stored_export_id, revision }` | Explicit exact source set/destination/closure export; never treat standard per-song archive success as evidence that unassigned stages were included. |

Every reply matches service generation, request ID/kind, action/revision and source/result identities. Read-only commands have known no-write failures; mutation commands retain conservative uncertainty after the first possible side effect. `SourceBusy`, `SourceUnavailable`, `InspectionLimit`, `InspectionCancelled`, `ReviewChanged`, `ArtifactConflict` and `SourceIdentityConflict` remain source/action-local. Do not parse messages to decide whether a project publication occurred.

The UI separates “request retained”, “source inspected”, “checkpoint recoverable”, “recovered copy saved” and “attached”. Put frame duration/rate, selected checkpoint, unknown tail/fault and primary action first; hashes/path/history live in expandable details. Source review must not cover Stop or require a hidden modal. Dirty metadata/note/clip drafts use existing Save/Discard/Cancel before choosing the target revision. Recovery itself neither saves drafts nor changes the active song. Repeated clicks coalesce to the same persisted action and no second worker is created while the service owns the first request.

## Restart reconciliation of requests and observed results

First validate recording-intent history. If an attachment exists, query `performance_attachment_committed` before opening a staging path. It proves exact historical publication only; show current source availability and later project changes separately. A missing source must not cause a second attachment, reinstall an old project snapshot or erase the committed receipt.

Then inspect one explicitly selected source through the bounded service and classify:

| Retained requests / observed source | Permitted conclusion and next explicit choice |
| --- | --- |
| Start exists, source missing/unreadable/busy/sidecar-bearing | Request retained; actual source/operation result unavailable. Keep local or raw evidence export where safe. Never retry Start into that identity or initialize a replacement stage. |
| Source is Recording/Interrupted, no normal manifest, last complete checkpoint exists | Offer explicit recovered copy of the reviewed selection. A stored Finish does not authorize normal sealing; unknown tail remains. |
| Source has no complete checkpoint | Evidence retained; no playable recovery. Export raw evidence; never synthesize a matching End/checkpoint. |
| Authenticated normal v2 source, exact linked Start/take/GUI clock/descriptor and exact persisted Finish ID/scope match semantic cut | Observe the existing normal result; offer a new explicit source-action attachment or exact pending-publication replay. No native action is issued. Accepted watermark/cut come from authenticated original records, never invented from the Finish request. |
| Normal source but a linked persisted identity/Finish contradicts it | Conflict. Preserve both; no orphan-adoption escape hatch and no “repair” of the request to match the source. |
| Authenticated normal v2 orphan, or missing persisted Finish without a contradictory retained request | A separately labeled explicit adoption action may attach the authenticated existing normal original, after full complete fault-free semantics. Retain “original request history unavailable”; do not insert a manufactured Finish into old intent history or claim observed native retirement. Root must freeze this adoption rule. |
| Recovered manifest matches this exact source-action operation/selection and all originals | Reconcile recovered outcome; retain unknown tail. Offer separate attachment or exact pending publication. |
| Recovered manifest lacks matching source-action proof | Inspect/export only in the initial packet. A later explicit adoption policy must independently authenticate its full original and selected checkpoint; no automatic action-ledger invention. |
| Authenticated normal v1 without supported Finish semantics | Inspect/export only in this packet. Do not silently broaden normal attachment or recover a normal source into a second mode. |

A released recording intent remains historical evidence and can be linked by a new explicit source action; it is never reopened or modified. Missing descriptor/Finish fields remain missing requests, while newly observed source facts are stored separately. Never infer the original selected device from the descriptor's rendered format or from a filename.

Current normal attachment's stage guard only checks WAL/SHM; the new reopened-source workflow must use the stricter all-three-sidecar bounded preflight before SQLite access. Do not route it through the older guard/unbounded sealed-reader path as a policy bypass. Already registered owned objects remain authoritative, with no fallback to a more convenient stage after owned authentication fails.

## Separate attachment, conflicts and keep-local

Normal admission requires the existing authenticated normal manifest, complete positive audio, strict v2 profile/config, complete six-stream selection equal to manifest index/count, healthy Finish/cut and the request reconciliation above. Recovered admission requires this action's authenticated recovered result, exact selected checkpoint/six prefixes/index, full-original digest and `unknown_tail=true`. A longer readable audio tail cannot enlarge the clip. All original streams and tails stay in the owned database, even though the arrangement clip plays only selected audio.

Persist operation/project/expected revision/track/clip/source manifest/range/rate/placement and the source-result binding before executing attachment. Use existing project/history/operation atomic publication. A known revision conflict may occur after successful ingestion; expose that library original and retained source truthfully. Do not claim “nothing was saved.”

For a typed known prepublication rejection, explicit release of that choice may permit a fresh choice with new operation/track/clip IDs and a newly selected expected project revision. Keep the rejected exact request and its result evidence. For an uncertain outcome, allow Keep locally to suspend the card and retain the same retry request; do not allow a replacement publication until read-only operation reconciliation proves no commit or finds the exact committed receipt. Corrupt/conflicting operation receipts are errors, not absence. Existing v1 intent immutability stays intact; supersession lives in the new action ledger.

Keep local never deletes sources, artifacts, histories or rollback sidecars and never frees their retained-capacity accounting. Returning a suspended action is an explicit UI disposition change on a new ledger revision, not a reversal of an old recording intent's irreversible `released` field. A new recording uses a new Start identity and cannot reuse an unproven owner/stage.

## Complete export of unassigned sources and original evidence

Offer a distinct **retained-source evidence archive** and, later, a combined song-plus-evidence export. Preserve OSARv2's existing semantics; do not silently insert unsupported local lifecycle tables or claim that its current closure includes unassigned sources. The coordinator freezes the new container/version, but no new runtime dependency is presumed necessary.

The archive closure includes the explicitly selected original file set with every file's size/hash and exact bytes; linked immutable review blobs; all relevant exact recording-intent and source-action history payloads/hashes; the immutable pre-recovery database image; any completed recovered working copy plus its manifest/selection/derivation receipt; pending/uncertain operation identity; and source/project relationships. Include unsupported/unreadable-source descriptors and missing-file declarations in the inventory, but fail a requested **complete** export when required bytes cannot be read consistently. A deliberately selected subset can be exported only with truthful subset labeling.

A sidecar-bearing stage remains ineligible for SQLite inspection/recovery. A separate raw-only export may preserve its database **and every sidecar exactly**, without SQLite open, under the existing owner lock and bounded stable file-set/hash checks. It proves retained bytes, not a consistent playable database, journal coldness or successful power-loss recovery. Unknown ordinary stage files are included in the bounded file-set inventory rather than silently dropped. Symlinks, redirected parents, unstable file sets, unavailable ownership or over-budget files refuse complete export without changing the source. Operational lock-file bytes, if included, are evidence only and never restored as ownership authority.

Capture a finite explicit source-set manifest first. Directory truncation, omitted unknown entries or a source arriving during enumeration must prevent an “all retained sources” completion claim unless a later bounded reconciliation establishes the exact declared closure. Export each object using bounded chunks to an exclusive new destination, verify all hashes and then publish the final archive receipt. Retry binds the same source set/destination/export operation and cannot overwrite an unrelated file. Keep prior incomplete exports; no cleanup deletes original evidence.

Restore first into a private inert evidence namespace. Validate container paths, counts, sizes and hashes before exposing anything; reject traversal, aliases and duplicate conflicting object identities. Restored sources/actions never auto-resume, auto-recover or auto-attach. Original request bytes and historical project IDs remain provenance; a restore-as-copy mapping is separate, not a rewrite of old intentions. A musician's later choice creates a new local action referencing the imported immutable evidence and reviewed mapping.

For a combined song-plus-evidence export, wrap an unchanged verified OSAR plus a verified evidence archive with a versioned closure manifest linking their hashes and identities. An attached recovered performance's full evidence closure includes both the recovered database and its pre-recovery image/history. Until that combined route exists, explain that the song archive preserves the attached original database but the separate evidence archive is required for unattached/pre-recovery stage evidence. Do not declare the broader complete-backup requirement met by only one of those files.

## Ordered implementation and review gates

1. **Freeze contracts and migration.** Coordinator selects copy recovery, action/review storage shapes and bounds, stable-admission projection, typed errors, cancellation/uncertainty states, orphan-normal adoption and archive scope. Preserve schema-5 histories byte-for-byte. Independent persistence review checks version/future-schema refusal, migration rollback, capacity refusal and action races before UI execution exists.
2. **Read-only UI and reconciliation.** Wire existing Scan/Inspect/cancel plus exact recording-intent reconciliation. Headless tests prove stale replies, retained credit, truncated scan, source-local faults, missing/owned/sidecar refusal and no mutations/engine calls. Reopened normal-source choices remain disabled until their durable action admission is implemented.
3. **Evidence-copy primitive and bounded recovery admission.** Recording/engine implement only whole-byte copy/authentication and selected recovered finalization on action-owned copies. Source/evidence snapshots are unchanged on success and every injected failure. Keep a single cumulative governor and continuous copy-owner handoff. No generic recovery fallback, normal seal capability or unbounded reopen.
4. **Durable execute/reconcile service.** Add source-action prepare/execute/outcome/keep-local with exact-current CAS replay, stable operation derivation, copy/artifact authentication, crash-point reconciliation and healthy catalog after source refusal. Stalled operations retain ownership/credit; no duplicate filesystem worker. No automatic project publication.
5. **Mode-specific explicit attachment and supersession.** Implement verified normal adoption, recovered selected-bounds admission, separate target/draft choice, known-rejection release/new action, uncertain retry and owned-object conflicts. Test receipt-first replay after source removal and later edits, with no current-document regression.
6. **Evidence export/restore and complete closure.** Add immutable source-set inventory and raw/object/history preservation, sidecar raw-only handling, unsupported/missing source refusal, bounded complete archive/restore and imported inert histories. The copy-recovery UI must clearly expose its evidence-backup boundary until this gate is done; no final feature acceptance without full required closure.
7. **Native UI qualification.** Coordinator uses a fresh package: inspect a real retained ordinary performance source without changes; explicit recovery on a fresh authorized copy; separate attachment; Undo/Redo; exact current document after restart; complete evidence export and restore; normal result reconciliation and a known conflict; keep-local and return. Exercise accessibility, keyboard focus, draft guards and always-available Stop. No native input required. This remains separate from physical listening, long-session, MIDI/model/plugin/installer/Windows acceptance.

Required adversarial cases span every slice: changed bad/unselected row with unchanged playable prefix; opaque column/type/schema/sequence changes; stale/mutated review/hash/usage; no checkpoint and checkpoint followed by bad tail; captured fault and pending cause; v1/v2/dual/null/future markers; sidecars before open and racing copy; owner contention; symlink/hardlink/path replacement; quota/disk/full-copy failure; crashes before/after image publication, interruption commit, recovered manifest commit and outcome receipt; lost attach acknowledgement and revision conflict after ingestion; conflicting same-take manifests; archive omission/truncation/path traversal; restart with imported pending requests. Each test must verify exact retained original bytes/rows/hashes and absence of unauthorized normal seal, project mutation or source cleanup.

No implementation or recovery acceptance follows from this document. The smallest next implementation after coordinator contract agreement is read-only Scan/Inspect/reconciliation UI; bounded copy recovery and its ledger are separate reviewed slices.
