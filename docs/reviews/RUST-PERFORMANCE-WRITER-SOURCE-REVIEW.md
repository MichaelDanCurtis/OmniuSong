# Independent review: incremental performance writer

October 20, 2026. **Accepted for the bounded device-free writer, interrupted-prefix recovery and complete-archive path.** The final workspace log has 636 passed, zero failed and three intentional ignored helpers across 50 result groups. The reviewer independently checked the log totals, source bindings, eight process-interruption fixtures and the completed large qualifier's stored PCM, source records and archive. No remaining blocker was found within this scope. Normal Finish, native quiescence, worker/UI recording and editable-note derivation remain required later work.

This review covers the journal append-group/selected-prefix changes, `engine::performance_records`, `engine::performance_writer` and the independent `performance_writer_review.rs` tests against [the frozen writer contract](../contracts/NATIVE-PERFORMANCE-WRITER.md). The reviewer ran no Cargo/fmt, device, GUI or live-catalog operation. Test source creates only isolated synthetic journals. The existing packaged arrangement workflow is a separate source/binary boundary.

## Findings and disposition

The initial recovery implementation derived the seal operation from only part of the reviewed request. Once a recovered manifest existed, a changed review problem or original physical-review hash could reuse the operation. The coordinator corrected the derivation to hash the caller operation plus the **complete original `PerformanceInspection`**. Replay separately authenticates the current descriptor, original-row digest, selected index and checkpoint, allowing controlled sealing metadata to change physical file bytes without allowing a changed request. The independent changed-review and changed-tail cases exercise this distinction.

A checkpoint-specific clock-anchor gap was found: the scanner rejected anchors on ordinary raw members but the final singleton checkpoint bypassed that member check. The coordinator moved the no-anchor check to contextual raw decoding, including checkpoints. The independent tamper fixture now adds a generically valid, rehashed checkpoint-header anchor and requires selection to stop at the preceding checkpoint. A separate mode shifts a Batch envelope's render timestamp within otherwise valid raw-chunk bounds; the scanner now checks that it equals the callback start.

The coordinator added `capture_fault_pending` independently of the resolved `capture_fault` and writer `first_error`. A callback can truthfully report a clear while the first-fault publisher has not finished writing its cause. That interruption must not appear healthy or acquire an invented kind/frame. An actual resolved cause clears the pending flag; neither condition is a writer syntax or SQLite failure.

The final source observations are addressed in the frozen implementation. Configuration rejects a GUI clock whose domain/epoch aliases the reserved render clock identity, including when the rational differs. A known Fault clear requires the matching resolved End cause; later Applied batches or new Panic acknowledgments are rejected after a sticky capture fault or unresolved fault publication. A separate `fault_cleared` flag rejects repeated or re-timed forced clears without conflating cause publication with the later actual clear.

The clear-scope check also permits the legitimate same-callback race: Begin in the old scope, Panic clear in that scope, acknowledgment of the next scope, then an asynchronous fault clear in the new scope. The common clear check accepts only the same worker/session and generations between Begin and End; the Panic-specific check still requires the old scope and callback-start frame. This allowance is source-audited, not a claim that a deterministic public test reproduces native concurrent fault delivery. Cause publication before an actual clear is also allowed. The two additional independent forged-packet tests exercise the contradictory known-clear and post-fault application cases.

## Audited boundaries

**Originals and clocks.** Configuration creates exactly one F32 audio stream, four prepared GUI-source streams and one render-control stream. The original GUI rational remains in descriptor provenance; exact integer gcd reduction must fit the journal timebase before creating the stage. Original `u64` observed ticks and `u16` velocities remain intact. Applied source records link to full callback-owned batch originals; rejected/discarded batches remain control evidence. Empty lease batches, Panic clears and automatic transitions are not converted into human notes. The profile uses Local/Uninterpreted envelopes, no MIDI channel, no UMP and no clock calibration.

The codec retains the existing 16-KiB envelope ceiling. Clear and transition records are split from End, avoiding a potentially oversized 128-transition envelope. A boxed durable Batch payload is allocated only off callback; the tap remains the existing fixed `Copy` union. Contextual decoding re-encodes the exact descriptor/stream/ordinal-bound envelope and compares bytes, so a self-consistent generic hash does not excuse a changed session, endpoint, event identity, clock or source link.

**Atomicity and retries.** `append_group` validates all members and simulates affected prefixes before inserting under one Immediate transaction. It bounds canonical headers plus payloads to 64 chunks/8 MiB. All-old replay requires exact bytes, order and consecutive global ordinals within the verified original prefix; mixed old/new requests conflict. Its deterministic content hash does not claim that arbitrary previously separate appends were historically atomic. The performance checkpoint supplies the owned cross-stream fence. A post-commit reply failure leaves an exact pending request; explicit retry can clarify durable state but cannot clear the writer's first error or resume packet admission.

**Bounded reduction.** The writer validates the actual renderer's Begin/Batch/PCM/End groups, not a parent-collected event list. It separates received, complete and durable positions. Whole callbacks are encoded before joining a commit group; group overflow flushes the prior complete group and re-encodes the next callback against the new control prefix. This matters because the preceding checkpoint itself consumes a control event/sequence. Audio payloads stay at most 1 MiB, raw chunks 64 KiB, complete groups 8 MiB, and pending callback data is bounded. Time, byte, chunk and callback-count limits are independent. These are fixed storage/work limits, not a measured latency claim.

**Consistent recovery.** The semantic scanner validates member order/digests, the predecessor chain, exact source events against applied batches, callback audio extents, scope and all six predicted prefixes. It selects the last fully valid checkpoint before a generic or semantic failure. It neither skips a broken group nor promotes valid audio preceding a missing/corrupt checkpoint. Empty or uncheckpointed material cannot become a playable recovered performance.

Selected-prefix recovery retains exclusive ownership through read-to-write conversion, verifies the original-row digest again inside sealing, and retains every later/bad chunk plus the interrupted index. The generic recovery/seal conveniences reject the owned performance marker, including on replay. The low-level selected-prefix primitive intentionally relies on the performance verifier for format semantics; it is not a sandbox against arbitrary in-process callers.

**Interruption and lifecycle.** Healthy storage can commit a validated partial callback as an unselected tail without fabricating its End or missing audio. Ambiguous storage failure permits no fresh tail write. All recovered material has an unknown tail. Closing the writer is not a callback fence, renderer destruction acknowledgment or native error-closure proof. No normal Finish/seal API, worker command, capture UI, implicit attachment or editable-note projection is implemented by this packet.

## Independent tests

The 14 independent cases use `recording_live_pair` and actual tap packets. They cover bit-exact PCM, six-stream identity, ticks near `u64::MAX`, exact clock reduction, live-owner refusal, rejected atomic batches, Panic and exact lease boundaries, partial-tail retention, absent-checkpoint refusal, generic recovery guards, stale review/source-tail changes and changed request replay. The feature-gated fault case exercises whole-group rollback and committed-but-unacknowledged replay while proving new packet admission stays closed. Two deliberately forged packet cases require rejection of a known fault clear without its matching End cause and of resumed application after a durable sticky fault; the latter keeps the previous 64-frame checkpoint and original rows unchanged.

The rehashed tamper case now tests five contradictions while retaining generic chunk validity: changed GUI release original, envelope session, checkpoint audio extent, checkpoint clock anchor and Batch observation time. Every case must recover only the prior complete checkpoint and leave original rows unchanged. The streaming case produces 65 maximum callbacks through the real renderer, eight-channel PCM exceeding 30 MiB, and 8,320 source-aware local events; it compares the rendered and retained PCM digests. It does not open a device, measure 30-minute capture, or claim human input.

The recording lane's active process test passed all eight owned-helper scenarios. The reviewer opened each retained fixture read-only: interruption after insert 1 through 6 or before commit left zero chunks and all six initial prefixes; interruption after commit left all six chunks, their exact payload/checksum records, advanced prefixes and an exact replay receipt. Every database passed integrity checking. The helper exit was deliberate process exit 77, with the child reaped before reopening. This is process-interruption evidence, not physical power-loss or native audio-worker qualification.
