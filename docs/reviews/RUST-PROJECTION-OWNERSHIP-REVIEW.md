# Independent projection ownership source review

October 22, 2026. Astra architecture review of the working tree based on `a0fd2fb`, including the final stored-history-pair and attachment-preflight fixes. **Decision: accept the bounded stage-2 source boundary; no remaining concrete source blocker identified.** This accepts structural musical schema-3 ownership and the staged refusal of unverified projection authority. It does not accept projection publication, native conversion controls or the complete recording milestone. Final compilation, tests and stable-source qualification remain the coordinator's responsibility.

The reviewer supplied architecture and independently read the implementation and test sources, including the [ownership contract](../contracts/NATIVE-PERFORMANCE-PROJECTION-OWNERSHIP.md) and [integration plan](RUST-PERFORMANCE-PROJECTION-PLAN.md). Only this review document was changed. No Cargo, formatting, build, native UI, audio/device/input/output, SQLite open, regular-store operation, network or download was performed by the reviewer. Test cases below were inspected, not executed or accepted on another agent's report.

## Structural and dependency boundary

Reviewed `omniusong-core/src/performance_projection.rs`, its tests and integration in `lib.rs`, `native.rs` and `note_edit.rs`. The core module owns strict outer DTOs with unsupported-version and unknown-field refusal, while depending only on existing core musical/source contracts. No core-to-performance dependency or dependency cycle is introduced.

Schema 3 requires an explicit version-1 root registry, even when empty. Each entry retains its projection identity, audio-stream `TakeReference`, exact review JSON string/digest fields, original source/instrument lanes and original note IDs/voice hashes/values. There are no project or operation IDs inside an entry that would require later archive-copy rewriting. The source reference describes ownership of the complete take; it does not itself prove the six-stream performance profile.

The limits are 64 entries, 16 nonempty lanes per entry, 20,000 original note bindings across the registry and 8 MiB of aggregate retained review JSON. Known string/array slots are bounded before DTO allocation; checked additions enforce aggregate limits. The enclosing document still has its existing 8 MiB limit, including JSON-string escaping, binding duplication and unrelated metadata. A review accepted by the kernel is therefore not necessarily small enough to publish into a document. These are refusal bounds, not measured memory or timing guarantees.

The review string remains exact. Core checks its JSON envelope, version, embedded review-digest field and take/manifest agreement, without claiming canonical encoding, digest correctness, lifecycle correctness or derivation. A deliberately incomplete/noncanonical review can pass these structural checks; the tests make that weaker authority explicit. Full strict review decoding, typed canonical serialization, the existing domain-separated digest and held-source recomputation remain shared-performance/publication duties. No replacement plain-bytes hash or normal-seal authority was added.

## Compatibility, edits and retained originals

Schemas 1 and 2 keep any root `performanceProjections` value opaque, including null, malformed lookalikes and external metadata. Their ownership enumeration does not interpret it. Explicit promotion refuses every preexisting key and changes only the schema and empty registry. The original native upgrade target remains schema 2.

`supports_native_takes()` now covers schemas 2 and 3. The reviewed core metadata/timeline/recording checks, session `DocumentView`, engine waveform reader, waveform qualification example and native app arrangement/clip/track paths use that capability. The historical attachment-receipt checker also accepts either take-capable schema. The searched production Rust consumers contained no remaining exact-schema-2 native-take predicate; legacy import and explicit schema-1 upgrade conditions retain their separate purposes.

Projection/lane/note IDs are unique across the registry; source/instrument lane pairs and original voice hashes are unique within an entry. Repeating the same original voice in a distinct explicit projection remains possible with distinct projected IDs. A present reserved lane must remain a notes track. Its current name/instrument and current note values may change, and notes or whole lanes may disappear. Those edits preserve the original binding rather than claiming the edited material still matches the original interpretation. Reserved note IDs cannot move to another schema-owned notes/audio lane or be reused through `add_note` after deletion. Opaque extension data on recording tracks remains opaque. A reservation accessor exists for future lane-creation operations.

`referenced_takes()` unions recording sources with registry sources independently of current notes or audible clips. Store visitation groups that union by take, validates each reference, checks each clip's current/original windows separately and verifies each resulting physical take. Nonempty registries remain refused before active resolution in this stage, so registry-only store/archive closure is prepared structurally rather than claimed as an enabled projection workflow.

## Admission, replay and history fences

Reviewed `omniusong-store/src/projection_boundary.rs`, `lib.rs`, `takes.rs`, `operations.rs`, `archive.rs`, `archive_copy.rs`, `performance_attachment_check.rs` and their relevant callers. Nonempty schema-3 registries are centrally refused at current-document loading, list-summary admission, reference validation, early create, take visitation and operation insertion. Generic Save cannot erase an unsupported current registry because it must first load the current document. A caller-built empty-schema-3 candidate also cannot bypass opaque-key promotion refusal in the shared save helper.

Operation replay validates the stored result through reference checking. History navigation now bounded-reads and parses both stored sides, rejects unsupported ownership on both, checks opaque-key promotion in the recorded forward direction, and verifies matching project identity plus the one-revision transition before choosing the Undo/Redo target. This closes the forged Redo bypass while preserving valid Undo of an empty-schema-3 downgrade whose older-schema field is opaque. Target references/files are checked before SQL mutation.

OSAR metadata traversal applies the staged refusal to the current document, both sides of every history row, every operation result and copy-lineage proof. Stored forward history transitions also receive the opaque-key collision check. Copy-proof parsing itself refuses unsupported ownership. Export, identity restore, copy restore and exact copy replay traverse these checks before active adoption; existing private staging or diagnostic retention on failure remains possible. The change does not promise that every refusal leaves no private stage.

OSAR `inspect_archive` intentionally retains its bounded header/snapshot-hash scope. It refuses a nonempty current project through document loading, but its summary does not validate every hidden history or proof snapshot. Such a summary is neither complete restoration proof nor permission to adopt a projection. The contract now states this limitation.

Fresh normal attachment performs metadata capability preflight after exact historical replay and before source ingestion. Dedicated recovered attachment does the same after validating the retained choice/history and checking the historical receipt or read-only reconciliation case. Metadata preflight opens no original, returns no document/source proof and does not replace commit-time revision/source/history validation. Exact historical commitment is not erased by current path availability. A later concurrent conflict can still retain a safely ingested owned original under the existing recovery contract.

## Inert evidence and remaining authority

OSRE remains complete inert evidence preservation under its existing raw catalog/source closure. It does not parse a retained registry into active projection authority or claim musical source recomputation. This stage intentionally leaves that forensic path available while closing active OSAR adoption of nonempty registries. No SQL migration or new normal recording-seal permission is introduced.

Removing the staged refusal later requires one typed atomic operation that recomputes from the exact owned source, constructs and validates the complete review-to-lane/note binding, and commits document/history/receipt together. Generic saves must then preserve admitted registry authority rather than minting or rewriting it. Archive current/history/result/proof validation must authenticate that same authority against held archived originals. Durable exact-request admission/reconciliation, reversible publication, source-complete archives, native review/edit/restart/audition and the broader MIDI 2/MPE and workstation gates remain mandatory.

## Tests inspected and limits of this review

The inspected additions comprise ten core tests, twelve independent store tests, two session view tests, one actual recovered-source preflight regression and one recovered native-waveform invariance regression. They exercise strict bounds/versions/owned fields, exact opaque metadata, promotion collisions, original binding preservation, ID reservations, malicious current/target/operation claims, source-less replay, empty-schema-3 recording history and both OSAR restore modes. The store fixtures compare logical catalog/schema/cell values and owned bytes; the archive attack independently reproduces the valid index before rehashing/reindexing a forged current-project claim. The recovered attachment test checks refusal before an unregistered original is ingested. These are meaningful intended assertions; this review reports no execution result.

The following cases are not established by the newly inspected tests:

- A fully reindexed OSAR whose unsupported registry exists only in hidden history or copy-lineage proof. Source traversal covers both; the new reindexed archive fixture attacks the current project, while hidden-history export refusal is tested separately. There is no new hidden-copy-proof attack fixture.
- An OSRE round trip containing a schema-3 registry. The unchanged inert-preservation boundary is source-reviewed, not newly qualified with that fixture.
- Exhaustive large multi-entry metadata/escaping capacity, peak memory, latency or real long-performance behavior. The limits are checked, but no capacity benchmark follows from these unit fixtures.
- Native schema-3 projection controls, audible equivalence, input/output capture, complete projection publication/Undo/Redo/archive/restart, thirty-minute recording or actual Windows behavior.

Two review findings were resolved before this decision: generic Save could bypass the helper's opaque-key collision refusal, and history navigation could bypass the resulting Save fence through a forged stored promotion. The final shared-save/archive transition checks and forward-pair navigation checks address both, with corresponding regression sources. Initial test compilation diagnostics and the final executed gate remain separate evidence to be supplied by the coordinator.
